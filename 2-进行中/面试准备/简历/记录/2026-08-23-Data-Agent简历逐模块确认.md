### 智能经营分析 Agent 项目定位

> 建设面向场景险业务的智能经营分析 Agent，为业务人员提供自助、高效、可信的取数、分析与主动告警能力。周活跃用户 30 余人，将报告类任务由 2～3 天缩短至约 2 小时，经业务估算每月节省约 23 人日，推动经营分析从有限人工响应转向业务自助，提升分析覆盖度与决策响应效率。

### 智能经营分析 Agent 已确认技术点

> **Agent 架构与编排：**负责 Agent 应用层整体架构设计与开发，构建由主 Agent 动态编排澄清、取数和报告 Agent 的多 Agent 协作体系，并整合 Tool、Skill 与知识能力形成“澄清—执行—验证”闭环。

> **可信取数与评测：**将自然语言诉求收敛为标准指标与结构化查询参数，通过指标支持边界、交互式澄清和结果校验，形成可控、可验证的问数链路；构建约 200 道业务问题的自动化回归评测集，已覆盖核心指标问数准确率接近 100%，单轮任务成功率达到 83%。

> **记忆管理与知识库构建：**按用户与 Task 组织长期记忆，支持个性化分析、跨会话任务续接、历史经验复用和冲突信息选择；围绕数据知识、分析方法与业务知识搭建分层知识库，将商分和业务经验沉淀为可组合 Skill。

> **知识治理与分析校验（标题待最终微调）：**构建“结构化整理知识 + 全量原始知识”的分层知识库，通过总结 Agent 预处理和人工确认，沉淀业务事件与动作、场景—分析方法映射、指标参考范围及指标间关系；Agent 优先使用整理后的知识，并在报告生成后校验指标适用性和数值合理性，异常时触发二次查询复核。

上述内容已确认；最终简历结构中，是否将其与“可信取数”合并为统一的准确性/可靠性保障要点，待全部项目素材确认后再决定。

> **查询性能与预计算：**根据数据规模和时效设计分级缓存，对聚合结果进行复用，对长周期流量明细采用“历史全量 + 每日增量”更新；将典型复杂查询的端到端耗时由 30～60 分钟降至缓存命中后的数分钟，并将约 1 小时的异常分析报告转为后台预计算，使业务查看时可直接获取结果。

### 理赔客服智能质检 Agent 已确认技术点

#### 项目介绍（AI 草案 / 违规发现量待核对）

> 面向理赔客服通话中的人身攻击、辱骂及严重服务态度问题，建设智能质检 Agent，实现日均约 1 万条通话全量筛查，将质检覆盖率由约 5% 提升至 100%，释放 1 名专业质检员人力；周均确认严重违规问题暂按由 2～3 条提升至 7～10 条、提高至原来的约 3 倍记录，投递前必须根据同口径原始统计重算。

- “客诉率绝对下降 1.3 个百分点”是项目目标，尚未获得上线后数据验证，不进入当前简历正文。

> **智能质检与分级复核：**将内部模型处理拆为角色校验和违规初审两阶段，先判断客服与用户标签是否正确，错标时通过脚本交换角色，再进行违规初筛；脱敏后交由外部 SOTA 模型完成逻辑复核与 A/B/C 分级，最终由专业质检员人工确认，并结合 Few-shot 与线上 badcase 持续优化。

> **Agent 评测与优化闭环：**在仅有约 20～30 条违规样本、随机抽检阳性率约 1‰ 的情况下，以召回优先策略上线；将专业质检员的复核结果沉淀为评测与迭代样本，持续优化 Prompt、Few-shot、分级标准和模型路由，形成“Agent 筛查—人工确认—样本回流—评测迭代”的闭环。

### 两个 Agent 项目的工程实现边界

- 智能经营分析 Agent 主要使用 Python 开发。个人完成应用层 Agent 编排、Tool、Skill、数据平台接口接入、缓存、评测脚本和定时任务，并部署在公司服务器。
- 公司提供服务器、指标平台与跑数接口、模型接口，以及文档读取等平台通用工具；不得将这些底层平台能力写成个人开发成果。
- 理赔客服智能质检 Agent 使用 Python，并依托公司内部低代码 Agent 平台 Friday 实现；核心工作以 Prompt 工程和质检流程设计为主，支持离线批量任务及线上调用。
