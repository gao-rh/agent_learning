### 1. 智能经营分析 Agent

- 项目定位与目标用户：面向场景险业务的一线业务、产品及分析人员，提供自助取数与经营分析能力。
- 原始业务问题：取数诉求存在指标、维度和时间歧义；分析依赖业务知识、分析方法与可信数据证据；日会、周会和经营监控要求较快响应。
- 系统或业务复杂度：从自然语言澄清到结构化查询、受控执行、结果校验，再到图表与报告生成；同时覆盖被动问答与定时主动服务。
- 个人职责与协作边界：负责 Agent 应用层整体架构与开发，担任技术负责人；与业务、产品、商分和数据团队协作，不将公司指标平台或既有算法归为个人底层发明。
- 关键技术方案和选型原因：主 Agent 负责理解、必要澄清、编排与结果整理；取数 Agent 统一处理查询；分析 Agent 生成分析、图表和报告。可信取数使用指标检索、交互澄清、结构化参数、代码化查询与校验链路；分析方法拆成可组合能力并封装为 Skill。
- 已确认量化结果：周活跃用户30余人；每月节省约23 PD；200道业务取数问题评测集上单轮任务正确率91%、取数 Agent 准确率95%；4类常驻通知。

- 最值得进入简历的内容：三类 Agent 的职责边界、可信取数链路、分析方法与知识、记忆/查询复用、主动通知及业务使用结果。

### 2. 理赔客服智能质检

- 项目定位与目标用户：面向理赔客服通话的服务态度质检，供质检与业务团队筛查、复核和确认问题。
- 原始业务问题：“态度差”等标准抽象且主观，人工抽检覆盖不足；多维度规则会相互干扰。
- 系统或业务复杂度：日均约1万条通话；需要把标准细化为可观察、可标注、可分级规则，并形成分层筛查、复核、脱敏、分级和人工确认链路。
- 个人职责与协作边界：担任技术负责人，负责标准工程化、评测、Prompt 自动迭代及 Python 工作流的生产实现；最终处罚由专业人员确认。
- 关键技术方案和选型原因：430条三人交叉标注、376条共识样本；维度化提示词；AI 基于真实 Case 与人工复核结果自动调整 Prompt 并自动评测；通过 Python 实现批处理、完整性校验、失败重试、日报与通知。
- 已确认量化结果：评测集召回率97%、线上准确率85%；质检覆盖率约5%提升至100%；释放1名质检员；周均确认严重违规问题由2-3条提升至7-10条。
- 生产状态与验证状态：定时质检链路已生产运行。近期用户确认口径优先于阶段资料中的早期探索数字。
- 最值得进入简历的内容：主观标准客观化、评测数据集、维度化提示词与自动迭代、分层生产质检链路、覆盖和人效结果。
- 不应写入或仍有冲突的内容：阶段资料中的30%、60%、约1500条等早期数字；内部 Agent 平台或“完整自治 Agent”表述；将自动分级写成最终处罚结论。

### 3. 公共营销数据建设

- 项目定位与目标用户：建设公共营销数仓，为活动运营、效果分析和漏损排查提供统一数据底座。
- 原始业务问题：系统、活动和节点类型多，链路口径复杂；主动触达场景存在缺失、错误等异常数据，奖励下发链路缺少统一全链路视图；无用数据、全量任务和大任务带来资源浪费。
- 系统或业务复杂度：整体涉及十余个业务系统、十余种活动大类，不同活动具有不同的节点结构和业务属性。
- 个人职责与协作边界：担任技术负责人，负责跨系统链路梳理、问题定位、数据链路建设及持续治理。
- 关键技术方案和选型原因：新建奖励下发全链路数据视图，优化补齐主动触达场景的全链路数据视图；推进无用数据下线、计算资源迁移、全量任务增量化及大任务治理。
- 已确认量化结果：存在异常数据的活动占比由约90%降至0%；日均节省1200 CU，释放存储空间约1.5 PB，年化收益约35万元。
- 生产状态与验证状态：数据链路与治理措施均已落地；异常数据包含缺失和错误两类，不表述为单纯的数据缺失。
- 最值得进入简历的内容：公共数据底座的业务价值、跨系统与活动结构复杂度、两类全链路数据视图建设，以及可量化的资源降本结果。
- 不应写入或仍有冲突的内容：不再使用旧的系统数量、业务过程、空跑占比和累计金额口径；资源单位必须写作专有单位 CU，不得改写为其他单位。
