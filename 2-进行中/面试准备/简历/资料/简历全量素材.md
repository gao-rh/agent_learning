### 3.2 智能经营分析

#### 业务问题

- 面向美团金融场景险业务，包括用户口述中的准时保、取消险等产品场景。
- 用户为场景险相关产运和商分，约 20–30 人；高频使用者主要是商分和少数资深业务。
- 大多数普通业务更常见的是取数需求，深度分析诉求相对少。
- 传统看数至少要等待半天；商分形成一份常规分析报告通常需要 2–3 天。

#### 能力范围

- 智能取数、查数、指标口径查询。
- 流量专题、保费专题、商户变化专题等固定分析。
- 未预先定义分析思路的开放式分析。
- 带业务事件的知识库和数据异常归因。
- 对话式分析。
- 每日定时分析流量和资源位，识别异常、推测原因，经大象主动触达业务并附简易报告。

#### 技术设计

1. **自主判断而非固定分类器**：用规范文档描述各类条件和能力边界，由 Agent 根据上下文自主判断，不预先把所有问题硬编码到固定意图路由。
2. **双类编排**：顶层分为“查口径/查数”和“经营分析”两类执行模式。
3. **可信取数链路**：澄清需求 → 调用指标支持范围工具 → 判断指标类型和复杂度 → 优先指标平台 → 超出覆盖范围时降级 SQL → 领域数据校验 → 返回结果与可靠性说明。
4. **指标平台路径**：通过接口查询平台支持的指标类型，命中后走指标平台；平台承担语法、字段和执行层校验。
5. **SQL 降级路径**：平台不支持时生成 SQL 查询数仓并做基础校验；明确向用户提示该路径无法提供与指标平台同级的准确性保障。
6. **领域数据校验**：为单指标沉淀参考范围，为多指标沉淀大致关系，用数据知识发现错误筛选条件、错误关联、选错对象、空结果和明显异常量级。它用于过滤低级错误，不宣称解决复杂语义错误。
7. **分析双模式**：固定日期和类型的流量、保费、商户等专题使用稳定 Workflow；开放式需求由 Agent 按工具和 Skill 自主组装分析步骤。
8. **知识与事件检索**：业务知识向量化；业务事件按事件类型预处理和分块；使用关键词+语义混合检索并排序。
9. **异常归因**：从总量异常开始，逐层下钻细分维度，定位到具体人群和 source，再检索该 source 相关业务事件形成原因判断。
10. **主动触达**：定时任务触发每日分析，使用传统统计方法识别异常，经大象推送问题、推测原因和简易报告。
11. **评测演进**：初期准备少量案例并由 AI 辅助迭代；第二阶段收集真实问题、人工设计问题和 AI 扩展问题，抽象为类别并形成 100 题数据集；第三阶段随真实使用 case-by-case 修正，没有无限扩展离线数据集。
