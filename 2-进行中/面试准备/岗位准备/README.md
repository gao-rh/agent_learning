## 收到下一场面试时

1. 用公司、团队和岗位 ID 区分岗位；相似标题不自动合并。
2. 找到已有档案后更新本轮信息：JD 来源与核验日期、面试日期／轮次、考核形式、可准备时间、实际投递简历。
3. 在该档案中维护岗位画像、简历证据映射、重点与未确认事项。技术长答案引用[能力资料](../资料/README.md)，个人事实引用[项目准备](../项目准备/README.md)。
4. 比较上轮：哪些要求变了、哪些答案已有、哪些能力仍待验证，只补变化。

现有专项虽然文件名带起稿日期，后续仍在同一文件迭代。真正的新岗位先在此登记；只有持续维护需要时才新建按公司／团队／岗位命名的轻量档案，不再复制完整题库。

## 岗位档案的最小结构

- 本次范围：岗位与 JD、轮次、时间、简历版本及关键未知项。
- 岗位画像与简历映射：工作／能力 → 依据 → 具体简历主张 → 可能追问 → 答案位置／缺口。
- 本轮阅读顺序：重点及理由、引用的能力章节、需要补齐的个人证据。
- 来源覆盖与本轮差异：已查、受限、待核验，新增与修正。

不在此统一评判所有岗位的优先级，不因为一次题目出现就推断市场频率。本人面试转录仍按指定范围查阅，不自动接入岗位档案。
