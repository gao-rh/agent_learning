### 最该补齐的技术逻辑

**热点 Join。** 假设店铺维表在连接键上唯一：热点分流方案要把事实侧分成热点和非热点两路；热点路关联可广播的热点维度子集，普通路正常 Join，再按原结果语义合并。加盐方案则让热点事实每行只落一个盐桶，热点维度记录覆盖全部盐桶，按店铺 ID 与盐连接。若两边各随机选一次盐，会漏匹配；若不控制右侧扩展，会增加成本。热点键少不自动等于广播对象小，要检查行数、字节数、键唯一性和内存。这里是算法说明，不是你项目已验证过的配置；AQE 与广播条件可对照 [Spark 性能调优](https://spark.apache.org/docs/3.5.6/sql-performance-tuning.html)。

**UV。** 精确 COUNT DISTINCT 的瓶颈取决于实际执行计划、去重基数、Shuffle 和状态开销，不能一概说全部原始数据进一个 task，也不能保证换 GROUP BY 必然更快。可讨论精确预去重或可合并去重集合，以及允许误差时的近似算法；Spark 的 `approx_count_distinct` 提供可设相对标准差的近似去重计数。必须先说明误差是否被业务接受，不能把近似结果伪装成精确 UV。[Spark：approx_count_distinct](https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/api/pyspark.sql.functions.approx_count_distinct.html)

**Flink 一致性。** 先解释 checkpoint 将源位置与算子状态保持一致，恢复时重放；端到端还要求可重放的源，以及事务性或幂等性的输出配合。事件可能被重新处理，关键是最终状态/外部效果的语义，不是机器只执行一次。离线覆盖与从零点消费只是操作描述，不能替代这些条件；仍须核对事件时间、迟到与覆盖范围。[Flink：Fault Tolerance](https://nightlies.apache.org/flink/flink-docs-stable/docs/learn-flink/fault_tolerance/)

**Flink 反压。** 下游消费能力不足会把压力向上游传导；它与消费延迟有关，但不等同。先看哪个算子/子任务忙、哪个被反压，再按瓶颈检查数据分布、计算、I/O、状态和外部 Sink；资源不足时扩容才是有依据的动作。[Flink：Monitoring Back Pressure](https://nightlies.apache.org/flink/flink-docs-stable/docs/ops/monitoring/back_pressure/)

**MapReduce。** 本场与字节均没讲完整，优先共用一份练习。不能把一个 HDFS 块绝对等同一个 Map，或把 Reduce 限定为求和；应包含逻辑输入切片、分区排序、溢写合并、Shuffle 和最终处理。[Hadoop：MapReduce Tutorial](https://hadoop.apache.org/docs/r3.3.6/hadoop-mapreduce-client/hadoop-mapreduce-client-core/MapReduceTutorial.html)

### 连续登录题的可检查答案

题面初始为连续登录 **大于等于3天**。先将粒度定为“一个用户的一天一次登录”，排除无效用户/日期，再去重。下面是 Spark SQL 风格的教学答案，均返回满足条件的用户，不是从面试中补写出的本人答案。

严格连续：相邻日期差为1时，日期减连续序号得到同一个组键。

```sql
WITH d AS (
  SELECT DISTINCT user_id, CAST(login_date AS DATE) AS dt
  FROM logins
  WHERE user_id IS NOT NULL AND login_date IS NOT NULL
), ranked AS (
  SELECT user_id, dt,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY dt) AS rn
  FROM d
), g AS (
  SELECT user_id, DATE_SUB(dt, rn) AS grp
  FROM ranked
)
SELECT DISTINCT user_id
FROM g
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

允许相邻两次登录之间缺一天：先确认该解释成立，即每个相邻间隔最多2个自然日；如果题目要求整个序列总共只能缺一天，下面这个算法不满足，需另做约束。还应确认计数指实际登录天数还是包含缺失日的跨度。此处按实际登录天数计算。

```sql
WITH d AS (
  SELECT DISTINCT user_id, CAST(login_date AS DATE) AS dt
  FROM logins
  WHERE user_id IS NOT NULL AND login_date IS NOT NULL
), p AS (
  SELECT user_id, dt,
         LAG(dt) OVER (PARTITION BY user_id ORDER BY dt) AS prev_dt
  FROM d
), marked AS (
  SELECT user_id, dt,
         CASE WHEN prev_dt IS NULL OR DATEDIFF(dt, prev_dt) > 2
              THEN 1 ELSE 0 END AS new_group
  FROM p
), grouped AS (
  SELECT user_id, dt,
         SUM(new_group) OVER (
           PARTITION BY user_id ORDER BY dt
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
         ) AS grp
  FROM marked
)
SELECT DISTINCT user_id
FROM grouped
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

| --- | --- | --- | --- |
| 1、2、3 | 是 | 是 | 恰好3天必须包含 |
| 1、2、4 | 否 | 是 | 题目给的正例 |
| 1、2、5 | 否 | 否 | 题目给的反例 |
| 1、1、2 | 否 | 否 | 同日重复不能算两天 |
| 1、2、10、11 | 否 | 否 | 同为连续标志的不同段不能合并 |
| 1、3、5 | 否 | 是 | 若全序列只允许缺1天，这行结果应不同，必须先澄清 |
