# 智能经分评估方案

> 2026-09-08 合并原评估讨论、v0.1／v0.2／v0.3 与后期口述。方法组织为 AI 整理草案；不把建议项自动视为生产实现。详细旧评测卡仍可按需查归档。

## 当前数字与适用范围

最终 200 道业务取数题的准确率为 95%，标准答案由人工确认，大模型对照判分。题目兼用于调试与验证，没有独立留出的测试集。这一后期口述覆盖早期泛称“约 90%”的取数介绍，但不能覆盖不同对象的指标。

| 数字 | 对象 | 不允许的合并 |
| --- | --- | --- |
| 95% | 最终 200 道取数题 | 不写成全部线上问题或独立盲测准确率 |
| 91% | Agent 问题回答准确率 | 不擅自绑定到 200 道取数题 |
| 88% | 会话满意度 | 不替代正确性或任务成功率 |
| v4 首跑 76%、累计 87% | 旧版本材料中首跑与任一轮通过的不同口径 | 不拿累计通过率冒充单轮成功率，不恢复为当前成绩 |

本轮未重跑公司评测，也未核验上述数字的原始明细。最终失败的最新回忆包括条件遗漏和执行报错／超时，不能归为全部是工具故障。

## 三层框架

| 层次 | 目的 | 对象 |
| --- | --- | --- |
| 顶层结果 | 是否提供正确数据并解决问题 | 数据准确率、端到端任务成功率 |
| 流程诊断 | 失败起点在哪里 | 需求理解、澄清／拆解／参数组装、取数、分析和最终表达 |
| 横向质量 | 是否可靠地持续运行 | 记忆、延迟、成本、稳定性、权限、安全及不编造 |

意图识别可以作为诊断项，不因为它出现在流程中就必须持续单列 KPI。报告属于分析输出，定时任务属于非会话入口和交付方式；按实际任务分别测。

## 判分原则

| 任务 | 需要判断什么 | 方法与边界 |
| --- | --- | --- |
| 数据与口径咨询 | 事实、定义、适用边界及引用正确；确实无答案时不编造 | 权威资料对照；语义 Judge 加人工复核 |
| 取数澄清 | 参数齐全时不多问；缺信息时集中指出真实缺失条件 | 人工标注参数与澄清预期，检查澄清后的任务是否完整 |
| 可信取数 | 指标、时间、粒度、维度、单位与结果正确 | 能程序比较的数值优先确定性校验；解释部分可辅助 Judge |
| 固定专题分析 | 关键指标齐全、计算正确、方法与专题一致、范围符合要求 | 比较数据、计算和报告；局部问题不强行跑完整专题 |
| 开放分析 | 目标覆盖、证据充分、推理与数据一致、结论区分事实和假设 | 无唯一业务答案不等于无法验证查询与数值；只看最终报告的 Judge 不能证明底层取数正确 |
| 记忆 | 正确保存和召回、冲突更新、过期处理、隔离与删除 | 只验证续接读取不能证明写入和治理全部正确 |
| 定时与主动交付 | 按时触发、数据就绪、重复与漏发、失败恢复、交付有效 | 需要调度与交付证据，不能仅看报告文字 |

数据准确率只计算含数据事实的适用任务。端到端成功要求必要任务完成、数据硬门槛通过、结论有证据、无越权与编造。两者分母不能随意互换。

## 一次可复查评测应保留什么

建议保留题目 ID、问题、题型、预期参数／答案、有效条件与判分规则；运行时记录模型／Prompt／工具／数据版本、查询条件、结果引用、Trace、耗时、成本、失败环节和最终判定。

- **Pass**：满足该题明确的通过条件。
- **Fail**：有效任务未完成、结果错误或触发硬失败。
- **Invalid**：题目、标准答案或环境前置条件导致本次无法用于预定比较；需给出原因，不能将所有服务失败随意剔除以抬高分数。
- 首跑、重试后恢复与任一轮累计通过分别报告；固定分母、样本版本与重试预算。
- 优先记录首个可确定的失败环节，后续传播造成的错误不重复算作独立根因。

这些是合并后的评估建议，未经实现与运行验收不写成项目已经完整具备的评测平台。

## 当前仍缺的证据

200 题的逐题日志、最终评分规则版本，91% 与 88% 的统计分母，以及全链路数据校验、记忆写入治理、定时交付等专项报告未统一取得。历史数字之间的精确版本追溯不作为本轮新任务。
