# 数据经营分析 Agent 拓扑图—绘图 AI 输入规格

> 用途：将本文档直接提供给绘图 AI，生成一张完整、易读、可用于方案讨论的架构拓扑图。
>
> 状态：这是经过讨论确认的“理想目标架构”绘图规格，不代表所有模块都已在生产环境实现或验证。

## 一、可直接交给绘图 AI 的任务

请绘制一张“数据经营分析 Agent 理想架构拓扑图”，使用中文标注。

这不是普通的模型调用流程图，而是一个“平台受控 + Agent 自主决策”的多 Agent 数据分析系统。

必须准确表达以下核心关系：

1. 用户从“主 AI 入口”进入系统，由主 Agent 统一承担对话、意图识别、澄清、高层计划、上下文组装和最终回复。
2. 系统主骨架是“受控编排器”：平台代码控制路由、状态、任务契约、权限、超时、重试上限、预算、checkpoint、Trace 和停止条件。
3. Agent 并不是被写死的流程节点；在受控边界内，Agent 可自行判断信息是否足够、如何澄清、如何分类错误、是否重试、如何调整分析计划以及何时停止。
4. 意图分为四条路径：“口径咨询”、“取数查数”、“经营分析”、“通用兜底”。
5. 口径咨询由主 Agent 直接完成，不要新增“咨询 Agent”。
6. 取数 Agent 是全系统共享的可信数据执行能力；直接取数和分析 Agent 内部的取数任务都必须经过它。
7. 固定分析和开放分析共用一个分析 Agent，通过加载不同 Skill、计划模板和报告模板区分；不要把每类分析画成新 Agent。
8. 开放分析采用 B 方案：主 Agent 先形成高层计划并组装完整上下文，然后将完整 `AnalysisTask` 交给分析 Agent；分析 Agent 内部自主完成详细计划、取数拆分、证据解释、迭代下钻、画图和报告。
9. 未命中已知意图时，通用兜底 Agent 只做能力探索、问题澄清和重新路由，不得绕过专业 Agent 直接访问底层数据工具。
10. 最终结果统一回到主 Agent，由主 Agent 结合对话上下文封装并回复用户。

## 二、画布和布局

- 画布：横向 16:9 或更宽，高清矢量架构图，白色或很浅的中性背景。
- 标题：“数据经营分析 Agent 理想架构拓扑图”。
- 主方向：整体从左向右，每条分支内部从上向下。
- 不要把所有节点排成一条长蛇，也不要让连线大量交叉。
- 使用游泳道或清晰分区，从上到下分为五层：
  1. 交互与入口层。
  2. 受控编排与意图路由层。
  3. 业务 Agent 与 Skill 层。
  4. 数据 Tool 与公司数据源层。
  5. 共享能力与横切治理层。
- “受控编排器”用一个大的虚线容器表示，包住主 Agent、意图路由、取数 Agent、分析 Agent、通用兜底 Agent 及其状态转移。
- “数据工具与公司数据源”在受控编排器边界之外，仅通过授权 Tool Gateway 访问。
- “共享上下文、知识与记忆”和“横切治理”放在图底部，作为多个节点共用的底座，不要与主流程线混在一起。

## 三、视觉语义

| 类别 | 建议颜色 | 形状 | 含义 |
| --- | --- | --- | --- |
| 用户与主 Agent | 蓝色 | 圆角矩形 | 交互、理解、高层计划与回复 |
| 受控编排器 | 灰蓝色 | 大虚线容器 | 平台代码控制边界 |
| 取数 Agent 与数据证据 | 绿色 | 圆角矩形 | 可信取数与可校验证据 |
| 分析 Agent 与分析 Skill | 橙色 | 圆角矩形 | 计划、下钻、可视化和报告 |
| 共享知识与记忆 | 紫色 | 横向底座 | 上下文、知识、记忆、历史经验 |
| 异常、拒答和人工审核 | 红色或暗红色 | 菱形/审核节点 | 异常、超界或高影响决策 |

连线规则：

- 粗实线箭头：主任务流和结果流。
- 细实线箭头：Tool/API 调用或数据传递。
- 虚线箭头：Agent 自主判断后触发的澄清、重试、计划调整和重新路由。
- 浅色无箭头关联线：知识、记忆、Skill 和治理能力的注入或约束。
- 所有线必须尽量使用直角折线，禁止大量斜线跨越整张图。

| Q10 | 数据证据校验 | 指标身份、业务适用性、时间、完整性、质量与权限 |

### 4.4 经营分析路径

| ID | 图上名称 | 图上副标题/职责 |
| --- | --- | --- |

| A2 | 分析方法命中？ | 匹配已沉淀的流量、商户、保费等分析方法 |
| A3 | 主 Agent 高层计划 | 确定任务目标、边界、上下文和交付要求，不在主 Agent 内执行详细分析 |
| A4 | `AnalysisTask` | 分析目标、范围、指标、渠道、时间、业务上下文、约束、Skill 和报告要求 |
| A5 | 分析 Agent | 拥有完整分析任务，内部自主计划、取数编排、证据解释、迭代下钻、画图和报告 |
| A6 | 固定分析 Skill | 已沉淀的分析路径、所需信息、分析步骤、停止条件和输出模板 |
| A7 | 开放分析 Skill | 通用分析原则、证据要求、下钻规则、停止规则和报告结构 |
| A8 | 详细分析计划 | 分解取数子任务，决定下钻顺序与停止条件 |
| A9 | 证据解释与迭代 | 根据 `DataEvidence` 决定继续下钻、调整计划或停止 |
| A10 | 计算与可视化 Tool/Skill | 与证据一致的统计、图表选择和可视化生成 |
| A11 | 报告撰写 Skill/模板 | 结论、证据、图表、不确定性和未解决项 |
| A12 | 报告校验 | 标准指标名、数值一致性、证据引用、权限与格式 |
| A13 | `AnalysisResult` | 结论、证据、图表、报告、不确定性、未解决项和 Trace |

## 六、“受控”与“自主”的边界

请在图右侧增加一个紧凑的双列说明区，不要将下列内容都连成流程线。

| 平台代码确定性控制 | Agent 在边界内自主决策 |
| --- | --- |
| 可进入哪些路径 | 当前信息是否足够 |
| 任务契约和 Schema 是否合法 | 具体追问什么 |
| 可以使用哪些 Tool 和数据 | 如何选择受权工具 |
| 超时、成本、循环次数和重试上限 | 如何分类错误和选择恢复方式 |
| checkpoint、Trace、日志和审计 | 分析的详细下钻计划 |
| 高影响操作的人工审核门禁 | 在边界内继续、调整还是停止 |

图中应有一句总结性标注：

> 平台代码定义边界和停止条件，Agent 在边界内理解问题、澄清、计划并处理可恢复错误。

## 七、不可改变的架构约束

1. 不得创建独立的“口径咨询 Agent”。
2. 不得把流量分析、商户分析、保费分析、开放分析分别画成四个 Agent；它们是同一分析 Agent 加载的不同 Skill/计划模板。
3. 不得让主 Agent 对开放分析进行详细执行拆分；主 Agent 只负责高层计划、任务边界和上下文组装。
4. 不得让分析 Agent 绕过取数 Agent 直接访问指标接口或数仓。
5. 不得让通用兜底 Agent 拥有全部底层工具；其目标是重新找到受控路径。
6. 不得将所有决策都画成平台硬编码；Agent 必须保留澄清、错误判断、详细计划和停止判断的自主性。
7. 不得只把“取数结果”当作一组数字；必须体现为含标准指标身份、来源、质量和 Trace 的 `DataEvidence`。
8. 不得画成每遇到错误都立即失败或每次都询问用户；取数 Agent 可在受控上限内自主修复参数、切换授权方法或重试，仅在需要新的用户信息时回到主 Agent 澄清。
9. 工作流不是默认的分析执行主体；若要表示 Workflow，只将其画为固定分析中的计划模板或硬门禁，不画为与分析 Agent 平级的执行者。

## 八、输出验收要求

绘图完成后，请自检：

- 第一眼能否看到“用户 → 主 Agent → 意图路由 → 专业路径 → 主 Agent → 用户”主链路。
- 是否只有主 Agent、取数 Agent、分析 Agent、通用兜底 Agent 这些主要 Agent 角色。
- 是否清楚区分了 Agent、Skill、Tool、平台编排和数据源。
- 分析 Agent 是否通过共享取数 Agent 获取数据，并形成可迭代回路。
- 是否同时体现平台确定性控制和 Agent 的有界自主决策。
- 是否显示 `QuerySpec`、`AnalysisTask`、`DataEvidence` 和 `AnalysisResult` 四个关键任务/数据契约。
- 是否避免字号过小、节点堆叠、线条交叉和把说明文本塞入每个节点。
- 如果一张图无法保证可读性，可在同一张画布中使用“主拓扑 + 取数回路局部放大 + 分析回路局部放大”，不要通过缩小字号强行塞进一张图。

## 九、最简拓扑摘要

```text
用户
  → 主 AI 入口
  → 主 Agent（意图、澄清、高层计划、上下文组装）
  → 受控意图路由
      ├─ 口径咨询
      │    → 主 Agent 澄清
      │    → 只读元数据工具
      │    → 口径证据
      │    → 主 Agent 回复
      │
      ├─ 取数查数
      │    → 主 Agent 澄清
      │    → QuerySpec
      │    → 取数 Agent
      │    → Tool Gateway
      │    → 日期/指标/计算工具
      │    → 公司数据接口、指标平台、数仓服务和缓存
      │    → DataEvidence
      │    → 证据校验
      │    → 主 Agent 回复
      │
      ├─ 经营分析
      │    → 主 Agent 澄清和高层计划
      │    → 命中固定分析 Skill 或加载开放分析 Skill
```
