# Agent 停止与换方向：实施细节 v0.3

> 2026-09-12。用户已授权实现与试用。实现依据为[方案 v0.2](2026-09-12-Agent停止与换方向技术方案-v0.2-AI草案.md)。本文件先描述实施契约，验收结果另附；不能把计划视为已通过。

## 用户操作

- 运行时可以输入草稿；“停止”只结束当前执行。
- “停止并发送”把新问题持久化，等旧执行的所有本地分支退出后自动执行。
- 同一会话最多一条待启动请求。重复提交同一 request_id 幂等；不同第二条请求不覆盖第一条。
- 新问题使用新 LangGraph thread_id。原任务及部分数据保留在 Trace，聊天中不伪装成成功报告。
- 当前的一次模型请求或工具调用允许完成；下一次模型、工具、补查和重试之前检查停止。多指标并行时所有分支共享停止标记。
- 只停止当前 request_id，旧标签页的停止操作不能作用到后来启动的新请求。

## 控制与业务分开

现有 ChatStore.send 持有会话文件锁。新增 RunControl 与独立 SQLite 控制库；停止接口只操作控制库和取消句柄，不等待会话锁。

普通执行、停止并发送、自动交接都经过同一准入控制器。旧执行退出、保存会话并释放文件锁后，才启动下一条请求。因此不需要把主图改成完整事件队列，也不需要同时更新两份会话副本。

控制库保存：
- runs：conversation_id、request_id、thread_id、问题、运行状态、取消状态及时间。
- pending_requests：新 request_id、旧 expected_request_id、问题、queued / starting / started / completed / interrupted 状态。

外部控制 API：
- POST /api/stop：id、expected_request_id。
- POST /api/replace：id、expected_request_id、新 request_id、text。
- GET /api/control?id=...：当前执行、取消状态、待启动请求与交接后的 ID。
- /api/message 继续兼容原调用和 SSE；只增加统一准入。

## 取消句柄

RunCancelled 是专用的正常控制信号。检查放在模型与查询前后、worker 或模型名额获取后、重试前、汇总和发布前。宽泛异常处理必须让它传播，不得触发失败兜底报告。

Trace 绑定同一取消句柄；模型返回后先记录实际 usage，再退出。流式模型的旧片段只保留到内部轨迹，服务端和网页按 request_id 屏蔽取消后的公开输出。

查询包装器生成模拟 query_id 并登记取消回调。取消接口独立清理；模拟成功/失败、查询 ID 迟到均写 Trace。真实平台仍不接入。

## 状态及交接

running → cancelling → cancelled；完成用 completed，其他异常用 failed。停止接口的“已受理”不等于旧本地线程已退出。

所有 worker 都结束后，主图记录取消终态。服务端保存取消消息和真实用量，释放旧会话锁，再运行待启动请求。

“改成本周”附带旧问题与已确认查询范围作为解释背景；不附带旧任务未验证的分析结论。新问题仍重新走标准指标、维度、日期与证据校验。

刷新通过控制库恢复待启动文字及当前任务。进程重启把遗留 running / starting 标为 interrupted，不自动重放付费执行，保存输入供用户重试。

## 验收

1. 查询和模型等待中取消；停止后不出现下一次调用。
2. 5 个并行分支退出完后才启动替代问题，排队分支不再取数。
3. 取消后模型真实 usage 保留、失败不触发重试。
4. 取消查询成功、失败、ID 迟到及重复取消。
5. 重复 replace、旧 expected_request_id、同会话两条待启动请求。
6. SSE 旧 delta / done 不覆盖新回复，刷新可恢复，停止与自然完成竞争。
7. “改成本周”继承所指指标、替换日期，不继承取消的结论。
8. 原测试回归、浏览器操作、少量真实 Kimi 验收。
