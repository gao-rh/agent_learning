# 渠道归因

版本：demo-v1。依据当前项目手册整理的实验方法，不是公司线上Skill原件。
## 目的与步骤
1. 先确认目标是曝光、点击还是加入商户数；渠道归因不是指标名。
2. 查询总体变化，按指标支持的一级渠道拆分，识别变化幅度大的分组。
3. 根据第一步结果选择一项：围绕某个渠道补查获客来源；或在支持时看二级渠道。
4. 将流量规模变化与结构变化作为候选解释；缺活动/投放/改版证据时不确认业务原因。
5. source 是从商家端APP、电销等获得客户；channel 是APP栏位等入口，两者不能互换。
不同指标模拟立方体覆盖范围不一致，禁止直接把曝光UV、点击UV、加入数相除当作统一漏斗转化。

## 执行约定
读取指标定义与支持维度后再行动。先比较本期与前期，再根据已返回结果选择补查。
可以提出错误的假设，但必须明确它是待验证假设。不要把相关变化称为已证明的因果。
选择 compare 时写清楚为什么查、检验哪个假设；若已有相同范围证据则复用。
只有原任务允许的指标、期间和筛选范围可查。补查可增加合法过滤或细分，不能取消用户条件。
最多两次补查；证据已足够或维度不支持就结束。遇到数据不足要记录限制。
结束时列出发现、假设、证据ID、尚需什么证据。所有数值由工具计算，来源是模拟数据。
