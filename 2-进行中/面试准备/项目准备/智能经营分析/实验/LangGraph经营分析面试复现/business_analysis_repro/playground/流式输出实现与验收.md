## 现在能看到什么

- 检索、计划拆分、每个并行分支的执行状态实时更新。
- 分支完成后，其完整表格先显示；标题区分“取数 Agent”和“分析 Agent”。
- Kimi 生成摘要时，实际收到一个文字片段就显示一个片段。生成期间标注“草稿待校验”，复核后用正式结果替换。
- 明细位于长回答之前；单指标默认展开，多指标可逐项展开。“查看上次明细”仅展示上一条结果，不再次调用模型或取数。
- 连接短暂中断后自动重连；执行中刷新页面也会恢复同一轮进度。

## 三种数据不要混淆

| 数据 | 现在放在哪里 | 作用 |
| --- | --- | --- |
| 最终计划、结果、草稿和验证状态 | LangGraph State / SQLite checkpoint | 图执行与澄清恢复 |
| 实时进度、每个 answer_delta、模型请求/响应和用量 | Trace JSONL | 回放与 SSE 补读；每个文字片段不会变成一个 checkpoint |
| 本轮 request_id、active 任务、消息与结果卡片 | conversation.json | 网页刷新后重新找到任务、展示完整对话 |

本版继续用 LangGraph `graph.stream(values/updates)` 记录图的状态变化，并在摘要模型的 `ChatOpenAI.stream` 上记录实际文字片段。SSE 是网页传输适配，没有新增一个 Agent 或新的图节点。官方也提供 messages/custom 等流模式，本次沿现有 Trace 做只读投影以复用回放与重连数据源。[LangGraph 官方流式文档](https://docs.langchain.com/oss/python/langgraph/streaming)

## 事件与异常怎么处理

- `plan / job / card`：只发送页面需要的拆解、分支状态和表格。原始 State、规划工具 JSON 和完整模型请求仍留在 Trace，不作为对话正文输出。
- `answer_start / answer_delta / answer_end`：开始草稿、追加真实片段、进入复核。它们不是最终交付标志。
- `answer_reset`：网络中断等失败后撤回本次未完成草稿，重试从空文本开始。最多2次生成尝试，仍受40次任务调用预算限制。
- `done`：持久化的最终对话，是客户端最终状态的依据。校验不通过的草稿不会以正式答案保留。
- 浏览器带 `Last-Event-ID=request_id:seq` 自动重连，服务端只补读未收到的事件。完整刷新会重放本次输入的进度；澄清之前的旧事件按 stream_after_seq 跳过。
- SSE 10秒心跳；180秒无新事件会提示刷新。流式连接不负责取消执行，关闭页面后任务仍可能继续产生模型用量。
- 同一个 request_id 的已完成 POST 重发返回已有结果；同会话执行中的第二个 POST 被会话锁拦截，不启动第二份任务。
