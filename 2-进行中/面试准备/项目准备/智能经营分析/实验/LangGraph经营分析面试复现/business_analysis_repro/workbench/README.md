# Data Agent 工作台

统一入口：[http://127.0.0.1:8787/](http://127.0.0.1:8787/)。双击项目根目录的 `启动DataAgent工作台.command`，或在项目根目录执行：

```bash
./启动DataAgent工作台.command
```

启动器复用已运行的工作台，在本机后台启动服务，PID 和日志保存在 `.runs/workbench-services/`。启动、浏览报告和查看轨迹均不请求模型；在对话页发送问题后才调用既有 Kimi 执行链路。业务数据仍为本地模拟数据。

## 页面与导航

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 对话首页 | `/` | 原有对话、流式回复、停止和消息插入；切换页面后恢复当前会话和输入草稿 |
| 测试报告 | `/reports` | 按测试时间列出所有符合报告命名约定的历史报告 |
| 完整报告 | `/reports/<报告ID>` | 渲染原 Markdown，保留目录、稳定锚点及原文入口 |
| 完整案例 | `/case/<批次>/<案例>` | 查看初始诉求、各轮对话和每轮动作；携带来源报告身份 |
| 单轮轨迹 | `/case/<批次>/<案例>/trace?turn=<轮次>` | 独立地址，只展开该轮的步骤和事件，提供完整案例与报告返回入口 |
| 项目资料 | `/docs` | 项目介绍、运行说明、执行链路、指标维度、Skill 与 Agent 经验 |

所有页面共用“对话 / 测试报告 / 资料”导航。报告进入案例时携带 `report` 参数，返回时保留对应报告，而不是跳到最新结果。聊天原有的 `/flow`、`/trace`、`/usage`、`/knowledge` 页面也接入导航。历史 8788 案例查看器和 8770 阅读页仍可独立使用。

## 实现边界

工作台是既有本地服务的薄入口，不另建 Agent 执行器，也不重跑历史结果。报告从项目根目录的 `测试报告-v版本-YYYY-MM-DD-HH-MM-SS.md` 自动发现，批次和轨迹沿用 `.runs` 中的固定记录。

文档直接读取登记的 Markdown 原件，阅读器复用 markdown-reader 的解析器与目录布局；不复制文档正文。登记之外的文件不会作为文档提供。iCloud 原件读取复用案例查看器的限时读取和本机缓存机制；原件未就绪时明确显示读取问题。

对话沿用现有 ChatStore、SSE、checkpoint 和运行控制库。浏览页面不触发模型请求。历史对话按需读取；草稿仅存在当前浏览器。执行与评分边界沿用原实验：复杂澄清计划确认不等于执行或业务通过。

## 离线验证

`tests/test_workbench.py` 验证报告按时间排序、来源报告身份、文档白名单与 HTML 转义、单轮原始事件隔离，以及报告导航前后既有会话保持。HTTP 检查使用替身执行器，不请求付费模型；流式回复、案例时间线和文件缓存复用对应回归测试。

2026-10-03 开发验收：相关离线回归 58 项通过。浏览器验证了报告列表、完整案例、独立单轮轨迹、返回对应历史报告、主页草稿与历史会话恢复，以及窄屏目录展开和 Escape 关闭。本次未新增真实模型调用；记录未就绪时提供重读入口，不把读取成功当作模型或业务正确性。
