# 理赔客服智能质检项目手册

> 2026-09-08 合并整理。做法和效果来自已保存的用户自述及本轮修正，文字为 AI 整理。本轮未执行公司代码、接入生产调度或取得统计明细。

## 1. 项目与职责

面向理赔客服通话中的辱骂、争辩、指责等服务态度问题，把人工抽检扩展为自动筛查、分级复核与人工确认。输入是平台已有 ASR 文本，用户不负责 ASR 或基础模型研发。

用户作为技术负责人，负责质检标准转译、Python 流程与工具、Prompt 迭代和评测，并与业务及质检人员协作。最新口述明确它是 **Python 确定性多阶段 Workflow**；模型负责阶段内判断，不把整体改写成自主多轮 Agent。早期 Friday／Skill 表述已被后续交接纠正。

## 2. 从通话到人工确认

| 环节 | 作用与已有说明 |
| --- | --- |
| ASR 文本输入 | 使用已有转写；语气、环境音和说话人标签错误会影响判断 |
| 关键词预筛 | 从大批量输入中筛选候选，兼顾成本与召回；全流程召回不能只看后段模型 |
| 内部模型初审 | 在受控环境内依据违规规则审查候选 |
| 规则与 AI 脱敏 | 对需外部复核的文本识别、替换敏感信息，尽量保留判断所需语义 |
| 外部模型复核分级 | 复核逻辑与证据，并做 A/B/C 分级；具体当前分级规则需来源支持 |
| 人工确认 | 专业质检人员确认违规，形成业务处理与迭代输入 |

后期口述与简历记录保留的交付机制包括日均万级批处理、完整性校验、失败重试与日报通知。C02 原附件曾展示锁、心跳、幂等、模型调用、报告及通知等候选资产；静态文件不能单独证明每一项当前都在运行。

## 3. Prompt 如何持续改进

线上真实 Case 与人工复核结果回流，AI 据此自动调整 Prompt，再通过自动化评测检查效果。这里是提示词调整，不是基础模型参数微调。

可以从“实际误判 → 人工结论 → 调整规则或提示 → 回归评测”解释闭环。新 Prompt 是否自动发布、准入条件、审核人与回滚方式尚未完整说明；不能从“自动调整和评测”推导出无人审核自动上线。

旧材料中的角色标签校验和脚本换位保留为历史细节；是否仍存在于最终每条链路，讲该细节时再核对。

## 4. 评测与结果

以下按后期口述及本轮确认保留，不是本轮独立复算结果。

| 指标或结果 | 当前说法 | 边界 |
| --- | --- | --- |
| 通话量 | 日均约 1 万条 | 后期规模；早期“数千条”只代表原记录阶段 |
| 质检覆盖 | 约 5% 提升至 100% | 指流程覆盖，不代表每通都进入外部模型，也不是召回率 100% |
| 人力 | 释放约 1 名专业质检员人力 | 不推导组织裁撤或额外成本金额 |
| 问题发现 | 周均确认严重违规由 2–3 条提升至 7–10 条 | 不额外推算精确倍数；统计时间与明细未核验 |
| 样本集 | 376 条，三人交叉标注 | 不命名为独立盲测集，不用“高准确率样本集”替代标注说明 |
| 离线召回 | 97% | 既有评测集口述；正样本数与混淆矩阵未取得 |
| 线上查准率（Precision） | 85% = 人工确认违规数 ÷ 模型标出的疑似违规数 | 用户本轮已确认：例如报出 100 条，其中 85 条人工确认违规；不是全部通话的 Accuracy，也不是 Recall |
| 客诉变化 | 客诉率相对下降约 14% | **用户本轮明确确认是实际数据，应保留**；原“预测所以删除”的处理不再沿用。统计窗口及独立归因证据未取得 |

14% 使用“相对下降”，不能改成下降 14 个百分点，也不直接宣称全部下降由本项目单独造成。线上 85% 的分母是模型标出的疑似违规数；离线 97% 召回率的分母是评测集实际违规数，两者分别报告。

## 5. 为什么有这么多旧数字

| 历史材料 | 它实际说明什么 | 当前处理 |
| --- | --- | --- |
| C01 情绪指数探索 | 2025 年 5–8 月的早期方案，文本难以表达语气，后来放弃连续情绪估计 | 保留演进，不作为当前定义 |
| C01 规则线下调试 | 2025 年 9–11 月，辱骂子模型与人工一致性约 60%，当时未线上应用 | 阶段事实，不能覆盖后期链路 |
| 原首页约 30% | 早期风险检测效果，口径与阶段不完整 | 归档，不作为当前效果 |
| C01 的 1000／200 条评测计划 | 当时计划与启动数量 | 不覆盖后期 376 条样本 |
| C02 约 1500／6700 条任务、C03 三日专项 | 特定任务、包内自记录或专项窗口 | 不等于当前日均规模或统一评测集 |
| 后期 376／97%／85% | 新增样本集与效果口述 | 当前采用，分别保存边界 |

早期探索与后期流程可以同时成立，不再把“仍是早期探索”当作项目最新结论。C01 的计划日期仍不自动代表每个子场景按期上线。

## 6. 脱敏子链路如何讲

已确认思路是规则识别强格式信息、受控模型补充语义判断，再校验位置并确定性替换，将脱敏文本传给外部模型。脱敏是隐私边界，与违规分类分开评价。

公开实验 3-3 可以解释相同方法的取舍：规则误删、语义遗漏、坏 JSON、降级和性能波动。其 Ollama／Qwen3、12 案例数据与指标属于公开复现，不能写成公司模型或项目效果。代码示例和详细指标只保留在[脱敏子链路材料](脱敏子链路实现与面试重点.md)。
