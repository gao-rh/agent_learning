## A. 数据工程与流水线（Q01—Q10）

### Q01｜P0｜如何设计一条多模态训练数据流水线？

**来源性质：JD 延伸。**

**参考答案：**我会先明确训练任务、样本单位和验收指标。例如图文问答的一条样本是图片、问题、答案及来源，不是一个文件。流水线分为接入登记、解码校验、标准化、去重、跨模态关联、清洗与质量打分、标注或合成、分集、发布。具体顺序需要按成本和依赖调整：便宜的坏文件检查应尽量早做，昂贵的模型调用放在必要的筛选之后。

每条样本保存原始来源、稳定 ID、父样本 ID、处理与标注版本；每次运行保存输入清单、算子版本和输出统计。近重复、同一视频切片等先建立分组约束，防止跨训练集和测试集。最终交付可复现的数据集清单、质量报告和读取方式。

**追问：**清洗后数量少了 30% 怎么判断对错？核对每个算子的过滤量与原因，按来源、类别、模态抽查被删和保留样本，并评估长尾覆盖与下游效果。

### Q02｜P1｜一个可复用的数据算子需要具备什么能力？

**来源性质：JD 延伸。**

**参考答案：**算子先有清晰的输入输出协议，区分一进一出的映射、筛选、去重、聚合和一进多出的切片。配置要显式传入，输出包含处理结果、原因码和必要统计，不能仅靠日志解释。执行上要考虑批量处理、资源需求、失败分类、可重跑，以及单机和分布式环境的一致语义。

例如图片清晰度算子应输出分数和模型/阈值版本；筛选策略再决定是否保留。保留分数便于重新设阈值，而不必重做全部解码和推理。接入流水线时还要验证组合后的吞吐、成本和数据分布变化。

**追问：**算子越多越好吗？不一定。存在重复成本和误删叠加；先验证每个算子对坏样本识别和下游效果的增益。

### Q03｜P1｜RDD、DataFrame 有什么区别？为什么通常优先使用 DataFrame？

**来源性质：JD 延伸的 Spark 基础练习；未找到近期同岗原题证据。**

**参考答案：**RDD 更接近分布式对象集合，提供较底层的变换接口；DataFrame 有字段和类型，Spark 可以理解表达式与关系运算，从而优化执行计划。结构化清洗、关联、聚合通常优先用 DataFrame 和内置函数，避免把可优化的逻辑塞进黑盒 UDF。

两者都有惰性计算：定义变换时主要是在构建计算依赖，动作触发执行。RDD 的自定义能力有用，但要承担更多类型、序列化和执行优化成本。Python UDF 还可能带来跨进程与序列化开销，不能仅按代码行数评价性能。

**追问：**什么时候缓存？同一昂贵中间结果被多次复用且资源足够时；一次性结果不应习惯性全部缓存。

依据：[Spark 编程指南](https://spark.apache.org/docs/latest/rdd-programming-guide.html)、[SQL 性能调优](https://spark.apache.org/docs/latest/sql-performance-tuning.html)。

### Q04｜P1｜什么是 Shuffle？哪些操作容易触发？

**来源性质：JD 延伸的 Spark 基础练习；未找到近期同岗原题证据。**

**参考答案：**Shuffle 是为后续计算重新分配数据，让相关记录到达同一个分区。按 key 聚合、某些 Join、全局排序和重新分区都可能触发；具体以物理计划为准。主要成本来自网络传输、序列化、落盘和长尾任务。

优化先减少需要搬运的数据：提前过滤与列裁剪、能局部聚合则先聚合、为合适的小表选择广播，再检查分区规模和倾斜。不能只说“多加分区”；分区过细会增加调度和小文件成本。广播 Join 也有内存和广播耗时约束。

**追问：**为什么一个任务拖很久？检查该分区输入量、热点 key、spill、GC、远端读取和失败重试，而不是直接认定资源不够。

### Q05｜P1｜数据倾斜如何定位和处理？

**来源性质：JD 延伸的数据调优练习；未找到近期同岗原题证据。**

**参考答案：**先确认慢在 Join、聚合还是读取，观察各任务的记录量、Shuffle 读写、运行时间和 spill，再统计热点 key。处理方案按原因选择：空值或默认值可分路；小表可广播；热点聚合可加盐做两阶段聚合；热点 Join 可拆分单独处理；执行引擎支持时也评估 AQE。

加盐不能破坏语义。例如 SUM 可以先按“原 key＋盐”求和，再按原 key 汇总；AVG 应合并 sum 与 count，不能平均各分区的平均数。Join 加盐时要让另一侧匹配到对应盐值，不能两侧独立随机加盐。先验证结果一致，再比较资源和耗时。

**追问：**COUNT DISTINCT 能直接两段相加吗？不能，同一元素可能落在多个盐分区，需要先保证去重归属，或使用符合精度要求的可合并估计结构。

### Q06｜P1｜为什么会有小文件问题？Parquet 为什么适合分析？

**来源性质：JD 延伸。**

**参考答案：**小文件会增加文件枚举、元数据访问、打开文件和任务调度开销，实际读取的数据可能很少，固定成本却很高。常见原因是分区过细、频繁微批写入、输出并行度与数据量不匹配。应结合读写模式控制分区，合并适当大小的文件，并安排压实任务。

Parquet 按列组织，支持压缩和按列读取；row group 的统计信息在适用条件下可以帮助跳过数据。它适合分析型扫描，但“用了 Parquet”不代表任何查询都更快。多模态原始大文件可留在对象存储，表中记录 URI、版本、大小、校验和与元数据，再按训练访问模式选择打包方式。

**追问：**所有图片都存成表内二进制好吗？取决于大小、访问局部性和读取器；要实测随机读取、顺序吞吐、解码与元数据成本。

依据：[Apache Arrow：Parquet 读写](https://arrow.apache.org/docs/python/parquet.html)。

### Q07｜P0｜任务失败重跑，如何避免重复数据和重复费用？

**来源性质：JD 延伸、项目追问。**

**参考答案：**先区分业务样本身份和处理版本。可用“输入对象及版本＋处理配置版本”确定幂等键，记录任务状态和输出清单。输出先写临时位置，校验成功后发布；发布方式要遵循具体存储的原子性，不假设对象存储的改名等同本地文件系统。失败重跑只补缺失分片，或者重算后按幂等键覆盖。

外部模型调用要单独处理：提交前后记录请求标识，服务支持时使用幂等键；超时后先判断是否可查询原请求，不能认为没收到响应就没执行。无法消除的不确定性应进入待核对状态。我的质检项目可以作为批次核对和重试的经历，但完整事务式提交属于这里的设计建议。

**追问：**有 checkpoint 就是端到端 exactly-once 吗？不是，还取决于数据源回放、状态恢复和外部写入协议。

### Q08｜P1｜Flink 的 checkpoint、事件时间和 watermark 怎么理解？

**来源性质：JD 延伸。**

**参考答案：**事件时间是业务事件发生的时间，处理时间是系统处理它的时间。watermark 表示系统对事件时间进度的判断，用来触发窗口等计算；它不保证以后绝无迟到数据。迟到事件要有明确的接收范围、更新策略或旁路处理。

checkpoint 保存一致的算子状态与源位置，失败后恢复并重放。端到端 exactly-once 还要求源可回放，以及下游支持事务提交或幂等写入。流式数仓面试里我会用“订单晚到、退款更晚到”说明：最终统计既要有时效，也要有补偿与对账规则。

**追问：**重放会不会再次请求模型接口？可能；外部请求并不会因为算子状态恢复而自动撤销，需要独立的结果记录和去重机制。

依据：[Flink 容错机制](https://nightlies.apache.org/flink/flink-docs-stable/docs/learn-flink/fault_tolerance/)。

### Q09｜P0｜海量样本调用模型做自动标注，如何提速和控成本？

**来源性质：JD 延伸、项目追问。**

**参考答案：**先去掉明显无效或重复样本，再分层：高确定性规则处理、低成本模型预标、困难样本使用更强模型或人工。调用侧同时限制并发、请求频率和 token 用量，使用有界队列形成背压；对限流和临时错误做指数退避加随机扰动，永久错误进入失败队列。

缓存键应包含输入内容、模型、Prompt 和关键参数版本；不能用旧标签静默覆盖新口径。评估用每个“合格样本”的成本和端到端吞吐，而不是只看请求每秒数量。并发过高可能放大超时、重试和重复费用。

**追问：**低成本模型置信度高就一定可以接受吗？不可以，置信度需在代表性标注集上校准，并保留抽检。

### Q10｜P1｜一条数据任务突然变慢，你会怎么排查？

**来源性质：JD 延伸。**

**参考答案：**先与正常批次对比输入规模、数据分布、代码配置和外部依赖，再拆分读取、解析、计算、Shuffle、模型调用和写入各阶段耗时。重点分清是整体吞吐下降还是少数任务长尾。

例如多模态任务 CPU 很忙、GPU 利用率低，可能卡在解码和预处理；GPU 空闲且网络等待高，可能卡在对象存储；只有一个分区慢，应查热点和超大样本。优化后不仅比较耗时，还检查结果数、质量分布、成本及失败率，避免以漏处理换速度。

**追问：**你最先加哪些监控？输入输出量、拒绝原因、分阶段耗时、队列积压、资源利用率、重试量，以及分来源/模态的质量分布。

### Q11｜P1｜每个样本保留最新的一条标注记录，怎么写？

**来源性质：SQL 基础练习，使用标注数据场景改写；未找到近期同岗原题证据。**

**参考答案：**用 `ROW_NUMBER` 在样本内排序，先按更新时间，再按唯一且有确定顺序的标注记录 ID 打破平局。要先确认同一 `sample_id` 是否包含多个独立任务；如果有，分组键应加入 `task_id`。

```sql
-- annotations(sample_id, label, updated_at, annotation_id)
-- annotation_id 唯一；NULL 更新时间放到最后。
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (
    PARTITION BY sample_id
    ORDER BY updated_at DESC NULLS LAST, annotation_id DESC
  ) AS rn
  FROM annotations
)
SELECT sample_id, label, updated_at, annotation_id
FROM ranked
WHERE rn = 1;
```

**追问：**先过滤“审核通过”还是先取最新？语义不同：前者取最新通过记录；后者检查当前最新状态。按业务要求决定。

### Q12｜P1｜按类别取质量分最高的前三条，并列怎么办？

**来源性质：SQL 窗口函数基础练习；未找到近期同岗原题证据。**

**参考答案：**严格最多三条用 `ROW_NUMBER` 并提供稳定的次序；前三个不同分数档位用 `DENSE_RANK`；竞赛排名用 `RANK`。例如 100、100、90、80 的 `RANK` 是 1、1、3、4，`DENSE_RANK` 是 1、1、2、3。

```sql
-- samples(category, sample_id, quality_score)
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (
    PARTITION BY category
    ORDER BY quality_score DESC NULLS LAST, sample_id ASC
  ) AS rn
  FROM samples
)
SELECT category, sample_id, quality_score
FROM ranked
WHERE rn <= 3;
```

**追问：**改成前三个分数档位时，可以保留 `sample_id` 在窗口排序里吗？不可以，否则不同 ID 会打散同分档位。

### Q13｜P1｜找连续登录至少三天的用户，怎么写？

**来源性质：SQL 备考推导题，不声称是该岗位原题。**

**参考答案：**先把时间转为业务日期，并按用户、日期去重。日期减去用户内的顺序号后，同一连续区间会得到同一个值，据此分组即可。先约定业务时区；跨时区日志不能直接截日期。

```sql
-- logins(user_id, login_time)
WITH days AS (
  SELECT DISTINCT user_id, TO_DATE(login_time) AS dt
  FROM logins
  WHERE login_time IS NOT NULL
), numbered AS (
  SELECT user_id, dt,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY dt) AS rn
  FROM days
), grouped AS (
  SELECT user_id, dt, DATE_SUB(dt, CAST(rn AS INT)) AS grp
  FROM numbered
)
SELECT user_id, MIN(dt) AS start_dt, MAX(dt) AS end_dt,
       COUNT(*) AS consecutive_days
FROM grouped
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

**追问：**有的人一天登录十次呢？第一步去重，否则顺序号会破坏日期连续性的判断。

### Q14｜P1｜按首次活跃日计算次日留存，分子分母是什么？

**来源性质：SQL 备考推导题。**

**参考答案：**分母是首次活跃日在某天的用户数；分子是这些用户中恰好在下一自然日活跃的人数。必须使用用户完整历史确定首次活跃，并排除还没有完整次日观察窗口的 cohort。若业务定义是“注册次日留存”，分母应换为注册表。

```sql
-- activity(user_id, dt)；dt 为业务日期，当前数据完整至 2026-09-14。
WITH days AS (
  SELECT DISTINCT user_id, TO_DATE(dt) AS dt
  FROM activity
  WHERE dt IS NOT NULL
), first_day AS (
  SELECT user_id, MIN(dt) AS first_dt
  FROM days
  GROUP BY user_id
)
SELECT f.first_dt,
       COUNT(*) AS cohort_users,
       COUNT(d.user_id) AS retained_users,
       1.0 * COUNT(d.user_id) / COUNT(*) AS retention_d1
FROM first_day f
LEFT JOIN days d
  ON f.user_id = d.user_id
 AND d.dt = DATE_ADD(f.first_dt, 1)
WHERE f.first_dt <= TO_DATE('2026-09-13')
GROUP BY f.first_dt;
```

**追问：**为什么条件放在 ON？右表日期条件若放 WHERE，会过滤掉未留存用户，改变左连接的分母。

### Q15｜P1｜最近七天累计，用 ROWS 还是 RANGE？

**来源性质：SQL 窗口函数基础练习；未找到近期同岗原题证据。**

**参考答案：**`ROWS` 按行数，`RANGE` 按排序值范围。只有每天恰好一行且日期完整时，“前六行加当前行”才等于七个自然日。同一天多行、缺日期都会让二者产生不同结果。

```sql
-- 假设 daily_stats 每个 model_id 每天恰好一行，已补齐无请求日期。
SELECT model_id, dt, request_count,
       SUM(request_count) OVER (
         PARTITION BY model_id ORDER BY dt
         ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
       ) AS requests_7d
FROM daily_stats;
```

**追问：**不补齐日期怎么办？按目标引擎使用时间区间的 RANGE，或关联目标日期之前六天至当天的数据再聚合；不能继续假设六行就是六天。

依据：[Spark 窗口函数](https://spark.apache.org/docs/latest/sql-ref-syntax-qry-select-window.html)。

### Q16｜P1｜Join 后金额翻倍，怎么修？NULL 有什么坑？

**来源性质：数仓/SQL 备考推导题、项目追问。**

**参考答案：**先检查连接两侧的粒度和键唯一性。订单金额是一单一条，订单明细是一单多条，连接后金额会随明细条数重复。应先把明细聚合到订单粒度再连接，或者在订单表上独立汇总；`SUM(DISTINCT amount)` 会误删金额相同的不同订单，不能通用修复。

```sql
-- orders: 每个 order_id 唯一；order_items: 一订单多条明细。
WITH item_agg AS (
  SELECT order_id, SUM(qty) AS total_qty
  FROM order_items
  GROUP BY order_id
)
SELECT o.order_id, o.amount, COALESCE(i.total_qty, 0) AS total_qty
FROM orders o
LEFT JOIN item_agg i ON o.order_id = i.order_id;
```

`COUNT(*)` 数行，`COUNT(col)` 忽略 NULL；`NULL = NULL` 不成立。`NOT IN` 的候选集合含 NULL 时可能让本应保留的行也无法通过过滤，反关联常优先考虑 `NOT EXISTS`，同时明确空键是否应保留。

**追问：**金额对了就足够吗？还要核对订单覆盖、键重复、退款口径、币种和分区范围。

依据：[Spark NULL 语义](https://spark.apache.org/docs/latest/sql-ref-null-semantics.html)。

### Q17｜P1｜手写字符串中最长无重复子串长度。

**来源性质：基础算法补位题，不是已查到的该岗位原题。**

**参考答案：**维护一个没有重复字符的滑动窗口，字典记录每个字符最近的位置。出现重复时，左边界移到上次出现位置之后，但只能向右移动。每个字符处理一次，时间 O(n)，空间 O(min(n, 字符集大小))。

```python
def longest_unique_substring(s: str) -> int:
    last = {}
    left = 0
    best = 0
    for right, char in enumerate(s):
        if char in last:
            left = max(left, last[char] + 1)
        last[char] = right
        best = max(best, right - left + 1)
    return best
```

**追问：**为什么要 `max`？`abba` 扫到最后的 a 时，上一次 a 已在窗口外；左边界若退回去，会重新引入重复字符。此代码按 Python 字符串码点计数；若题目按用户可见字形计数，需要额外定义分割规则。

### Q18｜P1｜数据流长度未知，如何均匀抽取 k 条数据？

**来源性质：数据工程场景的基础算法补位题。**

**参考答案：**用蓄水池抽样。前 k 条直接放入；第 i 条到达时，从 0 到 i−1 等概率抽一个位置，小于 k 则替换。处理到 n 条后，每条样本进入结果的概率都是 k/n；时间 O(n)，额外空间 O(k)。它保证均匀，不保证类别均衡。

```python
import random


def reservoir_sample(stream, k: int, seed=None):
    if k < 0:
        raise ValueError("k must be non-negative")
    if k == 0:
        return []
    rng = random.Random(seed)
    result = []
    for i, item in enumerate(stream, start=1):
        if i <= k:
            result.append(item)
        else:
            j = rng.randrange(i)
            if j < k:
                result[j] = item
    return result
```

**追问：**为什么早到的样本没有优势？已保留样本在后续每一步存活概率为 `(i−1)/i`，连乘后与后到样本一样得到 k/n。若需要长尾类别覆盖，应按类别分层分配配额，并记录抽样概率。

### Q19｜P1｜设计一张表时，为什么先说粒度？

### Q20｜P1｜ODS、DWD、DWS、ADS 怎么划分？

**来源性质：JD 延伸的数仓基础练习；未找到近期同岗原题证据。**

**参考答案：**常见约定是 ODS 保留源数据接入形态，DWD 做标准化的业务明细，DWS 沉淀可复用汇总，ADS 面向具体应用输出。名字不是统一强制标准，应先说明团队实际约定。分层价值是解耦来源、复用口径、缩小变更影响和方便追踪。

放到模型数据场景，源文件元数据、清洗/标注明细、数据集版本汇总、质量与模型效果看板可以分层组织；训练样本二进制是否进入某一层，取决于存储方案。不要为了层数齐全，对小规模一次性数据机械复制四份。

**追问：**怎样判断 DWS 值得建？看指标复用、口径稳定性、查询成本，以及维护和存储的代价。

### Q21｜P1｜三范式和维度建模怎么选？

**来源性质：数仓建模基础练习；未找到近期同岗原题证据。**

**参考答案：**三范式关注函数依赖，减少不合理冗余和更新异常；在通常的候选键定义下，第三范式要求非平凡依赖的决定因素是超键，或被依赖属性属于候选键。面试口述可以先用订单、用户信息反复更新导致不一致的例子解释，再按追问展开定义。

维度建模围绕业务过程组织事实与维度，强调分析时的可理解性和查询便利。两者服务的目标不同：事务系统通常更重视一致更新，分析层可以有受控冗余。建模选择还受变更频率、查询方式和维护成本影响。

**追问：**为什么星型模型也要维度表？共享一致的维度属性和历史口径，减少每张事实表各自解释用户或产品的差异。

### Q22｜P1｜事务事实、周期快照、累积快照有什么区别？

**来源性质：数仓备考推导题。**

**参考答案：**事务事实记录一次事件，例如一次模型请求或一次标注提交；周期快照按固定周期记录状态，例如每日各版本合格样本数；累积快照跟踪有明确里程碑的流程，例如一个标注任务从创建、分派、提交到验收。

累积快照经常更新同一流程实例的里程碑字段，不等于“每天全量存一份”。类型也不由 INSERT 还是 UPDATE 决定。选哪一种取决于要回答的问题：事件量、某时点库存，还是流程耗时。

**追问：**任务返工多次怎么办？累积快照保留关键里程碑，同时保留状态变更事件表，避免一行覆盖掉返工历史。

依据：[Kimball：累积快照](https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/accumulating-snapshot-fact-table/)。

### Q23｜P1｜SCD Type 2 如何保存历史？

**来源性质：数仓备考推导题。**

**参考答案：**当需要追踪的维度属性发生变化时，关闭旧版本的有效区间，新增一条新版本，并使用不同的代理键。常用半开区间 `[valid_from, valid_to)`，同一业务键各版本不应重叠。事实按事件时间匹配当时有效的维度版本。

必须区分“真实属性变化”和“历史错误修正”。迟到维度、回填历史以及时区边界都可能需要重新切分区间。每天复制全量维表是快照方案，不是自动等价于 SCD2。

**追问：**模型标签口径变了是否直接套 SCD2？可借鉴版本思想，但通常还应有独立的标签体系版本、迁移规则和数据集引用关系。

### Q24｜P1｜可加、半可加、不可加指标分别是什么？

**来源性质：数仓备考推导题、项目追问。**

**参考答案：**请求数、金额在相同口径的互斥分组间通常可加；账户余额能在同一时点跨账户相加，但不能跨日期直接相加，是半可加；比率、去重人数等通常不能直接加总。判断前必须明确维度、时间范围和是否重复。

例如整体成功率应为总成功请求数除以总请求数，不能把不同流量模型的成功率取简单平均。整体 P95 延迟也不能从各分组 P95 平均得到，需原始分布或可合并的分位数摘要。分母和可合并的基础量应一起保存。

### Q25｜P0｜AI 数据资产表至少有哪些字段？

**来源性质：JD 延伸。**

**参考答案：**我会把原始对象、加工样本、标注、处理运行、数据集版本和评测结果分开建模。原始对象保留来源、采集时间、权限/授权范围、URI、校验和；样本记录父对象、模态、切片边界和处理版本；标注保留标签体系、方法、审核和版本。

### Q26｜P1｜数据质量怎么治理？怎么定位某个指标突然变化？

**来源性质：JD 延伸、项目追问。**

**参考答案：**分结构质量、业务质量和任务适用性。结构上查空值、类型、唯一键、文件完整性；业务上查金额、状态和引用关系；模型数据还要查标签可靠性、模态一致性、重复、分布覆盖及测试污染。

### Q27｜P0｜预训练、SFT、偏好对齐分别需要什么数据？

**来源性质：JD 延伸。**

**参考答案：**预训练主要让模型从大规模语料学习表示与预测规律，重点在覆盖、清洗、重复率和混合比例。SFT 是有监督微调，通常提供输入及期望输出，强调任务格式、答案质量和指令覆盖。偏好对齐利用同一输入下输出之间的偏好关系，例如 chosen/rejected 回答；需要清晰、稳定的比较标准。

### Q28｜P0｜什么是高质量训练数据？如何证明清洗有效？

**来源性质：JD 延伸。**

**参考答案：**质量是相对于目标任务而言的。至少考虑正确性、完整性、可读性、相关性、多样性、难度覆盖、权限来源和无泄漏；不能只用一个模型评分代替全部维度。训练数据也不是越“标准、简单、流畅”越好，过度清洗可能删掉方言、长尾和真实复杂情况。

验证时先抽检保留与删除部分，测清洗器的误删和漏删；再比较类别、来源和难度分布。最终用受控实验看下游效果：尽量控制模型、训练预算和评测集，并同时报告样本量、token 量与成本，避免把更多训练量的收益归给清洗策略。

**追问：**质量分高但模型没变好怎么办？检查评分标准是否贴合任务、是否过度同质化，以及训练混合比例和测试集覆盖。

### Q29｜P0｜模型自动标注如何保证可靠？

**来源性质：JD 延伸、项目追问。**

**参考答案：**先把标签定义、边界案例和裁决规则写清楚，建立人工确认的校准集，再让模型按结构化格式输出标签和证据。评估分标签统计错误，选择自动接受、人工复核和拒绝的阈值；阈值应根据风险与人力成本确定。多人或多模型一致只能作为信号，不能自动当真值。

上线后同时抽检自动接受、人工复核和未命中的样本，保留模型、Prompt、标签规范和审核版本。我的质检项目可讲规则初筛、模型复核、人工确认的多阶段流程，以及 376 条、三人交叉标注的样本实践。交叉标注的具体独立性和分歧裁决方式，要按本人实际流程说明。

**追问：**只复核模型标出来的案例有什么问题？只能估计标疑样本的可靠程度，无法知道未标疑部分漏掉了多少真正问题。

### Q30｜P1｜人工标注不一致怎么办？主动学习怎么做？

**来源性质：JD 延伸、论文/项目追问。**

**参考答案：**先分清是人员理解不同、规范含糊，还是样本本身确有多义。标注者在互不影响下标同一批样本，观察一致率、分标签混淆和必要的一致性指标；将争议样本交由明确的裁决流程处理，并更新规则和示例。不能为了提高一致率，把所有难题都删掉。

主动学习可以优先送审高不确定、模型分歧和覆盖不足的样本，但要兼顾随机抽样与多样性，避免只挑异常点。被主动挑出的集合分布有偏，适合改善模型，不能未经校正就代表线上总体错误率。

**追问：**一致率很高就说明标得对吗？不一定，共同误解规范也会一致，需要外部标准、专家复核或明确的任务验收。

### Q31｜P0｜Precision、Recall、F1、Accuracy 怎么算？你的项目怎么讲？

**来源性质：JD 延伸、项目追问。**

**参考答案：**先指定正类，例如“真正违规”。TP 是标违规且真实违规，FP 是误报，FN 是漏报，TN 是正确放过。

| 指标 | 公式 | 回答的问题 |
|---|---|---|
| Precision | TP / (TP + FP) | 标出来的有多少真的违规 |
| Recall | TP / (TP + FN) | 真违规抓到了多少 |
| F1 | 2PR / (P + R) | 精确率与召回率的调和平均 |
| Accuracy | (TP + TN) / 总数 | 所有样本中判对多少 |

分母为零时要说明指标未定义或采用的实现约定。类别极不均衡时，全部判负也可能有很高 Accuracy，应看正类指标和分层结果。

**结合你的项目：**“线上模型标疑后经人工确认的比例约 85%，这是 Precision；离线召回约 97%，属于当时离线样本口径，不能直接当线上全量 Recall。覆盖率从抽检 5% 到流程覆盖 100%，描述检查范围，和 Recall 是不同指标。”这几个结果来自当前项目材料，本次未重算原始混淆矩阵。

**追问：**业务更怕漏报怎么办？可调阈值提高召回，同时量化误报带来的审核成本；不能把所有样本都标疑就宣称方案成功。

依据：[scikit-learn 模型评估](https://scikit-learn.org/stable/modules/model_evaluation.html)。

### Q32｜P0｜怎么构建一套有代表性的评测集？

**来源性质：JD 延伸。**

**参考答案：**先拆能力、任务、人群、来源、难度和风险，再按真实分布采样，同时补足低频高风险样本。保留正常、边界、异常和不可回答案例，给每题写清参考答案、可接受范围和评分方式。多模态还要覆盖模糊、遮挡、缺失、错配、长视频和跨模态冲突。

代表性主集用于估计整体表现，专项挑战集用于诊断弱点，两者分开报告。每个题集固定版本，记录来源、标注、分组和是否接触训练流程。更新评测集时同时跑旧集和新集，以区分模型变化与题目变化。

**追问：**测试集越难越好吗？不是。只有极难题会失去对真实业务流量的代表性，但完全没有难题又会掩盖关键缺陷。

### Q33｜P0｜怎么防止训练、验证、测试之间的数据泄漏？

**来源性质：JD 延伸、论文/项目追问。**

**参考答案：**按数据产生过程确定分组，先隔离独立测试集，再在训练范围内拟合预处理、选择阈值和调参。同一原始文档的改写、同一视频的片段、同一地块的图块，应避免跨集；近重复也要查。对用户、时间、机构、城市的泛化要求不同，分组方式也不同。

验证集用于选择方案，测试集在方案固定后估计最终效果。测试集一旦持续用于观察错误并修改系统，就逐渐变成开发集，需要另留独立集合。即使不使用标签，利用测试集分布拟合表示或预处理也应披露为相应的实验设定。

**结合你的项目：**200 道取数题同时参与调试和最终验证，应坦诚描述为“当前业务回归题集”，下一步再补独立题集与变化场景，不把既有结果改名为独立测试。

**追问：**为什么不能先切图再随机分集？同源图块高度相似，测试可能主要测到对已见地块的识别，而不是新地块泛化。

### Q34｜P1｜LLM-as-a-Judge 怎么做得可信？

**参考答案：**先明确判什么。数值、字段、权限和 SQL 条件能确定性检查的部分先用程序；开放性回答再给模型明确的评分维度、评分锚点和证据要求。用人工判定集衡量裁判的一致性和常见错误，而不是只看裁判输出格式是否正常。

成对比较时交换答案顺序，尽量隐藏模型身份，检查位置、长度和表述风格偏好。对分歧大或高风险样本交人工复核。裁判模型、Prompt 和参考答案也需要版本化，被评估模型与裁判的共同盲区要通过独立样本检查。

### Q35｜P1｜合成数据如何避免错误放大和同质化？

**来源性质：JD 延伸。**

**参考答案：**先用能力和场景缺口决定生成什么，再组合不同任务模板、来源与难度。生成只是候选产生，后续还要验证事实、格式、答案可执行性和模态一致性，进行去重与分布检查，并抽样人工验收。可程序验证的题，优先使用执行结果或确定性规则验收。

记录生成模型和版本、种子材料、处理链路与筛选原因；评测集不得作为生成示例回流训练。调整合成与真实数据混合比例时做受控实验，关注长尾任务与真实流量表现，不能因为合成样本数量翻倍就认为质量提升。

**追问：**让同一个模型生成并审核自己可以吗？可以作为一道筛选，但错误可能高度相关，需要独立验证方式和人工校准。

### Q36｜P2｜DPO 与 RLHF 大致有什么区别？偏好数据常见问题是什么？

**来源性质：JD 对齐数据职责的理论扩展。**

**参考答案：**常见 RLHF 流程先用偏好数据训练奖励模型，再用强化学习优化策略。DPO 在特定推导条件下将偏好优化写成直接作用于策略模型的目标，利用 chosen/rejected 的相对概率及参考模型约束，通常不需要单独训练显式奖励模型再跑在线强化学习循环。

**追问：**为什么同一 Prompt 下比较？偏好应尽量控制任务条件，否则不知道差异来自问题难度还是回答质量。

## E. 多模态数据与融合基础（Q37—Q44）

### Q37｜P0｜什么叫多模态对齐？你的论文与图文大模型有什么联系？

**来源性质：JD 延伸、论文追问。**

**参考答案：**我会分三层：对象对齐确认描述的是同一实体；时空对齐确认时间、位置和范围匹配；语义对齐让不同模态的表示或标签能够共同服务同一任务。能通过 ID 连接只解决了一部分问题，不能保证内容一致。

多模态数据融合的经验可以迁移到样本关联、缺失与冲突诊断、特征表示和评测设计。图文大模型还涉及更大规模的图文配对、语言指令、生成式输出和 token 组织，不能仅因为都是“多模态”就认为训练目标与模型结构相同。

**追问：**图文相似度很高就说明对齐正确吗？不一定，大意相似可能掩盖数量、方位、否定和实体错误，需要面向任务的检查。

### Q38｜P0｜早期融合、中间融合、后期融合怎么区分？

**来源性质：论文追问、JD 延伸。**

**参考答案：**区分依据是融合发生的位置。早期融合在较原始输入或低层表示阶段组合，要求数据形态和同步较容易统一；中间融合在各模态编码之后组合特征，例如拼接、加权或交叉注意力；后期融合组合各模型的预测分数或决策。

中间融合能学习模态间交互，但更依赖样本对齐和训练数据；后期融合便于独立训练和缺失模态降级，但可能错失细粒度关系。不存在统一最优方案，应比较任务效果、计算成本、可解释性和缺失条件下的稳定性。你的论文方法事实见 F 节卡片，口述时先说明融合发生在特征层。

**追问：**拼接就算“完成语义对齐”吗？拼接提供联合输入；能否学到有用对应关系，要由监督、结构和实验结果验证。

### Q39｜P1｜为什么多模态融合会比单模态更差？

**来源性质：论文相关的通用方法追问。**

**参考答案：**新增模态可能带来噪声、错配、过期信息、稀疏缺失或伪相关，也可能因为尺度与优化不平衡压制另一模态。在训练与测试分布变化时，一个训练期有用的模态还可能变成干扰。因此“信息更多”不保证有限数据下训练出的模型更好。

排查先比较两个单模态、简单融合和目标融合模型，再按类别、模态质量和缺失程度分层。检查错配率，做受控遮蔽/扰动和重复实验；随后再试归一化、门控、模态 dropout 或质量感知降权。新增机制必须在固定验证流程下证明有效。

**追问：**只看到两个向量某些维度一正一负，能证明语义冲突吗？不能。学习得到的坐标没有天然统一语义，还需验证表示尺度、对齐方式及与任务错误的关系。

### Q40｜P1｜某个模态缺失、很稀疏或质量很差，怎么办？

**来源性质：JD 延伸、论文追问。**

**参考答案：**先显式保存缺失状态和质量信息，区分真实的“没有该内容”、采集失败、格式错误和尚未到达。训练时可设计模态 dropout、缺失掩码、备用单模态路径或门控；推理时按已验证规则降级，并报告不确定性。

不能简单用全零向量就假设模型理解了缺失，因为全零也可能被当成有效内容。评测要分别报告完整模态、自然缺失和人为扰动下的表现。缺失往往与地区、人群或设备相关，还要检查是否带来系统性偏差。

**追问：**只在训练时随机丢模态够不够？不够。线上缺失可能不是随机发生的，需要用真实缺失样本验证。

### Q41｜P1｜CLIP 的基本原理是什么？能直接拿来清洗图文吗？

**来源性质：多模态 JD 的理论扩展。**

**参考答案：**CLIP 分别编码图片和文本，用对比学习拉近匹配图文、拉远不匹配图文，学习可比较的表示。典型训练中使用批内配对关系构造目标；它本身不是根据图片逐 token 生成回答的完整视觉语言助手。

相似度可作为图文匹配筛选的一项信号，但阈值要在目标领域校准。整体语义相近的错误描述仍可能高分；遥感、医学等领域也可能有分布差异。可以结合实体、数量、OCR 或任务标签的一致性检查，抽样估计误删和漏删。

**追问：**批内负样本都是真负样本吗？不一定，相同语义或同一对象的不同描述可能形成假负样本，需要考虑去重和训练目标设计。

依据：[CLIP 原论文](https://arxiv.org/abs/2103.00020)。

### Q42｜P1｜图文、音频、视频分别要做哪些质量检查？

**来源性质：JD 延伸。**

**参考答案：**共性是可读取、来源明确、长度/大小合理、重复与任务相关性。图片检查解码、尺寸、清晰度、遮挡和图文关系；音频检查采样率、声道、时长、静音、削波，以及转写与说话人/时间段的对应；视频还要检查帧时间戳、帧率、片段边界及音画同步。

质量不是一组固定硬阈值。例如模糊图片可能对鲁棒性训练有价值，口音也不应因 ASR 难而全部删除。先保留质量特征，按任务分配到正常训练、困难集或拒绝集，并保留拒绝原因。

**追问：**把音频转成文字是否完成多模态理解？转写保留语言内容，但语气、重叠说话、音色等信息可能丢失。你的质检经历要讲明输入是平台 ASR 文本。

### Q43｜P1｜多模态数据如何去重？为什么不能只做文件哈希？

**来源性质：JD 延伸。**

**参考答案：**文件哈希擅长发现字节完全一致的重复，重编码、缩放、裁剪和改写后就可能失效。可先做精确去重，再按模态使用感知哈希、文本近重复或向量召回产生候选，最后按相似关系与业务规则确认。

同一图片搭配不同问题可能是不同训练任务，不能只因图片相同就全部删除；但分集时要考虑它们共享底层内容。记录重复组与父对象，区分“去掉冗余样本”和“禁止同源跨测试集”两种目的。向量阈值过松还可能误合并语义相近的不同样本。

**追问：**A 像 B、B 像 C，就能认定 A 和 C 重复吗？相似阈值不天然具有传递性，直接连通分量聚类可能形成过大的误合并组。

### Q44｜P1｜多模态训练时 GPU 等数据，DataLoader 怎么优化？

**来源性质：JD 延伸、论文追问。**

**参考答案：**先测读取、解码、变换、组 batch 和主机到设备传输的耗时。根据瓶颈考虑预取、多进程加载、批量读取、缓存热点数据和合理的固定内存传输；同时监控 CPU、内存、存储带宽，避免盲目增加 worker。

变长文本、不同图片数或视频长度可用自定义 `collate_fn` 组织 batch，结合 padding、mask 或按长度分桶减少浪费。流式数据在多 worker、多进程下要明确分片，否则每个 worker 可能重复遍历同一数据。复现实验还需管理采样器与随机种子。

**追问：**为什么 worker 越多反而越慢？进程通信、解码竞争、文件句柄、内存复制或底层存储已经饱和，都可能抵消并行收益。

依据：[PyTorch 数据加载文档](https://docs.pytorch.org/docs/main/data.html)。

### Q46｜P1｜为什么要处理不规则区域？采样方案有什么代价？

**来源性质：论文追问；以下为通用方法解释。**

**参考答案：**固定输入大小便于批处理，但把大小和形状差异很大的对象直接缩放，可能压缩局部细节或引入背景。采样多个局部视图是在覆盖、信息损失和计算量之间做折中；过密会重复计算，过稀会漏掉关键区域。

比较采样策略时，应固定或记录图块数量、分辨率和计算预算，比较覆盖率、重叠率、小对象表现以及下游效果。Poisson disk 的直观特点是限制采样点过近，形成相对均匀的空间覆盖；并不保证每一个语义重要区域都被采到，也不应声称任何形状下都优于缩放。

**追问：**大地块图块更多，如何公平比较？明确按对象还是按图块计训练权重，控制每对象采样上限，并按面积分层报告。

### Q47｜P1｜为什么用 Swin Transformer？与 CNN、普通 ViT 有什么区别？

**来源性质：论文所用模型的基础追问。**

**参考答案：**CNN 通过卷积引入局部性和参数共享；普通 ViT 常把图像切为 patch，再在 token 间做注意力。Swin 在局部窗口内计算注意力，通过移动窗口建立跨窗口联系，再逐步合并 patch 形成层次表示。固定窗口大小时，窗口注意力部分对 token 数的增长比全局两两注意力更可控。

选择模型还要看预训练权重、数据量、图像分辨率与算力，不能只说“Transformer 一定比 CNN 好”。应在相同数据和合理训练配置下比较效果与成本。面试中说你实际使用的型号；当前文本有不一致，需按训练配置复核，别凭记忆填 Swin-T 或 Swin-L。

**追问：**移动窗口为什么有用？如果每层都保持完全独立的固定窗口，跨边界信息难以交流；错位分组让相邻窗口的 token 在后续层产生联系。

依据：[Swin Transformer 原论文](https://arxiv.org/abs/2103.14030)。

### Q48｜P0｜逐维加权、拼接、交叉注意力分别在做什么？

**来源性质：论文追问；方法比较为参考解释。**

**参考答案：**逐维加权是在已转换到兼容维度的表示之间做受约束的组合；拼接保留两组特征，再让后续网络学习组合规则；交叉注意力让一种模态的表示选择性读取另一种模态的多个位置，能表达更细粒度的关系，但结构和计算更复杂。

回答自己的方法时，按事实卡中的公式解释每个符号、权重从哪里产生、维度如何匹配、梯度如何传回两侧。要说明权重是全局、每样本还是逐特征的，不能只说“加一个权重”。维度相同仅满足运算条件，并不自动保证同一维有相同语义。

**追问：**权重优化时如何判断哪一侧“更正确”？需要讲清使用的标签与数据划分。若依赖真值，应属于训练或验证过程；推理时不能假设已知正确答案。当前优化细节待复核，不替论文补造一个在线门控机制。

### Q49｜P1｜Word2Vec 为什么能表示 POI？如何处理顺序与稀疏问题？

**来源性质：论文所用方法的基础追问。**

**参考答案：**Word2Vec 从上下文共现学习向量：CBOW 用上下文预测目标，Skip-gram 用目标预测上下文。POI 本身不是自然语言句子，需要先定义什么构成上下文，例如空间邻近或路径共现；因此表示学到什么，很大程度取决于语料构造。

这类表示能压缩离散类别和共现关系，但向量相近不等于用途相同。把对象内类别表示聚合后，可能丢失数量规模、细粒度位置和内部布局。可考虑额外保留 POI 数量、密度或空间结构作为比较方案；这些是改进建议，需用消融验证收益。

**追问：**某地块没有 POI 呢？按 Q40 显式区分真实缺失和采集缺失，采用已经验证的缺失表示与降级路径。

依据：[Word2Vec 原论文](https://arxiv.org/abs/1301.3781)。

### Q50｜P1｜Grad-CAM++ 和 EBM 能解释到什么程度？

**来源性质：论文所用解释方法的追问。**

**参考答案：**Grad-CAM++ 利用目标类别相对于中间特征的梯度信息，形成空间区域的重要性可视化，可帮助发现模型是否关注背景或异常区域。它是诊断证据，热图“看起来合理”不能单独证明模型学到了因果机制，也不能证明跨域泛化。

EBM 是基于可解释加性结构的模型，可以展示特征及选定交互项如何影响它自己的输出。如果使用它分析另一模型的行为，需要说明输入、预测目标、拟合方式和拟合忠实度；不能把辅助模型的解释直接等同于原网络的完整机制。

**追问：**怎么增强解释的可信度？做受控遮蔽、替换或扰动，观察输出变化，并用反例检验，而不是只挑几张好看的热图。

依据：[Grad-CAM++ 原论文](https://arxiv.org/abs/1710.11063)、[InterpretML：EBM](https://interpret.ml/docs/ebm.html)。

### Q51｜P0｜面试官质疑论文存在数据泄漏或实验不公平，你怎么回答？

**来源性质：论文追问；以下为复核框架，不是对论文已存在问题的判定。**

**参考答案：**我会先说明已经核实的划分方式，再承认尚未核对的边界。检查顺序是原始对象是否跨集、近邻/同源样本是否高度相关、预处理是否接触测试数据、调参和融合权重是否用过测试反馈，最后检查基线是否有相当的输入与训练预算。

空间数据尤其要区分新图块、新地块和新城市的泛化。同一地区随机划分不能直接证明跨城市适用；需要按目标另设空间或城市留出。发现验证流程不充分时，应保留原结果的适用范围，提出新的独立验证，不声称已有论文结果覆盖所有场景。

**追问：**测试集不训练梯度就绝无泄漏吗？不是。反复按测试表现选模型、阈值和处理策略也会造成测试信息参与方案选择。

### Q52｜P1｜如何设计消融实验？显著提升应该怎么证明？

**来源性质：论文追问；下列是建议设计。**

**参考答案：**先围绕核心主张逐一比较：单模态与融合、简单组合与目标模块、不同采样策略，以及解释分析指导的优化是否带来增益。尽量保持数据划分、输入分辨率、预训练初始化、训练预算与调参机会一致；复杂度差异较大时同时报告参数、计算和耗时。

指标除总体 Accuracy 外还看每类 Precision/Recall、Macro-F1、混淆矩阵及关键人群。对随机训练重复多次，报告均值和波动；重采样或显著性检验要尊重地块/城市等相关性，不把同源图块当完全独立样本。

**追问：**为什么只报提升 1 个点不够？不知道随机波动、样本量和类别代价，也无法判断是否值得额外成本。未做过的检验应直接说未做。

### Q53｜P1｜如果今天重做，你会怎么把研究流程变成工程系统？

**来源性质：论文与 JD 的迁移问题；答案为新方案。**

**参考答案：**我会把数据准备拆成可复用、可统计的算子，固定原始对象与衍生样本的关联，保存时空范围、缺失标记、处理与标签版本。训练和评测都从明确的数据集清单读取，保证一次实验可以追溯输入、配置和产物。

然后按来源和质量监控分布变化，建立单模态、融合、缺失和错配专项评测。算力优化先定位读取解码与训练瓶颈，再决定缓存、批处理或分布式处理。新模型只在明确的能力缺口上引入，先与简单基线比较；这部分是在既有研究之上的工程化设计，不是原论文已上线系统。

**追问：**你能带来的独特结合是什么？从数据粒度与流水线出发，又能理解融合、标注和模型评估之间的相互影响。

### Q54｜P1｜另一篇 DCAI-CLUD 论文与这个岗位相关吗？个人贡献怎么讲？

**来源性质：论文追问。**

**参考答案：**另一篇论文关注以数据为中心的土地利用数据集构建，公开摘要涉及样本筛选、预标注和标注质量/效率，和模型辅助标注、数据质量工作有联系。面试时可以把它作为数据生产经验的补充入口，但应先讲本人实际负责的模块，再展开整体研究背景。

回答贡献可用四句话：“团队要解决什么；我负责什么输入和输出；我做了哪个可解释的选择；有什么实验或材料能证明。”导师、合作者负责的设计和模块应如实说明。没有核实个人职责时，不能把整个数据集规模、标注组织和全部模型实验都归给自己。

**追问：**论文里的效率改善是不是你一个人带来的？区分论文整体结果与个人贡献；当前不代填比例，也不将旧项目数字挪到这篇论文。

依据：[DCAI-CLUD 作者与出版方摘要资料](https://tandf.figshare.com/articles/journal_contribution/DCAI-CLUD_a_data-centric_framework_for_the_construction_of_land-use_datasets/26495178)、[论文 DOI](https://doi.org/10.1080/13658816.2024.2387200)。

## G. Agent 与你的工作项目（Q55—Q60）

### Q55｜P0｜你是数据开发，为什么适合 MaaS 数据岗？

**来源性质：岗位匹配、项目追问。**

**参考答案：**“我可以从三个层面说明。第一是数据基础：做过既有数仓维护、业务链路关联、粒度与口径处理，可以把数据生产过程做得可追溯、可核对。第二是模型应用数据：在理赔客服质检中做过规则与模型结合的流程、Prompt 迭代和评估，接触过标注质量、误报漏报与人工复核的取舍。第三是研究：有多模态融合论文经历，理解异构数据表示、融合和评测的问题。

我希望在这个岗位上把这些经验用于数据流水线、自动标注、质量控制和评测。对于还没有亲自完成的大模型训练或大规模多模态生产链路，我会明确已有基础与待补部分，再讲可执行的方案。”

**追问：**最大的短板是什么？从真实缺口中选一项，例如底座训练规模或生产多模态链路经验，说明已掌握的相关机制及具体补足方式；不要把“过于追求完美”当技术短板。

### Q56｜P1｜Agent 和 Workflow 有什么区别？你的项目分别属于什么？

**来源性质：项目追问。**

**参考答案：**核心看执行控制权：Workflow 的关键步骤和转移由程序预定义；Agent 在给定目标和工具范围内，由模型根据上下文选择下一步动作。两者可以组合，固定流程里也可以有模型判断，不能因为调用了大模型就全部称为 Agent。

我的质检是 Python 多阶段 Workflow：初筛、复核、脱敏、进一步复核和人工确认等关键顺序受控。智能经营分析包含意图与指标澄清、取数工具和分析协作，适合讨论受约束的 Agent 设计。是否存在自由循环、动态规划，应按实际实现说明。

**追问：**ReAct、LangGraph、MCP 是同一层概念吗？不是。ReAct 是推理与行动交替的控制思路；LangGraph 是组织有状态流程的框架；MCP 是连接工具与资源的协议。名称不能代替具体执行机制。

### Q57｜P0｜深入讲一下质检项目的数据与评估闭环。

**来源性质：项目追问；当前事实与建议分开表述。**

**参考答案：**“输入是既有平台提供的 ASR 文本。我主要参与将业务质检标准转成规则、Prompt 和 Python 流程：关键词初筛后进行内部模型复核，经规则与模型脱敏，再做外部模型复核和严重程度判断，最后由人工确认。日批量约万通，需要核对批次完整性、处理失败与重试。

评估上整理过 376 条、三人交叉标注的样本，离线召回约 97%；线上标疑案例经人工确认的比例约 85%。我会区分离线与线上、覆盖与召回，并说明没有在这里重新计算混淆矩阵。”

**如果问下一步：**我会加强初筛未命中部分的抽检，按问题类型、转写质量和渠道拆错例，固定独立评测集；Prompt 调整要在同一回归集比较，发布与回滚按具体流程说明。自动生产发布、完整独立测试和自动回滚目前没有足够已确认材料，不作为既有成果。

**追问：**关键词初筛为什么危险？它可能在模型看到样本前就漏掉问题，必须评估全链路召回，不能只测已进入模型的子集。

### Q58｜P0｜深入讲一下智能经营分析：怎样保证取数与回答正确？

**来源性质：项目追问。**

**参考答案：**“主要流程是先确认指标、维度和时间范围，再通过指标 ID 映射到对应的数据应用、模型或 SQL，由取数环节传结构化参数获取结果，再用代码计算和校验，形成分析回答。指标和维度等知识在平台上由人工配置，我负责的应用编排与校验不等于独立建设整个平台。

曾出现指标选错、过滤条件遗漏、报告指标名称改变和超时等问题，所以我会沿用户意图、参数、数据、计算和答案逐段核对。模型查看前 200 行是预览，完整结果下载为文件后由代码处理，不能用预览替代全量汇总。”

**指标口径：**200 道业务取数题约 95%，有人类参考答案及模型判断环节，题目也用于调试；它证明当前回归题集表现，不能证明新业务问题独立泛化。总体答案表现、满意度和取数正确率需要分别解释，避免揉成一个“准确率”。

**追问：**如果 SQL 正确但业务答案错呢？可能指标口径、粒度、时间或分母选择错，SQL 可执行只是必要检查之一。

### Q59｜P1｜RAG 与工具调用有什么区别？Text-to-SQL 最容易错在哪里？

**来源性质：项目追问；另有近期发布的二手整理涉及 Text-to-SQL，实际面试日期及团队待核实。[S3]**

**参考答案：**RAG 通常先检索与问题相关的资料，再用资料支持生成；工具调用是让模型提出结构化调用，由程序执行查询、计算等动作。二者可以结合：先检索指标定义，再通过工具取数。取到文档与取得实时业务数据的可信边界不同。

Text-to-SQL 的困难不只有语法，还有找对表、连接关系、指标定义、日期范围、粒度和去重口径。应提供经过维护的语义信息与约束，先检查查询权限和资源限制，再验证参数、结果结构和业务不变量。金额、比率等核心计算尽量由程序完成，并给答案附可追溯的数据来源。

**追问：**执行成功就代表正确吗？不代表。能运行但用了错误分母、错误时间或一对多重复 Join，是更隐蔽的错误。

### Q60｜P1｜如何设计可靠的 Agent 执行与失败处理？

**来源性质：项目追问；以下为参考设计，不全部视为现有实现。**

**参考答案：**把任务目标、当前步骤、已确认约束、工具结果和执行状态保存为结构化状态。模型提出动作，程序检查参数、权限、预算和状态条件，再执行工具。可重试的临时失败有限次重试；业务歧义需要澄清；不可恢复错误应停止并说明缺失证据。

工具结果要关联请求和证据来源，压缩上下文时保留重要约束与引用。多次尝试评估成功率、工具错误和成本，防止一次演示成功掩盖不稳定。多 Agent 适合有独立职责、信息或可并行任务的情况；是否采用取决于协作收益、串行依赖、延迟和核验成本。

**追问：**断点恢复后会不会重复执行外部动作？可能。恢复状态和保证外部副作用只发生一次是两个问题，参见 Q07 的幂等与提交协议。

## 面试前需要本人补齐的 5 个小事实

这些是目前材料不能替你确定的内容。补齐后，论文回答会更自然，也更能承受追问。

1. **个人贡献：**两篇论文分别亲自负责哪些模块，合作者负责什么；能展开哪个实现或实验。
2. **实现配置：**主论文实际训练使用的 Swin 型号、初始化方式、损失函数，以及自己改过的关键代码。
3. **数据划分：**先按地块划分还是先切图；是否设验证集、空间/城市留出，是否检查同源与近重复。
4. **融合优化：**WFM 初始训练与后续权重优化分别用了哪些标签、数据与选择标准；推理时是否需要额外信息。
5. **一个真实失败案例：**哪类样本发生过误判，你如何定位是数据、表示、融合还是标签问题；实际尝试和结果是什么。

**不记得时的表达：**“整体方法我可以说明，具体配置/数据范围我需要按当时实验记录核对，不能凭记忆给一个不准确的数。这里我先讲已确认的部分。”随后回到自己确实做过的决策，避免不断补猜。
