### 口述整理规则｜用户于 2026-09-07 明确要求

1. 展示便于阅读、讲述的润色内容，同时保留原话和来源。可以去掉语气词、重复和不改变含义的表达。
2. 涉及事实、逻辑、术语含义、结论、实现细节或核心内容的修改，先给出“原话 → 拟改内容 → 原因”，得到本人确认后再写入整理稿。不得借润色补写能力、数字或事故。
3. 本人已经明确纠正的内容直接采用，例如“四五版”和“最终 200 道题”；不需要重复确认。未确认的转写词保留并注明，不自行猜测。

## 十、I｜Agent 与通用技术基础：14 题

**考察目的：** 补齐技术面可能从项目延伸追问的基础知识。题目提供覆盖范围，掌握深度按岗位职责和本人实际经验选择；语言和组件不用全部声称熟练。

| 范围 | 对应题目 |

### I01｜Agent、Workflow 和普通 LLM 调用有什么区别？怎样选择编排方式？

准备状态：待继续

- 能画出模型、工具、状态、决策和停止条件的最小循环；解释 ReAct、规划后执行、单 Agent 与多 Agent 的适用条件。
- 追问“为什么不用固定工作流”“是否真的需要 Agent”“什么时候并行、什么时候必须串行”。理论取舍和项目里的真实选择分开。

### I02｜Function Calling、结构化输出、Tool、Skill 和 MCP 分别解决什么？

准备状态：待继续

- 从一个请求讲模型提出调用、程序校验参数、执行工具、返回结果的过程；区分输出格式、调用协议与真正执行。
- 准备 schema 校验、工具选择错误、重复调用、鉴权、失败返回、超时与幂等的处理。能说明接口连接成功为什么仍不代表业务结果正确。

#### 项目追问与八股

**Agent 1｜工具调用与约束校验**

已有口述关键词：主 Agent 澄清，取数 Agent 组装结构化参数调用平台；日期和计算规则代码化；Prompt 先拆指标再明确各自条件。

**深入问法：** 从模型收到工具定义到平台返回数据，完整调用过程是什么？若工具参数 JSON 完全合法，为什么仍可能漏一个维度条件？如果增强防护，校验应该放在哪一层？

**可接的基础题：** Function Calling 与结构化输出有什么区别？模型与宿主程序分别执行哪一步？Tool、MCP、Skill 各是什么？类型校验、枚举校验、业务约束和意图完整性为何不能互相替代？

场景边界：运行链路是已有事实；Schema、参数契约和计划对照的具体增强方案按假设设计回答。

合并入口：[A03](#A03)、[A04](#A04)、[A06](#A06)、[G06](#G06)、[I04](#I04)。

出题依据：S10 的工具不准／护栏追问；既有 S02；用户实际遗漏问题；具体问法为本次改写。

### I03｜一套 RAG 检索链路怎么搭建，效果不好时怎样分层排查？

准备状态：待继续

- 覆盖切分、元数据、Embedding、词法与向量检索、混合召回、重排、上下文组织和证据引用；解释 BM25、相似度、TopK 与重排的取舍。
- 分别定位没收录、没召回、排序不对、内容过期和回答没用好证据；语义资产的专门选择逻辑复用 [B08](AI数据面试准备.html#B08)。

### I04｜Prompt 怎样设计和迭代？如何处理冲突指令、提示注入和不稳定输出？

准备状态：待继续

- 追问“Prompt 越长越好吗”“为什么加了一句话影响其他问题”“检索文档里出现指令怎么办”“输出 JSON 合法但内容错误怎么办”。

### I05｜上下文窗口、对话历史、摘要、长期记忆和缓存有什么区别？

准备状态：待继续

- 区分业务查询结果缓存、应用记忆、Prompt 缓存和 KV Cache；项目记忆机制复用 [A10](AI数据面试准备.html#A10)。

### I06｜LLM 推理有哪些必须理解的基础概念？

准备状态：待继续

### 阅读页如何维护

阅读页面由本机服务提供：`http://127.0.0.1:8767/`。服务未运行时，双击[打开口述编辑.command](资料/打开口述编辑.command)，或在仓库根目录运行 `python3 2-进行中/面试准备/资料/面试口述编辑服务.py --open`。它只监听本机；关闭服务后已保存的内容仍在 Markdown 中，离线 HTML 也会随保存更新。

从文件直接打开的 HTML 也可阅读。后续口述在对话中确认，再追加到本 Markdown；浏览器不是另一份答案存储。服务代码见[面试口述编辑服务.py](资料/面试口述编辑服务.py)。

若直接修改本文件的题目、要点、口述记录和“准备状态”，完成后在仓库根目录运行：

```bash
python3 2-进行中/面试准备/资料/生成面试阅读页.py
```

也可以直接让 Codex“更新清单并重新生成阅读页”。生成器只使用 Python 标准库；HTML 是离线阅读产物，不手工编辑、不保存另一套进度。刷新已打开的阅读页即可看到新内容。

口述记录使用现有的 `#### 口述记录｜日期 · 版本说明` 结构，包含“口述性质”“口述覆盖”“润色口述”和“原始依据”；有歧义时补充“保留原意的说明”。新版本追加在同一题的旧版本之后，模块材料之前。原始依据可以是逐字原话，也可以是已标明的本人素材／确认记录，不得把 AI 草稿伪装成原话。追加后运行生成器的 `--check` 可检查网页是否与内容源一致。

历史网页手动编辑的版本带有“口述格式：原文逐行”，正文各行使用引用前缀保存，生成器去掉前缀后按纯文本显示。这用于完整保留粘贴的标题、换行和符号，避免它们改变题目结构；编辑编号用于重试时避免重复追加同一版。
