### 3. 资源节省数字可能对应两个优化阶段

P02 写：基线约 1685 CU / 天，优化节省 851 CU / 天，年化成本节省 153,180 元。按同一基线推算，优化后约为 834 CU / 天。

P01 写：1685 CU / 天降至 462 CU / 天，即节省 1223 CU / 天，降幅约 73%，年化节省约 22 万元。

两个版本不能直接混用，但数字存在一个合理的阶段性解释：

- `1685 - 851 = 834`
- `834 - 462 = 372`
- `851 + 372 = 1223`

即 P02 可能记录第一阶段优化，P01 又纳入后续约 372 CU / 天的进一步下降；且两份材料使用的单位成本近似一致。这只是算术上的候选解释，仍需用监控日期和变更记录确认。

## Codex 反馈

### 1. 智能经营分析效果口径存在直接冲突

P01 写“查数正确率 100%、业务知识评测无错误”。但已保存的 v4 测评报告 O03 显示：

- `sql_write` 首跑通过率为 86.2%，两次机会累计为 95.0%；仍有流量漏斗路由题稳定失败。
- `no_sql` 首跑通过率为 35.0%，按报告数据推算累计为 55.0%；分析方法和业务知识是明显短板。
- O01 的真实问题记录也包含底表口径错误、上下文误解和业务同义词失败。

这些材料可能来自不同版本、不同题集或不同评判方法。只有补充 P01 对应的评测日期、题集、版本和分母后，才可能同时保留；当前不能使用“100% / 0% 错误”作为统一项目结论。

### 2. “业务知识优于人工”缺少可复核判定

需要明确：人工答案是谁写的、评分者是谁、怎样定义“优于 / 持平 / 错误”、是否盲评、样本数是多少。否则该结论主观性太强。它也与 O03 中业务知识题累计表现较弱相冲突。

### 3. 理赔质检的 Precision 100% 不能单独证明模型达标

零误报只说明在当前样本和阈值下没有 false positive。若模型非常保守、只报极少数样本，也可能获得 100% precision。至少还需要：

- TP / FP / FN / TN 与预测阳性数量；
- recall、F1 和各维度分项结果；
- 376 条有效样本如何从 430 条产生，54 条分歧样本如何处理；
- “三人取交集”是只保留三人完全一致样本，还是标签交集；
- 离线评测与生产数据上的人工复核结果是否一致。

### 4. 三人“取交集”会提高一致性，但可能降低代表性

直接删除分歧样本会让评测集更干净，也可能移除最接近真实边界、最能暴露模型问题的 hard cases。更稳妥的做法是保留分歧标签、进行专家裁决，并把一致样本与争议样本分层报告。

### 5. 理赔项目的时间演进目前只能形成候选解释

一种可能的演进是：C01 记录的线下规则模型和 200 / 1000 条评测规划 → 用户 2026 年 3 月加入 → 实际形成 430 条标注集 → 重构 Prompt → 搭建全量生产流程。但这只是由两份文档拼出的假设，需要用版本、上线时间和日志确认。

### 6. 晋升材料不是独立结果证据

P01 很适合提供“当时怎样向组织总结项目”的视角，但不能自证自己的准确性。尤其是“独立完成”“首次实现”“稳定运行”“零风险”“100%”等强结论，均需要一项至少对应一份外部证据：代码或评审、任务记录、监控截图、评测明细、上线通知、使用日志或业务验收。

### 7. P02 提高了营销项目的可核查性，但仍不是验证完成

P02 提供了测试报告、方案文档、优化记录和学习文档等内部证据指针，比 P01 单纯总结更接近可验证事实源。由于本轮未访问这些内部页面，当前只能确认“原文提供了证据入口”，不能报告里面的数据已经核验。
