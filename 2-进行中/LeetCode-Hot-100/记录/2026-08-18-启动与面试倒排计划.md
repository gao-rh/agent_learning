## 今天的 90 分钟学习卡

### 今日主题

哈希表：用额外空间换取快速查找，并把“我接下来需要找什么”作为键。

### 今日问题

1. [1. 两数之和](https://leetcode.cn/problems/two-sum/)
2. [49. 字母异位词分组](https://leetcode.cn/problems/group-anagrams/)

### 执行顺序

| 时间 | 动作 | 产出 |
| --- | --- | --- |
| 0—10 分钟 | 先预测哈希表查询的平均/最坏复杂度，再读 [哈希表核心原理](https://labuladong.online/zh/algo/data-structure-basic/hashmap-basic/) 的“基本原理、哈希冲突”部分 | 修正预测；区分映射接口和哈希表实现 |
| 10—35 分钟 | 独立做“两数之和”；先说暴力解法，再写一遍 Python 哈希解法 | 代码 + 时间/空间复杂度 + 为什么先查再存 |
| 35—70 分钟 | 独立做“字母异位词分组”；先设计能唯一代表一组异位词的 key | Python 代码 + key 的选择 + 字符集/排序复杂度边界 |
| 70—80 分钟 | 比较排序字符串与 26 位频次数组两种 key | 明确二者复杂度、Python 可哈希类型和适用边界 |
| 80—90 分钟 | 不看代码口述两题共同点和差异，记录状态 | 每题标为 `待继续` 或 `待验证`；不要直接标 `已理解` |

如果今天投入 2 小时，剩余 30 分钟优先完成未完成的第二题；若前两题已完成，再尝试 [128. 最长连续序列](https://leetcode.cn/problems/longest-consecutive-sequence/)，不要求今天强行完成。

### 开始前先回答的三个预测

1. “两数之和”为什么不能把当前元素先放入哈希表再查询补数？什么输入会暴露问题？
2. “字母异位词分组”的 key 可以是排序后的字符串，也可以是字符频次数组；二者的时间复杂度有什么差别？
3. 哈希表操作为什么只能说“平均 O(1)”，不能无条件说“最坏 O(1)”？
