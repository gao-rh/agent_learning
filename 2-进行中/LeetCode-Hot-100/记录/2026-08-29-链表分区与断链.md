## 原始问题

用户提交链表分区代码，并说明：“我一开始忘记断开链表形成环了，改了一下就对了。”

```python
class Solution(object):
    def partition(self, head, x):
        dummy_low = ListNode(-1)
        dummy_high = ListNode(-1)

        if head is None:
            return head

        p = head
        pl = dummy_low
        ph = dummy_high

        while p is not None:
            nxt = p.next
            p.next = None

            if p.val < x:
                pl.next = p
                pl = pl.next
            else:
                ph.next = p
                ph = ph.next

            p = nxt

        pl.next = dummy_high.next
        return dummy_low.next
```

## 用户理解

- 用户使用两个虚拟头节点，把 `< x` 和 `>= x` 的节点分别接到两个新链表中，最后拼接。
- 用户第一次实现时复用了原节点，但没有断开节点原有的 `next`，观察到最终链表形成环。
- 用户随后保存下一个节点并执行 `p.next = None`，修复了问题。

## Codex 反馈

### 修复正确

处理原链表节点时：

```python
nxt = p.next
p.next = None
```

这两行维护了一个重要不变量：**已经接入 `low` 或 `high` 的链表尾节点，其 `next` 不再保留原链表中的旧连接。**

顺序不能交换。如果先写 `p.next = None`，再读取 `nxt = p.next`，`nxt` 已经变成 `None`，剩余原链表会丢失。

### 为什么不清理旧指针可能形成环

以 `[1, 4, 3, 2, 5, 2]`、`x = 3` 为例，分区过程中某个大节点的旧 `next` 仍可能指向后面的小节点。最终再把小链表尾部连回大链表头部，就可能出现：

```text
大节点 -> 小节点 -> 大链表头 -> ... -> 原大节点
```

例如残留 `5 -> 2`，最后又连接 `2 -> 4`，就可能得到 `4 -> 3 -> 5 -> 2 -> 4` 的环。

用户当前做法是逐节点断链，逻辑清楚且安全。另一种常见写法是不逐节点断开，但在拼接前强制：

```python
ph.next = None
pl.next = dummy_high.next
```

两种方案都能正确结束大链表；逐节点断开提供了更强、更容易检查的不变量。

### 正确性与复杂度

- 每个原节点恰好进入 `low` 或 `high` 一次，不创建新的数据节点。
- 尾插保证 `< x` 组和 `>= x` 组内部的相对顺序不变，因此是稳定分区。
- 时间复杂度：`O(n)`。
- 额外空间复杂度：`O(1)`；两个 dummy 节点和若干指针不随输入规模增长。
- `head is None` 的提前返回可以保留，但不是必须；即使删除，循环也会直接结束并返回 `None`。
