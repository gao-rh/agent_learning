# 复现验收矩阵

> 2026-09-05：本页保留完整范围验收参考。用户只有 1–2 周非全职时间，当前按[短期核心学习安排](../记录/2026-09-05-一至两周核心学习安排.md)验收模型—工具—结果—继续/停止链路。多工具类型、流式、消息保存、并发、压缩、界面和持久化等不要求本轮全部完成。

状态：AI 草案 / 待确认；所有用户能力与复现实验当前均为**待验证**。本轮仅整理验收设计，没有运行这些测试。

验证必须区分：

- 静态证据：代码里确有某分支。
- 确定性运行证据：使用 fake/faux provider 和合成数据得到固定轨迹。
- 真实集成证据：特定 provider、环境、版本下的小样本验证。
- 用户理解证据：用户能预测、解释、修改和排错。

四者不能互相替代。

## 核心功能与失败路径

| ID | 阶段 | 场景 | 应提供的证据 |
| --- | --- | --- | --- |
| C01 | M1 | 消费者先等待、生产者后推送；反向顺序 | 事件不丢失，end 与 result 正常，输出顺序可预测 |
| C02 | M2 | 文本分片、工具参数跨多片、不完整 JSON | 中途只更新展示，完整准入前没有工具副作用 |
| C03 | M3 | 一次 read 后模型给出最终回答 | 两次模型请求、一次工具执行、完整关联 ID 的事件轨迹 |
| C04 | M3 | 模型直接回答、不用工具 | 一次请求结束，无多余模型调用 |
| C05 | M3 | 未知工具、参数错误、工具抛错 | 无非法执行；错误变成可追踪结果，而非无声消失 |
| C06 | M3 | stopReason=length 但参数看似合法 | 该助手消息的工具均不执行，返回截断错误 |
| C07 | M3 | 慢工具 A、快工具 B | 可并发；完成事件 B/A，历史结果 A/B |
| C08 | M3 | 一批含 sequential 工具 | 整批串行，不能仅把单个工具隔离后继续随意并发 |
| C09 | M3 | 同一文件多次 write/edit；不同文件 | 同文件排序、不同文件允许并行；失败不永久堵队列 |
| C10 | M3 | hook 阻止调用、覆盖结果、terminate 混合批次 | 正确记录阻止原因、执行次数与后续请求次数 |
| C11 | M3 | 模型流取消、shell 超时、子进程嵌套 | 无继续写流、无遗留受控子进程；既有副作用明确列出 |
| C12 | M3 | steering 与 follow-up 排队 | 明确何时注入；不沿用旧文的不同打断粒度 |
| C13 | M3 | 异步事件监听器延迟完成 | agent_end、waitForIdle、prompt 返回的时序证据 |
| C14 | M4 | 关闭后恢复、从早期消息分支 | 新分支上下文正确、旧分支仍可读，条目不混写 |
| C15 | M4 | 正常压缩、摘要失败、上下文溢出 | 保留窗口与摘要可检查；失败/重试不重复用户输入或遗漏工具结果 |
| C16 | M5 | 同名资源、项目不受信任、扩展异常 | 加载来源与优先级有证据，trust 与沙箱权限分别验证 |
| C17 | M6 | CLI/JSON/RPC/SDK 使用同一假响应 | 最终消息语义相同，协议 stdout 不混日志 |
| C18 | M6 | TUI 尺寸改变、长输出、取消和退出 | 界面/状态一致，终端输入模式恢复；人工验收说明环境 |
| C19 | M7 | 工具前/工具后未提交/结果已提交时崩溃 | 各窗口的重放与副作用策略，不虚称 exactly-once |
| C20 | M7 | 事务提交失败、存储重开 | 原子性、最后有效状态、不发布未提交状态的日志 |
| C21 | M7 | RPC 单请求取消、断连、durable abort | 三种语义不混淆；其他调用的取消谱系不串线 |
| C22 | M7 | 旧 attachment 发请求、任意分片/粘包 | 拒绝陈旧路由，合法帧恢复正确，大小边界生效 |
| C23 | M8 | 跨 provider 切换、usage、认证失效 | 固定供应商/模型/版本下验证；未知兼容性单列 |
| C24 | M8 | 新增工具与故障现场定位 | 用户独立实现、找到状态/调用链并补回归测试 |

## 完整范围的最后一道门

“全部 monorepo”必须进一步细化，下面是对齐检查域，不是目前已完整展开的规格：

| 检查域 | 不可漏掉的边界 |
| --- | --- |
| pi-ai | 逐 provider/API、认证/OAuth、模型目录、文本/图像、usage、重试、中止、跨模型历史变换 |
| pi-agent-core | 普通 Agent 与新 AgentHarness 分开验收，事件、队列、hooks、状态机、恢复 |
| coding-agent | 工具、信任/配置、资源、session、压缩、扩展、CLI 模式、导出、包管理 |
| tui | 主/备用屏、键盘、Unicode 宽度、长输出、图片、尺寸变化、终端与平台差异 |
| storage | 内存、JSONL、SQLite 契约一致性、失败、所有权、分支/查询 |
| chord/telemetry | 服务、插件、状态复制、显式 Context、观测数据与敏感内容边界 |
| protocol/client/server | 帧、版本、路由、取消、附着、断连、关闭；实验性安全与兼容性限制 |
| evals/build/release | 测试基架、可复现依赖、模型数据、打包、平台；不运行发布命令 |

每个不覆盖项必须写“未实现 / 不适用 / 上游未实现 / 验证受限”及原因。M8 才将这张域清单逐条展开为功能规格；本轮初步调研不能宣称已完成所有功能盘点。

## 安全与费用

- 测试数据只用合成文件、临时工作目录和最少权限，不运行模型建议的任意破坏性命令。
- project trust 不等于隔离；有写权限的容器挂载仍可能修改宿主文件。
- 不把个人凭据目录挂入不受信任实验，不读取/输出既有密钥。
- 无模型单测与真实集成测试分开；真模型按约 10 个代表案例另行核算，不无界重试。
- 不使用真实账单、真实账户操作或发送消息来检验工具副作用。
