# Pi 项目初步调研与执行地图

基线：2026-09-04 / v0.85.0 / `107d79f11072bbc8a3a757ed7fd69596bee7d68c`。本报告是关键链路静态阅读与文档核对，不是全仓逐行审计，也没有动态测试结论。

## 先明确要复现什么

Pi 不是一个训练好的大模型，而是组织模型调用、上下文、工具、会话和交互的程序，也称 agent harness。模型生成什么与程序准许并实际执行什么，是两层不同的责任。

“底层原理”可分为三层：

1. **Pi 自己实现的机制**：控制循环、消息变换、工具分发、状态、历史、压缩、扩展、UI，以及新持久化运行时。
2. **Pi 依赖的执行基础**：JavaScript 异步语义、Node.js I/O、进程/信号、HTTP 流、文件系统和数据库事务。需要能解释边界，不必先重写 V8、操作系统或数据库引擎。
3. **外部模型内部机制**：权重、训练过程、推理服务内部实现不在此仓库。完整复现 Pi 不能据此宣称完整复现供应商模型。

当前源码不是只有老文章描述的四个包。完整清单见 [包规模与官方文档索引](02-官方文档与源码索引.md)。

## 一条普通 Coding Agent 请求如何执行

下列是常规 CLI/SDK 路径的简化调用关系；实验性 server/client 路径另列，不把两套运行时混成一套。

```text
cli.ts / main.ts
  → 准备配置、信任决定、资源、模型运行时和会话
  → createAgentSession() 组装 Agent + AgentSession
  → AgentSession.prompt()
  → Agent.prompt() / runAgentLoop()
  → transformContext → convertToLlm
  → ModelRuntime / pi-ai 的模型、认证与 API 适配
  → 收到文本、思考块或 toolCall 的流事件
  → 工具预处理与参数校验 → 执行 → toolResult
  → 结果进入下一轮上下文，必要时继续调用模型
  → 事件驱动会话持久化和 UI 更新
```

这不是“模型直接执行 JavaScript”。模型传回工具名称、调用 ID 和参数；Node.js 中的工具实现才实际操作系统。

### 1. 入口和组装

- [cli.ts](本地资料/pi/packages/coding-agent/src/cli.ts)、[main.ts](本地资料/pi/packages/coding-agent/src/main.ts)：参数、模式、初始化、交互/print/RPC 分流。
- [sdk.ts](本地资料/pi/packages/coding-agent/src/core/sdk.ts) 的 `createAgentSession`（第 173 行开始）：建立模型与会话选项，创建 `Agent` 与 `AgentSession`。
- [agent-session-runtime.ts](本地资料/pi/packages/coding-agent/src/core/agent-session-runtime.ts)：管理会话替换与依赖服务重绑定；不要仅凭名字就把它等同于新 `AgentHarness`。
- [agent-session.ts](本地资料/pi/packages/coding-agent/src/core/agent-session.ts)：用户输入、扩展事件、工具配置、压缩与重试等产品层协调。
- 默认内置工具集合为 `read / bash / edit / write`；其他工具和扩展工具的启用有配置分支。以 sdk.ts 的当前 allowlist/denylist 逻辑为准。

### 2. Agent 循环：要读懂而不是只会调用

重点文件：[agent-loop.ts](本地资料/pi/packages/agent/src/agent-loop.ts)，803 行；[agent.ts](本地资料/pi/packages/agent/src/agent.ts)，592 行。

| 函数 / 入口行 | 负责什么 | 必须问的问题 |
| --- | --- | --- |
| agentLoop / 32 | 以 EventStream 包装一次新输入循环 | 为什么函数可以先返回流、工作在之后完成？ |
| runAgentLoop / 96 | 建立本次上下文并发出起始事件 | 哪些数组复制了，哪些对象仍共享引用？ |
| runLoop / 156 | 内层处理工具和 steering，外层检查 follow-up | 哪个条件让下一次模型请求发生？ |
| streamAssistantResponse / 279 | 上下文变换、模型流读取、部分/最终消息 | 部分消息是否等于最终可以执行的指令？ |
| failToolCallsFromTruncatedMessage / 379 | 将输出长度截断的工具请求转成错误结果 | JSON 恰好能解析，为什么也不能执行？ |
| executeToolCalls / 409 | 根据全局和单工具策略选并行/串行 | 为什么不是所有工具都随便并行？ |
| prepareToolCall / 607 | 查工具、参数预处理、校验和 before hook | TS 类型为什么挡不住模型发来的错误 JSON？ |
| executePreparedToolCall / 677 | 调用本地工具、收集进度、归一化异常 | 取消信号谁监听？进度回调何时失效？ |
| createToolResultMessage / 784 | 组装回到历史与下一次模型上下文的结果 | 调用 ID、isError、content 和 details 谁消费？ |

退出不只有“模型说完”：error/aborted 会终止；无工具且无待处理输入时自然结束；`shouldStopAfterTurn` 可停止；一批已完成工具全部返回 `terminate:true` 时可跳过自动工具后续请求，但仍要看排队消息。教学版若增加步数/费用上限，应标为自己的安全扩展，不能说是上游默认行为。

### 3. 流式返回与 JavaScript 的关系

[EventStream](本地资料/pi/packages/ai/src/utils/event-stream.ts) 只有 88 行左右，是适合第一轮精读的小文件：

- producer 调 `push(event)`；consumer 用 `for await...of`。
- 已有消费者等待则直接唤醒，否则将事件放进队列。
- 消费结束与 `result()` 返回最终值是不同接口。
- Agent 的流、模型供应商的网络流、stdout 输出不是同一个东西。
- 内存事件队列本身不是持久日志，也不能直接假设它提供有界背压。

继续读 [models.ts](本地资料/pi/packages/ai/src/models.ts)、[types.ts](本地资料/pi/packages/ai/src/types.ts)、一个 [API 适配实现](本地资料/pi/packages/ai/src/api/anthropic-messages.ts) 与 [消息变换](本地资料/pi/packages/ai/src/api/transform-messages.ts)。观察 role、toolCallId、停止原因、错误、usage、thinking 数据怎样映射。不同 provider/API 不可假定完全等价，也不可把所有流都说成同一种 SSE。

### 5. 事件顺序、取消和排队输入

固定版本默认 `toolExecution = parallel`。预检按源顺序执行，允许的调用可并发；结束事件可以乱序到达，而 toolResult 消息按模型原始调用顺序形成。若一批包含声明为 sequential 的工具，整个批次改为串行。

`Agent.subscribe` 的监听器按顺序等待。收到 `agent_end` 不必然等于监听器、写入和清理已经全部完成；`await prompt()`、`waitForIdle()` 有不同的完成边界。

当前低层循环在完成本轮工具批次后读取 steering；follow-up 则在循环将结束时读取。官网首页仍有“当前工具后打断剩余工具”的简述：与此基线的工具批次代码不能直接等同，应在实验中以事件日志核实。不要从旧版本教程推断 v0.85.0 的打断粒度。

`AbortController` 只是协作式取消。网络请求、工具、子进程都要响应它；已经发生的文件写入不会因 abort 自动撤销。

### 6. 会话历史不等于模型上下文

- [session-manager.ts](本地资料/pi/packages/coding-agent/src/core/session-manager.ts) 和 [session-format.md](本地资料/pi/packages/coding-agent/docs/session-format.md)：普通 Coding Agent 会话条目、父子关系、分支与恢复。
- [messages.ts](本地资料/pi/packages/coding-agent/src/core/messages.ts)：应用消息转换。
- [compaction.ts](本地资料/pi/packages/coding-agent/src/core/compaction/compaction.ts)：选择保留内容、摘要和模型调用。
- [branch-summarization.ts](本地资料/pi/packages/coding-agent/src/core/compaction/branch-summarization.ts)：切换分支时的摘要。

需要分别画出：完整磁盘历史、当前分支、当前准备发给模型的消息、UI 展示。压缩通常改变后续上下文构造，不是简单删除旧文件；摘要本身也可能丢信息、失败或产生模型成本。

### 8. 新版持久化 Harness 与实验性客户端/服务端

这是完整范围的一部分，但不是前几课的前置条件：

- [AgentHarness 类型](本地资料/pi/packages/agent/src/harness/agent-harness.ts) 与 [实现规范](本地资料/pi/packages/agent/docs/harness.md)：Session、Branch、AgentLane、operation，accept/drive/requestAbort，恢复与提交边界。
- [runtime/drive](本地资料/pi/packages/agent/src/harness/runtime/drive/)：把生成、工具、检查点、恢复、结束拆为可恢复的步骤。
- [mutation-line.ts](本地资料/pi/packages/agent/src/harness/session/mutation-line.ts)：会话变更的提交顺序。
- [SQLite 后端](本地资料/pi/packages/session-backends/sqlite-node/README.md)：存储、事务和所有权。
- [protocol](本地资料/pi/packages/protocol/README.md)、[client](本地资料/pi/packages/client/README.md)、[server](本地资料/pi/packages/server/README.md)：路由、请求 ID、取消、附着身份和跨进程传输。
- [Chord](本地资料/pi/packages/chord/README.md)：独立的服务/插件组合与状态复制基础；[telemetry](本地资料/pi/packages/telemetry/README.md)：显式可观测性契约。

不能把“重放”说成外部副作用 exactly-once；外部执行已发生而本地结果未提交，是必须处理的恢复窗口。

实现规范 §0.9 明确列出未实现/进行中项：JSONL 快照压缩、watchSession、部分 telemetry、search、named-branch/streaming forks 等；Postgres 与 precise rewrite 属未来/管理工具方向。它们不能因出现在文档里就算已交付功能。最终验收以固定提交已实现的行为为基线，未实现项单列而非静默补全。
