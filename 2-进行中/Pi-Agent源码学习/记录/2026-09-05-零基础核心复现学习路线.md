## 你最终要做出来的东西

你自己写一个在终端运行的小 Agent。你输入：

> 读取练习目录里的 notes.md，把第一行标题改成“本周学习记录”，保存后告诉我改了什么。

它能把问题发给 Kimi；收到工具调用后，由你写的程序查找工具、检查参数、读写文件；把执行结果交回 Kimi；继续运行直到完成或遇到需要停止的情况。你能沿着日志解释每一步，并修改其中任意一个工具。

你要独立写出模型调用、工具注册与执行、循环、消息历史、流式事件和停止处理。读完源码后，可以关掉参考实现重新写关键函数，并解释自己的简化与 Pi 的区别。

## 你现在先做什么

先进入第 1 课，目标是**运行和修改第一个 JavaScript 小程序**：

1. 理解 JavaScript 文件与 Node.js 的关系：文件保存代码，Node 负责运行它。
2. 在练习目录创建一个很短的 `01-basics.mjs`；先学习输出文字、声明变量、字符串与数字。
3. 用 `node 01-basics.mjs` 运行；修改变量后，在再次运行前先说出预期结果。
4. 尝试重新给 const 变量赋值，观察报错，再改用 let，解释两者差别。

这一课的完成标准：你能从空文件写出同类程序，自己运行，并找到报错对应的代码行。下一课再引入对象、数组和消息结构。现在不用先掌握 Promise、泛型或读完整源码。

这里描述的是下一次学习任务；本次规划没有代你完成练习或创建答案文件。

“简化工具”的含义：文本读取、整文件写入、唯一精确匹配替换、执行 shell 并获取输出/退出码。图片处理、复杂模糊编辑和所有平台兼容性留在扩展范围。

## 七个阶段：你学什么、写什么、怎样过关

### 1. 写出最小 JavaScript 程序

学：变量、字符串/数字、对象、数组、条件与循环、函数、基本模块导入导出。用 JavaScript 编写 .mjs 小文件。

读：[MDN 中文指南](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide) 的语法与数据类型、控制流、函数、对象、集合；按当课范围选段。

做：从打印文字，逐步写成“消息记录器”：用对象表示一条消息，用数组保存多条消息，写函数添加/筛选/打印消息。

过关：给你一个新需求“只打印用户消息”，你能自己修改；能解释对象、数组和 JSON 文本的差别，知道数组/对象赋值与浅拷贝的基本行为。

暂估 4–6 小时，包括练习；根据实际进度调整。

### 2. 理解等待、文件和失败

学：Promise、async/await、try/catch/finally；Node 文件读取与路径。用小日志例子理解等待期间其他任务怎样执行，再介绍事件循环的必要部分。

读：[MDN 使用 Promise](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Using_promises) 的基础与错误处理；后续按例子查 Node 文档。

做：读取练习文件并显示内容；文件不存在时给出可解释的错误。写两个有延迟的操作，预测 await 前后日志的顺序。

过关：解释“函数还在等待”时进程是否还能处理别的事；能修复漏写 await、未捕获异常和清理遗漏。

暂估 4–6 小时。

### 3. 接入 Kimi，做一个普通聊天程序

学：请求与响应、JSON、角色与消息历史、模型参数、凭据读取；先使用非流式响应。

读：[Kimi Chat Completions API](https://platform.kimi.com/docs/api/chat) 中请求 messages、返回 message、finish_reason 的相关部分。

做：输入一句话、调用 Kimi、打印完整回答；将上一轮消息附在下一次请求里，实现连续对话。打印去掉凭据的消息结构，检查模型实际收到什么。

过关：能解释模型为什么知道上一轮说了什么；主动漏掉历史后能预测区别；区分你的消息存储与供应商内部状态。

暂估 3–5 小时。接入前先确认当前账号可用的模型与对应参数，完成小样本调用预算说明。凭据通过本机配置提供，不发到对话或文档里。

### 4. 写出真正的工具循环

学：函数作为值、工具注册表、JSON Schema 与运行时校验、工具调用 ID、循环和停止条件。

读：[Kimi 工具调用指南](https://platform.kimi.com/docs/guide/use-kimi-api-to-complete-tool-calls) 中定义工具、处理 tool_calls 和回传工具结果的部分。

做，按以下顺序逐个增加：

1. 先写一个直接调用的 read 函数，在练习目录读到内容。
2. 写一个固定返回值来模拟模型提出 read 请求；按工具名分发执行，并形成结果。
3. 让 Kimi 返回真实 read 请求，执行后把结果回传，观察第二次模型回答。
4. 把一次工具调用改为循环；同一响应中的多个调用先顺序执行，每个结果正确对应调用 ID。
5. 再增加 write、edit、bash，检查错误与文件结果。

过关：不用抄完整 Agent 实现，自己写出循环；能说明每次请求包含哪些消息、是谁选择工具、是谁真正执行、何时继续、何时结束。未知工具、非法参数、文件不存在和编辑匹配不唯一都有明确结果。

给学习版设置明确的最大轮数和工具超时；这些属于教学实现的约束，不直接当成上游默认策略。工具仅对合成练习目录使用。

暂估 8–12 小时；这是主线最需要花时间的阶段。

### 5. 对照 Pi，读懂它为什么这样写

学：够读源码的 TypeScript：type/interface、联合类型、类型收窄、函数类型；读到 class/this、闭包或泛型时再用小例子补。

读，按问题拆开，不要求一次通读：

- [types.ts](../资料/本地资料/pi/packages/agent/src/types.ts)：消息、工具、事件分别怎样描述。
- [agent-loop.ts](../资料/本地资料/pi/packages/agent/src/agent-loop.ts)：runLoop、prepareToolCall、executePreparedToolCall、createToolResultMessage。
- [agent.ts](../资料/本地资料/pi/packages/agent/src/agent.ts)：一次运行的状态、取消与事件处理。
- [工具实现](../资料/本地资料/pi/packages/coding-agent/src/core/tools/)：与你的四个工具逐项比较。

做：在你已有的小 Agent 上给消息和工具结果加类型；写一张“我的函数 → Pi 的函数 → 我的简化”对照表。顺着一次 read 操作标出调用与状态变化。

过关：能解释 TS 静态类型为什么不能代替工具参数校验；能识别自己的循环与 Pi 的关键差异，并从错误现象定位到相应函数。

暂估 4–6 小时。原克隆继续作为参考；不要求把整个 Pi 项目先构建起来。

### 6. 加上流式输出、事件和取消

学：迭代器与异步迭代、for await、事件通知、AbortController、超时清理。先消费现成流，再理解事件队列如何实现。

读：[EventStream](../资料/本地资料/pi/packages/ai/src/utils/event-stream.ts)、[agent-loop.ts](../资料/本地资料/pi/packages/agent/src/agent-loop.ts) 的 streamAssistantResponse；配合 [MDN 迭代器与生成器](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Iterators_and_generators)。

做：

- 把整段回答改为逐段显示，并记录“开始、进度、完成、失败”事件。
- 用固定分片模拟器练习工具参数跨分片拼接，完整且通过校验后才执行。
- 写一个小型异步事件队列，处理事件先到/消费者先等两种情况。
- 增加用户取消和超时，清理模型请求、计时器以及受控 shell 进程。

过关：解释“已显示部分内容”和“响应已经结束”的差别；取消后不继续开始新工具；知道已完成的文件修改不会自动回滚。

暂估 6–10 小时。无需编写复杂终端 UI；文本输出和可观察日志即可。

### 7. 保存对话，独立验收

学：序列化、简单状态保存、测试输入与预期结果；认识上下文有长度限制。

做：正常结束后把对话保存为 JSON；重新启动时加载历史继续问。若上下文超出当前教学限额，明确停止并提示开始新会话，自动摘要留作扩展。

完成下表的验收，并解释结果：

| 验收 | 你要证明什么 |
| --- | --- |
| 普通回答 | 不需要工具时能直接结束 |
| 读文件后回答 | 工具确实读到了合成文件，结果正确回传 |
| 修改文件 | 模型请求、实际文件变更与最终说明一致 |
| 多次工具调用 | 每次结果与调用 ID 对齐，循环顺序清楚 |
| 错误路径 | 未知工具、非法参数、缺失文件有可追踪结果 |
| 截断与取消 | 不执行不完整请求；超时/取消后停止新增操作 |
| 保存与恢复 | 正常退出后加载历史可继续对话 |
| 独立修改 | 不参考现成完整答案，新增一个工具并定位一个故意埋入的循环错误 |

确定性错误与分片测试优先用固定响应；真实 Kimi 集成用少量代表案例。你能从空文件重写简化循环、讲清一次执行的消息变化，即可证明主要机制已掌握；遇到问题的部分继续标为待验证。

暂估 3–5 小时。目标是核心机制复现，不要求与全部 Pi API 行为兼容。

## 节奏建议

上面的主线合计 **32–50 小时**，是包含小练习的初步工作量估计，不是用户已承诺的投入或保证完成时间。按每周约 6 小时，约 6–9 周；按每周约 10 小时，约 4–5 周。前三课结束后按你的实际学习速度校准。

一次学习建议 45–90 分钟，只解决一个新问题。流程：

1. 看一个小例子，说明它要解决什么。
2. 你先预测输出或行为。
3. 你运行、修改，描述现象。
4. 我根据你的代码和解释纠错，再对照 Pi。
5. 用一个很小的新题检验能否迁移。

若同一个概念连续卡住，就拆小并补课，不以课表迫使进入后续内容。每次给你的开头应是“今天要完成什么”，接着给练习和验收；源码归档、索引和维护情况只在影响学习时提及。
