## 1. 小红书｜商业化-AI Native Engineer

**画像：一个能从业务问题出发，自己写代码把 Agent 产品交付出来，并持续改进效果的人。** 理想候选人曾做过有人使用的 AI 工具，能解释用户为什么用、流程怎么设计、工具何时执行、失败怎么恢复，以及效果如何验证。产品意识和工程执行要同时成立。

**JD 明确的要求：** 页面归类为后端开发，但职责覆盖完整用户流程、Agent 运行、创意多模态任务和效果迭代。编码、真实 LLM／Agent 产品经验是实质要求；独立项目和开源成果可以作为证据。它没有把模型预训练或论文发表列为核心门槛。[官方 JD，岗位 17846](https://job.xiaohongshu.com/social/position/17846)

**候选人材料：** Recall_15 的《小红书-Rednote- Ai native面经》带实习标签，问到项目用户与效果、视频 Agent 架构、上下文管理、工具异步执行和工作流选择，也有前端及编码问题。它与 AI Native 工程方向相关，**不能确认是商业化团队，更不是这条社招的原题**；页面显示 08-05，未据此补写年份。[候选人原帖](https://www.nowcoder.com/feed/main/detail/fa23d7dd47324d11aa66cd9376ff21b8)

**综合判断：** 你最可能与这类面试官围绕业务 Agent 展开有效讨论。但仅会描述方案仍不够，需要讲清自己实现、调试和改进了哪些部分。可以用一个“业务人员实际使用的助手，从任务失败记录找到原因，再用评测验证修复”的完整交付，体现这类画像。可能追问系统实现与失败案例，是推断，不是已知面试安排。

## 2. 淘天｜业务技术-AI应用研发工程师-用户运营

**画像：有业务后端经验，能够把运营动作接入 Agent，并保障在线服务稳定的人。** 典型背景是用户运营、营销或业务平台研发，既理解人群与运营策略，又能处理任务状态、服务调用和并发问题。

**JD 明确的要求：** Agent 的规划、工具和记忆，与实时反馈、分布式服务一起出现。Java／Go／Python、微服务等是工程要求；后训练部分措辞是了解基础方法，不能解读成必须精通所有强化学习算法。页面经验标签为 2 年，正文写至少 1 年后端经验，保留这一差异。[官方 JD，100021120004，页面日期 2026-07-31](https://talent.taotian.com/off-campus/position-detail?lang=zh&positionId=100021120004)

**候选人材料：** HELIOSA 的《淘天日常实习生-用户运营技术-AI应用开发工程师一面凉经》与公司、用户运营技术和 AI 应用方向都相近。自述同时覆盖 Agent 执行流程、仓库与工具操作、RAG 切分，以及 Java 类加载、线程池、锁、集合和缓存。它直接提示“Agent 项目＋语言基础”可能同时考察；但它是实习，无法证明你的社招会使用相同题目或笔试形式。页面显示 08-18，年份未明确。[候选人原帖](https://www.nowcoder.com/feed/main/detail/5dca9d9dd8284cc4aada23b9f0c20f15)

**综合判断：** 与你的业务 Agent 意向有关联，但后端不是可以略过的部分。你补充的“偏算法组”是沟通信息，不能据此抹去 JD 的后端要求。理想交付例子是把运营意图转成可执行任务，处理超时、重试和重复执行，并验证业务效果。最值得确认的是算法同事与本岗分别负责模型训练、策略和服务实现的哪一部分。

## 3. 阿里控股／平台技术部｜数据公共层、数据语义层建设

**画像：一个本来就能把企业数据建好、管好、服务好，再把数据变得适合 Agent 使用的数据平台工程师。** 他能厘清实体、粒度、关联和指标口径，也能把这些规则接到实际数据链路和接口中。

**原始 JD 明确的要求：** 面向 Agent 的语义层是职责之一；端到端建模、流批处理、质量、血缘与 SLA 同样属于核心。LLM／Agent 部分强调兴趣与学习能力，而数据治理要求深入理解或实战。这更像以数据工程为基础招聘。原始证据来自用户提供的截图，未找到可以确认同一职位编号的公开官网页面。[岗位截图转写](阿里平台技术部/岗位JD-截图转写.md)

**实际工作线索：** DataWorks 官方语义分析文档展示了从加工 SQL 和元数据中提取业务定义、形成语义模型，再人工修改、供 Agent 使用的产品流程。这说明此类工作需要校准数据的真实含义，不能只给表补一句自然语言描述。**这是相关产品实现，不是该流通中心团队归属、技术选型或面试内容的证据。** [官方技术文档](https://help.aliyun.com/zh/dataworks/user-guide/data-agent-semantic-analysis)

**综合判断：** 你的智能经分、语义资产和查询可靠性经历有切入点，但数据建模与治理很可能被追问。一个合适的人应能把“同名指标口径不同”落到模型、规则、校验和发布流程里，并解释计算链路怎么运行。本次没有找到可确认“流通中心＋该社招岗位”的候选人原帖，不能保证面试主要聊 Agent。

## 4. 阿里云｜AI Data 工程师-MaaS数据

**画像：能把原始、多模态数据生产成训练与评测可用资产，并与算法同事一起判断数据价值的人。** 常见对应背景是大数据工程加模型数据处理，核心产出是一套可规模化运行的数据生产与质量反馈流程。

**JD 明确的要求：** 数据处理、筛选、标注、合成及模型反馈占主要内容，同时保留建模和指标资产工作。需要编码、大数据框架和机器学习基础，并有模型数据处理能力；不能把它读成只做业务问数，也不能直接等同模型底层研究岗。约面邮件部门为 AI 模型与产品评测部。[官方 JD，100016763005，页面日期 2026-09-07](https://careers.aliyun.com/off-campus/position-detail?lang=zh&positionId=100016763005)；[本次约面记录](2026-09-09-阿里云MaaS数据约面核对.md)

**实际工作线索：** 阿里云 PAI 的 Data-Juicer 文档展示了配置数据处理算子、提交分布式任务和多模态清洗等工作。这能帮助理解“AI 数据工程”如何落地：需要考虑处理效率、算子组合和产物质量。**尚未确认招聘团队使用该工具。** [PAI 官方实践，更新于 2026-04-01](https://www.alibabacloud.com/help/en/pai/quickly-submit-a-datajuicer-task)

**综合判断：** 与你原来关注的“大模型 AI 数据”吻合度高于业务 Agent 意向。可能追问如何判断样本质量、如何验证处理策略的效果，以及数据流程如何扩展；这些是基于职责的推断。只讲 Agent 如何调用模型，难以完整展示这条岗位需要的能力。本次未找到可核实的同名、同部门社招面经。

## 如何用这些画像判断后续沟通

你目前最有区分度的表达方向，可以是 **理解业务、能把 Agent 接入真实工作流程，并能用错误案例和评测改进结果的应用工程师**。这是根据你的意向和已聊过的项目提出的定位建议，是否成立仍需要你的实际交付证据支撑。
