## 3. SMQ 的阅读口径

依据[论文原文](https://arxiv.org/html/2606.31041v1)：

- arXiv 说明投稿 FITAT 2026，未在此核实已录用。文中名次是作者报告时的榜单，不是实时排名。
- 模型经过整理；论文不是自动语义生成服务的完整实现研究。
- 语义模型、SMQ 编译片段与 Agent 最后组合的 SQL 是三个不同层级。“编译器”不能被扩张成最终查询全程正确性证明。
- “每步一个工具”指循环策略；不是系统总共只有一个工具。
- 主结果 515/547 = 94.15%，是完整系统效果。其主实验为 Spider2-snow，表中按原始数据库来源分类；不能由类别名推出执行后端。
- 与其他系统的模型、知识条件等差异，使整体分数不能直接作为语义层的独立增益。
- 原文 V-C 的章节交叉引用有疑点：它引用 III 节的两类困难，对应讨论实际在 I 节。译文没有改写原件编号。

## 4. Sema-SQL 的版本与结果口径

依据[论文 v2](https://arxiv.org/html/2604.23477v2)及所保存 v1/v2 HTML：

- 摘要页题名为 *SEMA-SQL: Beyond Traditional Relational Querying with Large Language Models*；HTML 正文仍为 *Sema-SQL: Extending Relational Queries with Large Language Models*。译文标题对应正文。
- 对两个 HTML 正文文本做比较，主要可见变更为 LOTUS 连接顺序讨论增加 Glenn（2025）引用，参考文献随后重编号；没有声称核对 PDF 的全部版式差异。
- 93.3% 查询生成准确率、89.2% 端到端答案准确率、93.3% 语义连接调用缩减率是三个不同指标。
- 28% 时间／21% Token 改善的统计范围为发生优化的 33 条查询；连接实验为 10 个案例。
- LLM UDF 视作确定的未解释函数，是符号推理假设。计划等价不证明其外部知识正确；把 UDF 改写为 SQL 的语义也需要另行保证。
- 算法 1 的复杂度按原文保留；本次没有替作者补出子集与分区枚举的严格复杂度证明。
- Qwen3-256B 是论文原始模型名，未擅自改成别的型号。Token 比例的文字概括与个别表格列不完全吻合，精算应以表值重算。
- 论文示例的湾区名单含 Santa Cruz，而仓库 README 示例含 Napa；保留来源差异，不将模型或示例中的地域名单当成权威事实。
- 图 8 所在正文交叉引用写到图 10，但相应图注为图 8。译文按实际图资产嵌入，不再把图 9 链接指向不存在的锚点。
- 参考文献从 HTML 抽取，保留英文书目信息并移除“Cited by”回链；不是逐条验证了 60 条引用所述内容。

### 本次实际阅读的公开代码

#### schema_generator.py

[固定源码](https://github.com/semasql/SEMA-SQL/blob/b4866921ad0843c73a6966aca0cdd89082da1cf1/src/semasql/db_utils/schema_generator.py)

本次完整静态阅读了该文件。可观察到：

- 生成从 SQLite 文件和 `database_description/` 的 CSV 开始，按 CSV 文件名确定待处理表。
- 用 PRAGMA 获取列定义，合并描述，再为列取最多三个不同样本值，形成模型输入。
- 通过模型输出 YAML；代码以 `yaml.safe_load` 检查可解析性。
- 部分 CSV 读取或格式问题会记录后跳过，采样失败也可能只留下警告。因此要区分生成成功与覆盖完整。
- 该函数显示的流程没有充分展示关系、业务公式、证据绑定等全面语义验证，不能把它当作完整企业平台实现。
- 主键判断使用 `pk == 1`，复合主键的后续序号值得进一步检查。这里只记录阅读发现，没有修改源码。

这些观察针对指定文件和版本，不推断仓库其他模块完全没有相关能力。

#### symbolic_verification.py

[固定源码](https://github.com/semasql/SEMA-SQL/blob/b4866921ad0843c73a6966aca0cdd89082da1cf1/src/semasql/core/symbolic_verification.py)

本次完整静态阅读了该文件，发现其符号表示范围有限：

| 代码路径 | 观察 | 为什么影响证明范围 |
| --- | --- | --- |
| 普通 selection | 返回符号表副本，没有建模过滤条件 | 不能据此证明任意普通谓词的变换 |
| 普通 join | 组合行存在条件，未表达实际连接谓词 | 连接语义没有完整进入模型 |
| 部分 TopK／aggregation 分支 | 返回未变副本 | 没有完整刻画排序、聚合效果 |
| 最终 equivalence 检查 | 比较行存在条件 | 没有同时覆盖输出值、重复度、顺序等全部 SQL 语义 |

代码对异常、超时等会返回不等价，但这不能弥补符号模型本身遗漏的语义。正确的学习结论是：检查“验证器究竟表示了什么”，不要只检查“是否调用 Z3”。

本次未沿调用者、全部规则守卫和运行测试验证适用范围，所以不据单模块静态阅读认定所有优化错误或论文实验无效。
