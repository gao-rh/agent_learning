# 岗位 JD 归档说明

## 归档目标

本目录保存 2026-09-03 调研中发现的 AI 训练数据工程、训练数据算法、评测数据与数据飞轮岗位。每个文件尽量保留招聘页面原始职责和原始要求，并记录来源、抓取时间和证据边界。

## 目录结构

```text
岗位JD/
├── README.md
├── 岗位目录.md
├── 腾讯/
├── 非腾讯-近30天/
├── 当前存量/
└── 强相邻/
```

## 口径

- `腾讯/`：2026-08-04 至 2026-09-03 在腾讯官方招聘体系发布或更新，训练/评测数据为核心职责的岗位。
- `非腾讯-近30天/`：同一窗口内，从官方招聘页或可回到官方投递入口的同步页面核验到的核心岗位。
- `当前存量/`：发布日期早于窗口，但 2026-09-03 仍能在公开招聘体系核验的核心岗位。
- `强相邻/`：以 Agent 环境、仿真或训练数据基础设施为主要职责，和核心方向高度相邻但不完全等同的岗位。

## 证据等级

| 等级 | 定义 |
| --- | --- |
| A | 官方页面或官方结构化接口可直接取得完整 JD |
| B | 官方投递入口仍有效，但正文或日期需要官方同步索引/招聘镜像补充 |
| C | 当前只能取得招聘镜像正文；已保留镜像与官方入口，仍需后续复核 |
| D | 仅确认岗位存在，完整原文尚未取得；不得用于精确能力频次统计 |

## 原文边界

- `原始职责`、`原始要求`只保存来源页面文本，不做措辞优化。
- 研究者判断、去重说明和证据限制放在独立小节。
- 同一 JD 多城市发布时，合并为一个岗位族，但保留所有已知职位 ID、城市和链接。
- 招聘页面的“发布/更新日期”可能是刷新日期，不等于新增 HC；岗位文件不把它解释为净新增人数。
