# 2026-08-23 第 3 章记忆实验复现口径核对

## 原始问题

这次 10 个用例、4 种记忆格式的实验结果，是不是仍然没有和书里的实验对上？

## 用户理解

- 用户感觉：本次结果中 Notes / Enhanced Notes 并不差，Advanced JSON Cards 也没有显示出书中所说的明显优势，因此怀疑实验口径还是没有对齐。

## Codex 反馈

### 已对齐的部分

- 使用原仓库英文 YAML 测试用例。
- 英文模式直接调用原 runner 的 `memory_prompt()` 和 `answer_prompt()`，没有翻译或修改 prompt。
- 使用 Notes / Enhanced Notes / JSON Cards / Advanced JSON Cards 四种表示。
- 每轮只向 writer 提供“旧记忆 + 当前会话”；最终回答只能看最终记忆。
- Judge 的通过公式与原 runner 一致：无实质幻觉，且 precision / recall / reasoning 均不低于 3。

### 未对齐的部分

- 原 runner 的 authoritative campaign 是 60 用例 × 4 模式；本次是 10 个目的抽样用例 × 4 模式。
- 原 runner 默认 writer 是 `doubao-seed-1-6-250615`；本次 writer + answerer 是 Kimi K2.6。
- 原 runner 默认 Judge 是 `moonshot-v1-32k`；本次是 GPT-5.6 SOL 子 Agent。
- 原 runner 设置 `temperature=0`、`seed=37`，记忆/回答输出上限为 6,000 / 1,200 token；本地 wrapper 关闭 Kimi thinking，未显式设置相同 temperature/seed，上限为 16,384 / 4,096 token。
- 本次 GPT Judge 逐条以原会话为最高证据，并显式标记 fixture / expected criteria 与原对话的冲突；这与原书生成结论时的实际 Judge 行为不能直接视为相同。

因此，本次是“原数据 + 原 prompt + 原链路的 Kimi/GPT 对照实验”，不是书中 campaign 的严格复现。它不能用数值直接验证或推翻书中结论。

## 发散联想

- 当对比记忆表示时，writer 模型、answerer 模型、Judge 口径、样本集和生成参数都会改变结论；不只是 prompt 需要固定。
- “结构更好”至少应拆成三个可观测问题：writer 是否写对、表示是否便于状态更新、answerer 是否正确使用。
- 本次的价值不是复现书中排名，而是已经看到了 writer 污染、answerer 误用、生命周期丢失和输出上限四类具体失败。

## 结论状态

- 问题：待验证
- 当前草案判断：是，本次仍未与书中完整实验严格对齐；但机制与 prompt 已基本对齐。

## 后续动作

- 若要检验“是模型/Judge 导致差异，还是书中结论本身不稳定”，先用相同 10 个用例完全复刻原 runner 的 writer、Judge 和参数，再决定是否扩大到 60 用例。

## 后续复盘：Advanced JSON Cards 失败阶段

### 原始问题

Advanced JSON Cards 未通过时，究竟是记忆本身写错，还是记忆大致正确但回答用错？

### 拆分结果

- 10 个 Advanced arm 中 4 个通过，6 个未通过。
- 航空用例：记忆生成在第 1 轮即触发 16,384 token 上限，无最终记忆和回答。
- 多药品用例：writer 在源对话没有给年份时自行补成 2023；answerer 又声称有 4 种降压药却只列出 3 种。属于“写错 + 用错”。
- 旅行改签用例：writer 写入源中没有的 62,000 miles，并把个人 Amex 与后续 corporate Visa 的付款历史压平；answerer 照着复述。错误主要起源于记忆。
- 医疗手术用例：最终卡片明确保留 `surgery_auth_status=not yet received, being expedited`，但 answerer 完全漏掉这个最关键阻塞项。记忆正确，回答用错。
- 保修用例：卡片已正确保留保修、延保和 120 天购买保护；answerer 额外编出精确维修价格、自修选项和保修影响，还先将已过期的购买保护称为“最佳选项”再否定。记忆大致正确，回答用错。
- 税务用例：卡片关键生命周期实际保留得不错，捐赠为 `initiated`、装修为 `planned`，并存有 Schedule A 剩余额。answerer 仍把未完成的 5 万美元装修加入房屋 basis，同时重复计算全额房贷/房产税与家庭办公部分，还自行将 4,700 拆成两笔 2,350。存在部分 writer 过度确认字段，但可观测的主要失败在 answerer。

### 当前草案结论

Advanced Cards 的结构优势主要是“让对象、状态、版本和来源更易被检查”，不是“自动保证 writer 写对或 answerer 用对”。本实验没有程序化查询这些字段；answerer 只是一次性读取整个巨大 JSON 后自由生成回答。因此结构优势可能未被利用，反而带来更长上下文、更多重复状态和输出上限风险。

## 3-1 / 3-2 阶段总结（AI 草案）

### 已经覆盖的学习内容

- 已看清记忆写入链路：`M(t-1) + H(t) -> M(t)`，下一轮不再看旧原始会话；最终回答只看 `M(t) + Q`。
- 已看过 Notes / Enhanced Notes / JSON Cards / Advanced JSON Cards 四种记忆结构的真实输出和逐轮变化。
- 已观察 Layer 1 精确事实、Layer 2 多实体/更新、Layer 3 跨会话综合的难度差异。
- 已用原英文 YAML 和原 prompt 跑 10 个目的抽样用例 × 4 格式，保留 39 个成功 arm 和 1 个真实输出上限失败。
- 已观察四类失败：writer 污染、answerer 误用、生命周期处理错误、输出上限。
- 已确认“格式更结构化”不等于“答案更正确”；结构优势需要查询、状态过滤和回答约束才能发挥。
- 已有 token、费用、延迟、结构大小和独立 Judge 结果；但已明确这是 B 级受控教学实验，不是书中 60×4 的 C 级完整验收。

### 仍需要学的内容

1. **必须补：分阶段评估。** 将当前只看最终答案的 Judge 拆成 writer fidelity / state update / answer usage 三段，否则无法知道错误是在哪一步发生。学习状态：`待继续`。
2. **必须补：亲手解释一条完整失败链。** 建议用医疗 Advanced 案例：源对话 -> 最终卡片 -> 最终回答，由用户判断为什么是 answerer usage 失败。学习状态：`待继续`。
3. **后续章节学：真正的记忆检索与查询约束。** 3-1/3-2 是把整个最终 memory state 塞给 answerer，没有测试 embedding / top-k / 按字段过滤 / Agent 多轮搜索。这些主要对应 3-9 和 3-11。学习状态：`待继续`。
4. **可选验证：严格复刻书中排名。** 只在目标是验证书中结论时，才需要同 writer / Judge / 参数跑同 10 例，再决定是否扩到 60×4；对掌握记忆机制并非必需。状态：`待验证`。

### 不建议继续的动作

- 不建议在同一 Kimi K2.6 + 同一 prompt 配置下继续盲目增加样例数；当前主要失败机制已经重复出现，边际学习收益很低。
