# 2026-08-22 Agent 脑手分离与沙箱

## 原始问题

现在的 Agent 架构通常是脑手分离。什么叫大脑和手分离？沙箱在其中承担什么成分？希望结合《深入理解 AI Agent》和当前学习内容解释清楚。

## 用户理解

- 用户初始理解 / 假设：现在的 Agent 架构通常是“脑手分离”。
- 待澄清：“大脑”“手”“Harness”“工具执行器”“环境”“沙箱”是否处于同一层。

## Codex 反馈

- “脑手分离”是有用的工程类比，但不是统一的正式架构名称。更严格的表达是：**模型负责提出下一步行动，Harness 负责校验、授权、调度和回传，执行器在环境中产生真实副作用。**
- 模型返回的 tool call 只是结构化的行动意图，不等于工具已经执行；执行结果必须作为新的观察回到上下文，模型才能继续判断。
- “手”可进一步拆成工具定义、调用适配器和执行器。工具定义告诉模型“能做什么”；执行器才真正读文件、运行代码或调用 API。
- 沙箱不是大脑，也不等于工具。它是通用执行工具运行时的隔离边界，主要约束文件系统、网络、进程、资源和生命周期；权限门控发生在执行前，沙箱约束已经获准运行的进程，二者互补。
- 书中更精确的边界是：沙箱的权限与重置机制属于 Harness；沙箱内不断变化的文件和进程属于 Environment。
- 不是所有工具都需要沙箱。任意代码、Shell、浏览器或桌面操作尤其需要隔离；转账、发邮件等真实外部副作用无法靠“放进沙箱”解决，应使用窄接口、最小权限、预览确认、幂等和审计。

## 发散联想

- 当前第 3 章记忆实验主要位于“上下文 / 眼睛”一侧：外部记忆被检索并写入上下文后影响模型决策，但记忆本身不是模型参数意义上的“大脑”。
- 已有 `minimal-agent-tool-loop` 正好能观察脑手分离：`TOOLS` 是接口说明，模型返回 tool call，Python 的 `execute_tool` 才实际执行，tool result 再追加回消息轨迹；最大迭代次数是 Harness 约束。这个实验使用 Python 虚拟环境，但虚拟环境只隔离依赖，不等于安全沙箱。
