# 2026-08-19 第 3 章实验 3-3 与理赔项目脱敏关联

> 我的理赔项目可以把我学习中的那个实验的部分参考一下，结合一下。我其实跟他做的是一样的，只不过我在公司里拿不出来。所以你就把这个先当做我那其中的脱敏部分吧。我那个项目的核心其实也不是脱敏，但是有脱敏的部分。有脱敏的部分就先按他这个来。这是那个 Agent 书的第三章的一个实验。

用户提供的实验说明是“实验 3-3：基于本地模型的智能日志脱敏”：通过 Ollama 调用本地 Qwen3 小模型检测并脱敏日志中的 PII，以 JSON Schema 返回类型、位置和置信度；高吞吐场景可组合正则预筛与 LLM 深度分析。

- 真实项目链路中包含脱敏环节，但公司内部实现、代码和数据不能带出。
- 用户确认：先把书中实验 3-3 当作理赔项目脱敏部分的公开、脱敏参考，并在学习实验与项目复盘之间建立关联。
- 用户认为，实验描述的脱敏部分与自己真实项目中所做的部分相同或高度对应。

## Codex 反馈

### 可以建立的对应关系

| 书中实验 3-3 | 理赔客服风险质检中的位置 |
| --- | --- |
| 敏感日志作为输入 | 可能包含敏感信息的 ASR 文本或中间文本 |
| 在本地模型中识别 PII | 在文本离开受控边界前发现敏感内容 |
| 输出类型、位置和置信度 | 为替换、遮盖、审核和追踪提供结构化依据 |
| 正则预筛 + LLM 深度分析 | 对应项目中的规则与 AI 组合脱敏思路 |
| 脱敏后的文本供后续处理 | 脱敏后再进入外部模型复审环节 |

因此，实验 3-3 可以作为[理赔客服风险质检](../../面试准备/项目准备/理赔客服风险质检/README.md)中“脱敏子链路”的公开学习替身，但不能代表整个项目。项目的核心仍是风险筛查；脱敏解决的是数据能否安全进入后续处理的问题，不直接解决风险识别准确率。

### 必须保留的证据边界

- “按实验来”表示用公开实验还原功能与设计取舍，不等于确认公司内部实际使用了 Ollama、Qwen3 0.6B、相同 JSON Schema 或完全相同的实现。
- “召回率 95% 以上”“显著降低假阳性”目前只是用户转述的实验说明，尚未看到数据集、样本量、PII 类型分布、评测口径和对比基线，不能写成个人项目的已验证结果。
- 模型给出的“置信度”不天然等于校准后的真实概率；如果要用它控制自动脱敏或人工复核，需要单独做阈值与校准实验。
- 本地推理降低了敏感文本发送到云端的风险，但隐私保护还取决于日志留存、模型输入输出缓存、访问权限、密钥与审计等边界，不能把“本地模型”等同于“已经安全”。

## 发散联想

- 这个公开实验很适合在面试中解释一个完整但脱敏后的局部设计：为什么先在受控边界内检测和替换敏感信息，再调用外部模型。
- 如果后续真正复现，可以重点比较三条链路：纯正则、纯本地 LLM、正则预筛加本地 LLM。比较维度至少包括召回率、精确率、延迟、吞吐量和漏脱敏风险。
- 小模型是否能稳定识别地址、口语化密码等上下文型 PII，是实验最值得验证的部分；身份证号、银行卡号等强模式本身未必需要 LLM。
