## 用户理解

## Codex 反馈

### 1. 实验要解决什么

实验 3-12 不再研究“怎样把已有答案检索出来”，而是研究：面对大量历史案例，能否让 LLM 先从数据中发现可能影响结果的因素，把自然语言案例转成结构化特征表，再从特征表中归纳出若干可解释的案例原型，最后用这些原型辅助分析新案例。

从数据开发视角，它相当于：

```text
自然语言案例
  -> LLM 自动发现候选字段（特征工程）
  -> 按字段抽取每个案例
  -> 向量化和聚类
  -> 得到典型案例原型及结果分布
  -> 新案例匹配原型并提示缺失信息
```

### 2. 正式实验数据

- 数据源：真实 CAIL2018 中文刑事案件。
- 罪名：盗窃罪、故意伤害罪、诈骗罪。
- 固定样本：420 条，其中训练 360 条、留出测试 60 条；每个罪名训练 120 条、留出 20 条。
- 训练数据用于发现 schema、抽取特征和建立原型；留出案件不能参与这些步骤，只用于最后验证。

### 3. 四个阶段

1. **因子发现**：不先给固定字段，把训练案件分批交给 LLM，让它自由提出可能影响裁判或量刑的因素。
2. **结构化抽取**：将分批发现的因素归并为 `通用核心因子 + 罪名扩展因子`，再按这套 schema 从每个案件抽值；未提及的信息填 `null`。
3. **案件原型聚类**：把布尔、分类、数值因素向量化，在每个罪名内部用 KMeans 聚类；用轮廓系数在 k=2–5 中选择分组数，并计算每个原型的典型刑期和定义性因素。
4. **新案建议**：从留出案件抽取已知因素，匹配最近的同罪名原型，只引用原型统计给出解释和不确定性提示，并附法律免责声明。

### 4. 第一条真实教学案例

一条留出盗窃案的大意：被告人利用自己在市场做搬运工的便利，预先打开仓库天窗，市场关门后攀爬进入多个摊位，盗取现金 2,075 元和一张非单位不能支取的转账支票；数日后持支票到银行取现时被抓获。

在看模型 schema 前，首先要由用户判断：如果目标是比较历史案例并估计相似案件结果，这段事实中哪些因素值得变成结构化字段，哪些只是叙事细节。

### 5. 历史运行与本次预算边界

仓库保存的正式历史运行使用 360 条训练、60 条留出，共 117 次 API 调用、958,190 tokens；这不是本次学习新增消耗。本次及后续不会默认全量重跑，若需要在线验证，只抽取约 10 个代表案例，并在运行前说明调用量和费用。

### 6. 它与 JSON Card、记忆抽取的区别

用户理解：LLM 先发现 JSON Card 应该组织哪些字段，再从原文抽成对应字段，最后做统计。

其中“先发现字段 → 再逐案抽取 → 再统计”是正确的；但这里的产物更准确地称为 `schema + 特征表`，不是实验 3-1 的用户记忆 JSON Card。JSON 只是序列化格式，字段也可以进入数据库表、Pydantic 模型或 Parquet。

两类任务的边界：

| 维度 | 用户记忆抽取（3-1） | 结构化知识抽取（3-12） |
|---|---|---|
| 输入 | 某个用户的一段或多段会话 | 大量不同案件及其罪名、刑期 |
| 目标 | 记住该用户未来仍需要的事实和当前状态 | 发现所有案件共有的影响因素与统计模式 |
| 输出 | 用户级 Notes / JSON Cards | 数据集级 schema、逐案特征表、聚类原型和结果分布 |
| 更新关注 | 新事实覆盖旧事实、实体消歧、时间状态 | 因子稳定性、抽取准确性、聚类质量和留出泛化 |

所以它不属于狭义的记忆抽取，而是离线的知识发现和特征工程。产出的 schema、特征表和原型以后可以被 Agent 当作知识库或长期知识使用，但“可被记忆系统保存”不等于“生成过程本身就是记忆抽取”。

实验真正想表达的不只是“从原文抽 JSON”，而是：

```text
原始案件文本 + 已知结果标签
  -> 从多条数据中发现共同 schema
  -> 将每条文本转成可比较的结构化特征
  -> 从特征和结果中归纳群体模式
  -> 用留出新案检验这些模式是否有参考价值
```

实际数据也不是纯原文：`fact` 是非结构化案情文本，罪名和实际刑期是结构化标签。LLM 主要从 `fact` 发现和抽取因素；聚类后的刑期统计还要使用数据集提供的实际刑期标签。

### 7. 核心学习目标

本实验真正要表达的是：RAG 不只能把原文检索给模型；面对大量历史记录，还可以先用 LLM 发现共同的业务维度并转成结构化特征，再用传统统计/机器学习归纳群体模式，最后让 Agent 基于这些模式解释、追问和建议。

需要掌握五点：

1. **Schema discovery 与 extraction 是两个阶段**：前者决定“表应该有哪些列”，后者决定“每一行的列值是什么”。Schema 漏掉关键因素会污染所有后续案例，比单行抽取错误影响更系统性。
2. **LLM 与传统算法分工**：LLM 擅长理解文本、发现和填写语义字段；KMeans、轮廓系数和分布统计负责可复算的聚类与数字。不要让 LLM凭空生成刑期数字。
3. **训练集与留出集隔离**：schema、抽取规则、聚类和原型只能由训练数据形成；留出案件的真实刑期不能进入建议 Prompt，否则属于标签泄漏。
4. **聚类原型只是数据模式，不是因果规则**：因子方向、相似原型和刑期分布不能自动等同于法律上的量刑因果关系。
5. **逐层验收而不是只看最终建议**：依次检查因子是否合理、字段是否抽对、缺失值是否正确、聚类是否成形、原型样本量是否足够、建议是否只引用原型统计并明确不确定性。

本实验历史运行虽通过产物验收，但聚类信号较弱：盗窃/诈骗/故意伤害的最佳轮廓系数分别约为 0.061/0.143/0.217，且存在只有 1 个训练样本的原型。因此它能证明流水线跑通，不能证明这些原型已经具有可靠预测能力。

从工程视角，最值得迁移的模式是：

```text
非结构化业务记录
  -> 数据驱动发现候选 schema
  -> 人工审查并版本化 schema
  -> 批量结构化抽取
  -> 统计/聚类/规则归纳
  -> 留出集验证
  -> Agent 只基于可追溯结果做解释和追问
```

实际项目中不应完全放任 LLM 自动决定 schema；更稳妥的是让 LLM 发现候选因素，由领域专家合并、删减和确认后，再批量抽取。

## 发散联想

- 这不是普通 RAG，而是“LLM 辅助特征工程 + 无监督聚类 + 基于案例的推理”。
- LLM 发现的因素只是候选相关因素，不自动等于法律上的因果因素或正式裁判规则。
- 原型若样本太少或聚类结构很弱，即使建议完全忠实于原型统计，也可能没有实际预测价值。
