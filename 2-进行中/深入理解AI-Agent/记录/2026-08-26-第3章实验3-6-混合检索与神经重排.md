## Codex 反馈

### 实验目标

3-6 不再研究单个 BM25 公式，而是用同一语料和人工相关性标注做消融：比较稀疏 BM25、稠密向量、RRF 融合、归一化加权融合，以及融合后神经重排各自解决了什么问题、增加了什么成本。

### 当前代码中的固定输入

- 当前 `evaluate.py` 定义 20 篇文档，而 README 中“17-doc”属于历史输出描述，应以代码为准。
- 12 条查询：4 条近似重复技术代码、1 条精确人名、4 条零词汇重叠的英文语义改写、1 条中文跨语言查询、2 条长文档语义查询。
- 技术代码簇包括 `XR-7001` 至 `XR-7006` 和多个近似 HTTP 状态码；这些文档除代码外几乎相同，用来制造稠密向量难以区分、BM25 精确命中的场景。
- 语义簇故意让查询与正文几乎没有共同词，例如查询“植物如何把阳光转化为食物”，相关英文文档写的是“Green plants convert sunlight into chemical energy stored as sugars.”，用来制造 BM25 无候选、稠密检索占优的场景。

### 五条受控链路

```text
BM25
Dense
BM25 + Dense → RRF
BM25 + Dense → min-max 归一化加权
BM25 + Dense → RRF → Cross-Encoder 重排
```

### 评价指标

- `Recall@3`：前三名召回了多少人工相关文档。
- `MRR`：第一个相关文档排得多靠前。
- `nDCG@3`：整个前三名排序质量。
- 构建与查询延迟，以及重排前后的名次变化。

### 核心教学边界

- 融合负责合并互补候选，重排只负责重新排列已经进入候选池的文档。
- 如果稀疏和稠密两路都没把正确文档放进候选池，重排器无法凭空找回来。
- RRF 主要使用名次，避免直接比较不在同一尺度上的 BM25 与余弦分数；归一化加权融合对分数分布和权重更敏感。

### 两种融合的真实实现

两路先独立检索，得到两个 `(doc_id, score)` 排名列表。融合阶段按 `doc_id` 取并集并去重；文档只出现在一路时，另一路贡献为 0。它既不拼接文本，也不拼接 BM25 稀疏向量和 Dense 稠密向量。

#### RRF：只融合名次

```text
RRF(d) = Σ_source weight(source) × 1/(k + rank_source(d))
```

当前默认 `k=60`、两路权重均为 1。原始 BM25 分数和余弦相似度被丢弃；同一文档在两路中都靠前时，会得到两项贡献相加。`k` 越大，第一名与后续名次之间的差距越平缓。

例：BM25 把 `XR-7003` 排第 1；Dense 把 `XR-7001` 排第 1、`XR-7003` 排第 2。若 `XR-7001` 不在 BM25 列表中：

```text
XR-7003 = 1/(60+1) + 1/(60+2) = 0.03252
XR-7001 = 0          + 1/(60+1) = 0.01639
```

因此两路共同支持的 `XR-7003` 胜出。

#### Weighted：先各自归一化，再加权求和

每一路独立做 min-max：

```text
normalized_score = (score - 本路最小值) / (本路最大值 - 本路最小值)
```

随后：

```text
fused(d) = dense_weight × dense_norm(d)
         + sparse_weight × sparse_norm(d)
```

它保留“同一路中分数差距有多大”的信息，但归一化结果会受候选池中的最高分、最低分和离群值影响；只有一个结果或所有分数相同时，当前实现把该路所有归一化分数设为 1。

融合完成后输出统一候选列表；神经重排器只读取 RRF 前 `rerank_pool` 个候选并重新排序，无法恢复未进入融合池的文档。

### 本实验需要真正掌握的内容

1. **职责边界**：BM25 与 Dense 负责候选生成，融合负责合并两路证据，Cross-Encoder 只重排已有候选。
2. **互补失败模式**：BM25 在零词汇重叠和跨语言查询上漏召回；Dense 可能混淆仅代码不同的近重复文档。
3. **融合差异**：RRF 只使用名次、尺度稳定；Weighted 保留归一化后的分数差距，但更受候选池、离群值和权重影响。
4. **重排边界**：重排器可能改善排序，也可能因模型领域不匹配把正确结果降级；它不是必然增益，更不能恢复候选池外文档。
5. **质量与成本**：同时比较 `Recall@3`、MRR、`nDCG@3` 与端到端延迟，不能只看单一准确率。
6. **实验设计**：固定语料、查询、人工标签、`top_k` 与模型，只切换检索链路；先逐查询解释失败，再汇总宏指标。

逐查询观察：

1. 4 条技术代码和 1 条精确人名上，BM25 与 Dense 都把答案排第 1。当前小语料没有制造出 Dense 混淆代码的失败，因此只能证明 Dense 在本样本上没失败，不能据此否定 BM25 的精确匹配价值。

5. Cross-Encoder 没有带来总体增益：它把垃圾回收语义查询的正确文档从第 1 降到第 2，把中文跨语言查询从第 1 降到第 3。前者中错误文档与正确文档的负 logit 仅差约 0.003，属于模型不确定时的误排；后者使用的是英语 MS MARCO 重排器，中文查询与其训练分布不匹配。重排器只增加约 20 ms 平均延迟，却把 MRR 从 1.0 降到 0.9028。

### 实验结论

- 本数据集上最佳且最稳定的是 RRF：保持 `Recall@3/MRR/nDCG@3=1.0`，融合计算本身几乎没有成本；主要耗时来自 Dense 编码。
- Weighted 不是错误算法，但分数归一化和权重会放大某一路的错误高分；RRF 也不是永远正确，它可能出现同分并受 tie-break 影响。
- 重排器必须用与语言、领域和任务匹配的模型，并在自己的验证集上验收；“模型更复杂”不等于“排序一定更好”。
- 本次核心教学目标已经覆盖；若以后要做更严格的生产型实验，应扩大查询集、加入 Dense 容易混淆的真实编号案例、预热后单独计时，并对 RRF 同分规则和重排模型做单变量对照。

### 补充理解：BM25 主要纠正 Dense 的什么问题

BM25 纠正的不是“语义理解本身”，而是 Dense 的**语义过度泛化**：Dense 可能知道两个文档主题非常相似，却没有把其中一个必须逐字符一致的标识符当成决定性约束。

典型的编号混淆是：

```text
查询：XR-7003
D1：Product model XR-7003 is a smartphone available now.
D2：Product model XR-7005 is a smartphone available now.
```

两篇文档除最后一位编号外完全相同。Dense 向量主要表达“某款 XR 手机型号”，两个向量会非常接近；数字可能被切成子词，编号差异也可能只占整个文档向量的一小部分，因此 D1、D2 的相似度差距很小，容易受模型、分块和近似向量索引误差影响而互换。BM25 若把 `XR-7003` 保留为一个精确 token，该稀有 token 只出现在 D1，会给予 D1 很高的 IDF 贡献。

同类案例还包括订单号、发票号、错误码、软件版本、数据库字段名、API 名称和相似人名。BM25 在这些场景提供的是**字面证据锚点**，用来压制“主题很像但身份不对”的 Dense 候选；RRF 中，正确文档若同时得到 Dense 与 BM25 支持，通常会超过只得到 Dense 支持的近似文档。

BM25 除了快，还有三个常见优势：精确 token 可控、得分来源可解释、对新出现的专有名词和未见编号无需重新训练模型。但它依赖正确的分词/归一化：如果分析器把编号拆坏、删除连字符或忽略数字，这个优势也会消失；标准 BM25 也不理解同义改写和跨语言。

本次 3-6 中“编号混淆”只是要检验的典型风险，**并没有实际发生**：Qwen3 Embedding 把 4 条技术代码都排在第 1。因此当前证据只能说明这个 Dense 模型在这组简单编号上表现良好，不能用它证明 BM25 已经完成了编号纠偏。

### 重点复习图：3-6 流水线与公式

```mermaid
flowchart TD
    Q[查询 q] --> S[BM25 稀疏召回]
    Q --> D[Dense 稠密召回]
    S --> U[候选并集并按 doc_id 去重]
    D --> U
    U --> R[RRF 名次融合]
    U --> W[归一化加权融合]
    R --> P[取 RRF Top-N 候选]
    P --> X[Cross-Encoder 重排]
    R --> E[和人工标签比较]
    W --> E
    X --> E
    E --> M[Recall@3 / MRR / nDCG@3 / 延迟]
```

每层核心公式：

1. BM25：`s_s(q,D)=Σ_t IDF(t) × TF(t,D)(k1+1) / [TF(t,D)+k1(1-b+b|D|/avgdl)]`。
2. Dense：`s_d(q,D)=cos(E(q),E(D))`；当前向量已归一化，因此代码用点积 `E(D)·E(q)`。
3. 候选池：`C=TopK_sparse ∪ TopK_dense`，按 `doc_id` 去重。
4. RRF：`s_rrf(D)=w_s/(k+r_s(D)) + w_d/(k+r_d(D))`；缺席一路时该项为 0。
5. Weighted：每路先做 `ŝ=(s-min)/(max-min)`，再算 `s_w(D)=w_s ŝ_s(D)+w_d ŝ_d(D)`。
6. Cross-Encoder：`z(D)=CE([q;D])`，直接把查询和候选文档一起送入分类模型，按输出 logit `z(D)` 降序；当前实现不额外做 sigmoid。
7. Recall@3：`前三名中的相关文档数 / 全部人工相关文档数`。
8. MRR：`1 / 第一个相关文档的排名`，再对查询取平均。
9. nDCG@3：`DCG@3 / 理想排序的 DCG@3`，相关文档越靠后折扣越大。

最短结论：**BM25 找精确词，Dense 找语义；融合扩大并整合候选，重排只优化已有候选顺序；最后同时比较质量与延迟。**
