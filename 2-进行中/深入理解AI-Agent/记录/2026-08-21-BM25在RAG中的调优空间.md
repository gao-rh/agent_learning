# 2026-08-21 BM25 在 RAG 中的调优空间

## 原始问题

本记录暂按“RG”指“RAG”理解。

## 用户理解

- 用户已从倒排索引和 BM25 的基本公式继续追问工程调优空间。
- 当前问题尚未区分 BM25 公式参数与整个 RAG 检索链路的参数。

## Codex 反馈

### BM25 公式中的核心参数

\[
\operatorname{score}(q,d)=\sum_{t\in q}\operatorname{IDF}(t)\cdot
\frac{f(t,d)(k_1+1)}
{f(t,d)+k_1\left(1-b+b\frac{|d|}{\operatorname{avgdl}}\right)}
\]

| 参数 | 控制的问题 | 调大后的主要效果 | 边界 |
| --- | --- | --- | --- |
| `k1` | 同一个词在文档中重复出现时，TF 多快饱和 | 允许重复词继续带来更多增益 | 不能解决同义词、分词错误或缺词问题 |
| `b` | 文档长度应多大程度影响 TF | 更强地惩罚长于平均长度的文档，并相对抬高短文档 | `b=0` 不做长度归一化，`b=1` 完全使用长度比例 |

Lucene/Elasticsearch 的常见默认值是 `k1=1.2`、`b=0.75`；本书实验 3-5 的教学实现默认 `k1=1.5`、`b=0.75`。默认值只是起点，不是普遍最优值。

`IDF`、文档长度 `dl` 和平均文档长度 `avgdl` 也进入公式，但通常是由索引语料自动统计出来的量，不是直接手调参数。分块方式、索引范围和分词结果会间接改变这些统计量。

Lucene/Elasticsearch 还暴露 `discount_overlaps`，控制同位置重叠 token（常见于同义词处理）是否计入字段长度。经典 BM25 的某些版本还有查询词频参数 `k3`，BM25+ 等变体还有 `delta`，但它们不属于当前书中实现和常见 Lucene BM25 的主要调参面。

### RAG 中更大的优化空间

| 层次 | 可调内容 | 为什么可能比 `k1`、`b` 更重要 |
| --- | --- | --- |
| 文本处理 | 中文分词、领域词典、大小写/全半角、停用词、同义词、缩写、错误码和数字归一化 | BM25 只能匹配进入倒排索引的词；分错或没展开的词，公式无法补救 |
| 分块 | chunk 大小、重叠、按标题/段落/表格切分、是否添加上下文前缀 | 直接改变 TF、文档长度、`avgdl`、IDF 统计和可召回粒度 |
| 字段设计 | `title`、`body`、标签、实体、错误码分字段索引并设置 boost，或使用 BM25F | 标题、正文和标识符的相关性贡献本来就不应完全相同 |
| 查询处理 | 查询改写、关键词抽取、同义词扩展、实体识别、must/should、短语和邻近匹配 | 解决用户表述与文档词面不一致的问题 |
| 候选召回 | BM25 `top_k`、元数据过滤、按场景分路召回 | 决定相关文档是否有机会进入后续阶段；`top_k` 不是 BM25 公式参数 |
| 混合检索 | BM25 + dense embedding，使用 RRF 或权重融合 | BM25 擅长专名、错误码和精确词，dense 擅长同义表达，两者互补 |
| 重排 | cross-encoder/LLM reranker、字段与业务特征 | 用更贵但更精细的模型重新判断较小候选集 |

### `k1` 和 `b` 的调参假设

- 若无意义的关键词堆叠或模板重复很多，降低 `k1`，让 TF 更快饱和，可能更稳。
- 若关键词重复确实代表文档主题集中，提高 `k1` 可能有益。
- 若所有 chunk 长度很接近，`b` 的影响通常较小。
- 若长 chunk 只是混入更多无关内容，提高 `b` 可能有益；若长 chunk 因结构完整而确实包含更多有效证据，过高的 `b` 可能误伤，应降低。

这些只是待验证假设，不能直接作为生产参数结论。

### 建议的验证顺序

1. 建立有相关性标注的代表性查询集，并按精确实体/错误码、普通关键词、同义表达、混合语言和多跳问题分组。
2. 固定分词、分块和查询处理，以默认 `k1`、`b` 建立 BM25 baseline。
3. 做小范围网格实验，例如 `k1 ∈ {0.8, 1.2, 1.6, 2.0}`、`b ∈ {0, 0.3, 0.6, 0.75, 1.0}`。
4. 第一阶段召回优先观察 Recall@k，同时记录 MRR、nDCG@k、P95 延迟和候选数量。
5. 再分别消融分词、分块、字段 boost、查询改写、dense 融合和 reranker；一次只改一类主要变量。
6. 在未参与调参的留出查询集上复测，避免针对少量问题过拟合。

在 RAG 第一阶段，首先要保证相关证据进入候选集，因此 Recall@k 通常比只看 BM25 分数或 Top-1 更重要；排序质量再由 MRR/nDCG 和重排阶段衡量。最终还需验证答案是否引用到正确证据，不能只看检索指标。

## 发散联想

- BM25 的“同义词失败”不是通过继续调 `k1` 或 `b` 就能修复的机制缺陷，应通过查询扩展、学习型稀疏检索、dense retrieval 或混合检索解决。
- 分块是 BM25 与 RAG 的交汇点：它既决定模型最终看到的证据粒度，也改变 BM25 的全部文档长度和词频统计。
- 当前官方实验 3-5 支持 `--k1`、`-b`、`--eval` 和 `--explain`；真正运行前应由用户先预测参数变化方向，再执行受控对照。
