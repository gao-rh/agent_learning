# 2026-08-27 第 3 章实验 3-11：双层用户记忆

## 原始问题

> 行，下一个实验吧。

## 用户理解

- 用户已确认实验 3-10 收口，进入实验 3-11。
- 对实验 3-11 的机制、三组对照和结果尚未形成结论。

## Codex 反馈

### 1. 实验要回答的问题

实验 3-11 不再提出一种全新的检索算法，而是验证两类记忆是否互补：

- **结构化记忆卡片**：保存当前状态、实体关系和新旧指令覆盖关系，适合快速确定“现在到底是什么”。
- **原始对话检索**：按需找回原话、原因和时间线，适合提供细节、证据和出处。

双层设计的核心不是把同一份信息存两遍，而是让上层卡片充当“当前状态索引”，让下层原始对话充当“可追溯证据库”。

### 2. 三组受控对照

```text
Plain
原始对话 -> 固定窗口分块 -> BM25 -> 回答

Contextual
原始对话 -> 固定窗口分块 -> 为每块生成定位前缀
        -> 对“前缀 + 原文”建 BM25 -> 回答

Dual Layer
与 Contextual 完全相同的检索结果
        + 实验 3-1 已生成的 Advanced JSON Cards
        -> 回答
```

脚本先在 Plain 索引上让 Agent 规划最多 3 条搜索词、每次取 Top-4，然后把同一组搜索词同时用于三条链路，避免某条链路因查询不同而占便宜。

### 3. 首个教学案例

案例 `layer2_12_contradictory_financial_instructions` 包含三段会话：

1. Patricia 最初设置：85,000 美元，10 月 1 日，编号 `WT-89045`。
2. James 修改为：100,000 美元，9 月 27 日，编号 `WT-89067`。
3. Patricia 最终修改为：95,000 美元，10 月 1 日，编号 `WT-89089`；旧编号自动失效。

最终问题是：

> 我女儿买房的汇款，现在是什么状态？

正确答案至少应确定：当前仅 `WT-89089` 有效、金额 95,000 美元、10 月 1 日汇往 Sarah 的 Chase 账户；此前 85,000/100,000 美元的版本都不是当前状态。

### 4. 当前已核对的历史结果边界

该案例中历史 Plain、Contextual 和 Dual Layer 三组都找到了最终会话并答对，因此它能展示双层记忆的职责，却不能证明双层一定优于单层。Dual Layer 的回答同时引用了结构化卡片和原始 chunk，但还包含账户号、路由号等用户并未询问的敏感细节，说明“信息更多”不等于“答案更好”。

历史全量报告声称三组总体通过率分别为 78.33%、86.67% 和 95.00%，但前序实验已发现自动 Judge 会出现假通过，所以这些聚合分数只能作为待人工审计的线索，不能直接当结论。

### 5. “双层”到底是哪两层

用户追问：

> 当前的状态与可检索的原始对话，这个是记忆吗？这个就是 JSON Card 是吗？

严格拆分如下：

| 层 | 当前实验的实际实现 | 更准确的名称 |
|---|---|---|
| 上层 | 实验 3-1 最终生成的 `Advanced JSON Cards` | 结构化长期记忆 / 当前状态索引 |
| 下层 | 原始历史对话按固定窗口分块，加上下文前缀后建立 BM25 索引 | 可检索会话历史 / 情节记忆 / 证据库 |

因此，“当前状态”这一层在本实验里**就是 Advanced JSON Card**，并不是另一套新格式。卡片通过 `status: Scheduled`、`status: Superseded`、新旧编号和实体关系等字段，帮助模型快速判断当前有效状态。

原始对话如果按“经过模型抽取、压缩后的长期记忆”这个狭义定义来讲，不算提炼后的记忆；它是历史记录。可是当系统把跨会话历史持久化、建立索引，并允许新会话按需检索时，它在 Agent 架构中通常属于 episodic memory（情节记忆）或 memory archive（记忆档案）。为了避免概念混乱，本次学习将其称为“可检索历史证据”，不直接称为“摘要记忆”。

### 6. 双层方案解决的矛盾

只使用 Advanced JSON Cards：读取快、当前状态清楚，但生成卡片时可能漏掉细节、写错事实、丢失原话和原因。

只使用原始对话检索：原始证据完整，但每次回答都需要在大量旧版本和互相冲突的指令中重新判断哪个版本最新；还可能因为 Top-K 限制没有召回决定性对话。

双层方案希望形成分工：

```text
Advanced JSON Card：先给出“现在是什么”
可检索原始对话：再说明“为什么、依据是什么”
```

当前代码的具体实现还有一个边界：它没有检索 JSON Card，而是把该测试案例最终的整份 Advanced JSON Card 直接放进 Dual Layer 的回答 Prompt；只有原始对话块经过 BM25 检索。因此，这个实验验证的是“给回答模型额外提供结构化卡片是否有帮助”，还不是一个完整的生产级双层记忆检索系统，也没有实现卡片与原始证据冲突时的自动仲裁规则。

### 7. 当前实验的准确执行顺序

用户将其概括为“JSON Card 加 BM25 搜索历史对话，双重获取信息”。方向正确，但严格来说不是两次搜索：

```text
用户问题
  ├─ 直接加载该案例最终的 Advanced JSON Card（不检索）
  └─ 用 BM25 检索历史对话块
          ↓
把卡片和召回的原始对话一起交给回答模型
          ↓
生成答案
```

实验设置三组消融：

1. `Plain`：只对原始对话块做 BM25。
2. `Contextual`：对“上下文前缀 + 原始对话块”做 BM25，但回答时提供原始对话证据。
3. `Dual Layer`：与 Contextual 使用相同的检索结果，再额外提供 Advanced JSON Card。

因此，`Contextual` 与 `Dual Layer` 之间的唯一核心变量是是否额外提供结构化卡片。实验要观察卡片是否能帮助解决跨会话状态更新、同名实体消歧、冲突指令和主动风险提示，而不是验证一种新的 BM25 算法。

### 8. 按原实验配置复算的报告结果

本地已有一轮完整的 60 案例历史运行：Layer 1/2/3 各 20 例；固定窗口每块 8 轮、重叠 2 轮；Agent 最多规划 3 次搜索、每次 Top-4。回答、搜索规划和前缀模型为 `doubao-seed-1-6-250615`，独立 Judge 为 `moonshot-v1-32k`。

本次学习没有重新运行这些案例，只读取和复算已有 evidence，并人工抽查 3 个差异案例；本次新增外部 API 调用为 0，新增 Kimi/豆包 API tokens 为 0。用户进一步确认：后续付费实验默认抽取约 10 个有代表性的案例，不再默认全量跑测试集；批量运行前必须先说明规模和预计消耗并获得明确确认。

自动 Judge 报告：

| 层级 | Plain | Contextual | Dual Layer |
|---|---:|---:|---:|
| Layer 1 | 19/20（95%） | 19/20（95%） | 19/20（95%） |
| Layer 2 | 15/20（75%） | 15/20（75%） | 20/20（100%） |
| Layer 3 | 13/20（65%） | 18/20（90%） | 18/20（90%） |
| 总计 | 47/60（78.33%） | 52/60（86.67%） | 57/60（95%） |

这轮共有 448 次 API 调用，输入 1,727,047 tokens、输出 505,121 tokens，总计 2,232,168 tokens，无调用错误。`validation` 的 `passed` 表示实验产物、调用回执和三组结果齐全，不表示 60 个问答全部正确。

按 Judge 的逐例模式统计：43 例三组都通过；4 例只有 Dual Layer 通过；7 例 Plain 失败而 Contextual、Dual 都通过；3 例 Plain、Dual 通过但 Contextual 失败；1 例只有 Contextual 通过；1 例 Plain、Contextual 通过但 Dual 失败；1 例三组都失败。因此加入前缀或卡片并不是单调增益。

### 9. 人工抽查

#### 卡片产生真实核心增益：多信用卡案例

问题要求比较 Chase Freedom Unlimited 与 Amex Gold 的机票奖励。Plain 和 Contextual 只召回或只掌握 Chase 的 1.5% 返现，未拿到 Amex 机票 3 倍积分，因而错误推荐 Chase。Dual Layer 从 Advanced JSON Card 补回 Amex 信息，正确推荐 Amex。这说明当 Top-K 原始对话漏掉另一个实体时，结构化卡片确实能补全全局状态。

但 Dual 答案同时声称 Amex 积分可转 United，并用“没有写手续费”推断无境外交易费；前者不在证据中且事实错误，后者论证也不成立。Moonshot Judge 仍给了满分，证明“Dual 通过”不等于答案没有幻觉。

#### 自动 Judge 明显不可靠：开店扩张案例

Gold 标准要求区分：面包业务可能 2025 年 2 月开始，但咖啡烘焙许可证尚未申请、需 8–12 周，因此烘焙业务可能推迟到 4–5 月；还应提醒三相电容量、18,000 美元签约款和总资金超过 300,000 美元。

Plain 与 Contextual 都只回答“最早 2 月开业”，没有做上述业务拆分，Judge 却判为通过；Dual 被卡片中的“目标 3 月开业”锚定而判失败，但也同样没有给出“2 月面包、4–5 月烘焙”的严格答案。因此这一例不能支持“Contextual 优于 Dual”，反而证明自动 Judge 的评分依据与 Gold 不一致。

#### Judge 自相矛盾：保修案例

Gold 明确说明信用卡延长保修只覆盖缺陷和故障，意外摔裂屏幕应由已过期的 120 天购买保护、AppleCare+ 或自费维修判断。Judge 却在部分判词中声称延长保修包含意外损坏，并对表达相近的答案给出不同通过结果。这进一步说明 95% 只能称为“该 Judge 下的报告通过率”。

### 10. 当前可负责的实验结论

1. 报告分数呈现出合理趋势：Contextual 前缀主要改善需要跨会话综合的 Layer 3，Advanced JSON Card 主要补强多实体和状态冲突较多的 Layer 2。
2. 双层方案确实存在有效案例：当 BM25 Top-K 漏掉某张信用卡等实体时，卡片能补回全局状态。
3. 双层方案也会退化：卡片中的旧目标、错误状态或额外细节可能锚定回答模型；当前脚本没有卡片与原始证据的冲突仲裁。
4. 不能把 `95%` 当作真实准确率。至少需要重新审核差异案例，并对最终答案做原子事实核验、引用一致性检查和幻觉检查。

## 发散联想

- 结构化卡片类似数据库中的“当前状态表”，原始对话类似不可变的“事件日志”。
- 双层记忆与事件溯源思想相近：平时读当前状态，出现争议或需要解释时回查历史事件。
- 如果卡片更新错误，双层系统也不能盲信卡片；应回到原始证据核验，并保留来源和更新时间。
