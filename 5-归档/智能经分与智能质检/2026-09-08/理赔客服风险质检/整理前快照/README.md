# 理赔客服风险质检

> 状态：已发现从早期探索到日常自动化的候选实现资产，正在核对真实生产状态、效果与个人贡献。不得在验收前包装为成熟质检系统。

## 项目定位

- 面向理赔客服通话的风险筛查，识别疑似辱骂、明显冲突等可能导致客诉的高风险通话。
- 当前链路为：已有 ASR 文本 → 关键词预筛 → 内部模型初审 → 规则与 AI 脱敏 → 外部模型复审 → 人工审核。
- 用户负责风险检测链路，但不负责平台已有的 ASR 能力。

## 当前证据边界

- 客服通话量约数千通/天。
- 当前准确率约 30%，召回率无法可靠计算，日均命中约 1–2 个疑似 case。
- 尚无可靠的客诉改善或完整人工抽检数据。
- 可用于说明隐私边界、分层筛选和人工复核，不可表述为成熟业务成果。
- 新增的 C01 历史材料记录了“情绪指数探索 → 规则质检线下调试 → 评测与推广准备”，但当时明确尚未线上应用；它与当前两级模型链路的演进关系、后续计划完成情况和指标口径仍待核对。
- 新增的 C02 压缩包静态展示了数据查询、模型推理、二次复核、报告、通知以及锁 / 心跳 / 幂等 / 重试等资产，并有约 1.5 千条普通任务、约 6.7 千条专项任务的自记录候选；尚缺调度后台、真实日志和独立验收。
- C02 含疑似 API Key 和其他内部敏感信息；原包未复制、代码未执行。若密钥仍有效，必须先在公司侧轮换和清理。
