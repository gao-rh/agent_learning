# 智能经分分析 Skill 设计评审 v0.3

> 状态：根据用户最新口述形成。指标按专题路由、完整报告与局部一层分析的区别已经用户确认；完整专题数量、名称和工程字段仍待补充。

## 一、核心结论

项目的分析 Skill 按业务专题组织。用户可能对不同指标使用完全相同的问法，系统不能仅根据“怎么样”“为什么变化”“异动”等字面表达选择一个通用分析 Skill，而要先确认标准指标，再根据指标所属业务专题调用对应的分析方法。

```text
用户问题
→ 确认标准指标
→ 查询指标所属专题
→ 命中对应的专题分析 Skill
→ 判断用户需要完整报告还是局部分析
```

## 二、已确认示例

| 用户表达 | 核心指标 | 专题路由 | 专题关注点 |
| --- | --- | --- | --- |
| 某渗透率今天怎么样 | 渗透率类指标 | 异动分析专题 | 今日表现及变化原因 |
| 商户活跃用户数今天怎么样 | 商户类指标 | 商户分析专题 | 商户专题的结构与变化 |
| 保费为什么今天变化这么多 | 保费类指标 | 保费分析专题 | 目标、达成率及驱动因素 |
| 生成今天的渠道分析报告 | 渠道指标 / 完整报告意图 | 渠道专题分析 | 从头到尾完成渠道分析并生成报告 |

这些问题的句式相近，但不能命中同一套通用异动流程。

## 三、路由实际需要判断三个维度

### 3.1 标准指标身份

先确定用户所说的指标究竟对应哪个标准指标。指标身份错误，后续专题和分析方法都会错误。

### 3.2 指标所属专题

通过受控的“指标 → 专题”映射找到对应分析 Skill。该映射应来自指标元数据、专题配置或业务规则，不能只让模型根据指标名字自由猜测。

### 3.3 用户要求的分析范围

进入专题后，再决定执行深度：

- 用户明确要求完整专题报告：执行该专题的完整长链路；
- 用户只问具体指标或具体维度的情况 / 原因：执行该专题当前问题的一层分析；
- 用户表达不清：一次性澄清是要看数、分析当前变化，还是生成完整报告。

## 四、推荐的专题 Skill 结构

每个专题 Skill 至少应包含：

| 内容 | 作用 |
| --- | --- |
| 支持指标清单 | 决定哪些标准指标进入该专题 |
| 指标与业务目标 | 说明专题真正关心的问题，例如保费需要结合目标 |
| 默认比较方式 | 今日、昨日、同比、环比、目标值或其他基准 |
| 一层分析规则 | 用户只问具体问题时，本次分析哪些直接因素 |
| 完整分析链路 | 用户要求完整报告时，从哪个节点开始、怎样逐层推进 |
| 可用维度和公式 | 定义下拆、贡献、漏斗等方法的合法输入 |
| 继续与停止条件 | 防止局部问题被自动扩展成多层长分析 |
| 输出模板 | 区分局部回答与完整专题报告 |
| 数据不足处理 | 何时澄清、拒答或说明无法归因 |

## 五、同一专题的两种执行深度

```text
对应专题分析 Skill
├─ 局部模式
│   ├─ 继承用户给出的指标、维度和时间
│   ├─ 只分析本专题规定的一层直接原因
│   └─ 输出并停止，可建议下一步
└─ 完整报告模式
    ├─ 从专题起点开始
    ├─ 按专题规则执行多层分析
    └─ 生成完整报告
```

因此，“完整报告”和“一层分析”不是两个跨专题的通用 Skill，而是专题分析 Skill 的两种任务深度，或者由专题路由后选择的两条内部路径。

## 六、通用分析方法的正确位置

趋势、公式拆解、维度贡献、漏斗和目标 Gap 可以作为专题 Skill 共用的计算方法、reference 或脚本，但不作为用户请求的第一层分类。

例如：

- 保费专题使用目标 Gap、公式因子贡献和必要的维度下拆；
- 渗透率异动专题使用趋势确认、分子分母拆解和维度贡献；
- 商户专题使用自己的商户指标关系、结构和变化方法；
- 渠道专题使用渠道层级贡献、漏斗和 source 定位。

专题决定“为什么分析、先看什么以及怎样解释”，通用方法解决“具体怎样计算”。

## 七、推荐实现

```text
分析路由器
├─ 标准指标确认
├─ 指标专题映射
└─ 任务深度判断
    ↓
专题分析 Skill
├─ 专题指标与业务目标
├─ 局部一层分析路径
├─ 完整报告路径
└─ 需要调用的通用计算方法
    ↓
共享取数 Agent / Tool Gateway
├─ 指标、维度、时间标准化
├─ 数据查询与完整性校验
└─ 返回实际指标、来源和结果
```

推荐将“指标 → 专题”的映射做成可维护、可校验的结构化配置，并让取数结果继续保留实际标准指标身份。否则同一句问法很容易因为模型自由理解而进入错误专题。

## 八、需要补齐的唯一分类冲突

此前用户确认的四类常规经营分析为：

1. 保费；
2. 渗透率；
3. 渠道归因；
4. 用户留存归因。

本次新增明确提到“商户分析专题”。当前尚不能判断它是第五类、替代其中一类，还是与用户留存存在包含关系。

在该问题确认前，v0.3 只确认路由原则和三个示例专题，不给出最终 Skill 数量。

## 九、当前可用于面试的表达

> 我们的分析 Skill 不是按用户是否说了“异动”来路由，而是先把用户表达映射到标准指标，再根据指标所属的业务专题选择分析方法。同样一句“这个指标今天怎么样”，问渗透率会进入渗透率异动分析，问商户活跃指标会进入商户分析，问保费则会结合目标和达成情况进入保费分析。进入专题后还会区分任务深度：明确要完整报告就执行专题长链路，只问具体指标原因则只分析当前层的一层因素，不默认无限下钻。
