# 智能经营分析：记忆模块设计

## 目标

记忆模块主要解决四类问题：

- 保存用户关键信息；
- 保存用户偏好；
- 支持多会话连续性；
- 复用历史分析经验，并在用户纠错后更新错误记忆。

## 整体结构

```text
记忆模块
├── 用户信息
├── 用户偏好
├── 用户长期 Memory
│   ├── 完整 Memory：内部按 Task 专题组织
│   ├── Memory Summary：完整 Memory 的压缩版本
│   └── 分析经验：记录在相关 Task 中
└── 会话记录
    ├── 会话详情
    └── 会话摘要
```

用户信息和用户偏好是两个独立对象，不混入完整 Memory 或 Memory Summary。分析经验属于用户长期 Memory。

整体设计大体参考 Codex 的记忆机制：保留完整会话记录，在对话结束或系统闲时提取和整理长期记忆，形成按 Task 组织的完整 Memory 及其 Memory Summary，后续再使用这些记忆。

### 记忆表示

长期 Memory 不增加 JSON Card 或 Advanced JSON Card 层，继续采用按 Task 专题组织的可读文本：

- 完整 Memory 保存 Task 的过程、进度、数据、可视化、报告链接和分析经验；
- Memory Summary 对完整 Memory 进行压缩；
- 后续通过 Summary 和相关 Task 文本使用记忆，不依赖 Card ID 或 Card CRUD；
- JSON Cards 与 Advanced JSON Cards 只作为第 3 章实验中的记忆表示对照，不进入经分项目架构。

选择可读文本而不增加 Card，可以避免额外的 schema 设计、字段迁移和卡片更新复杂度。第 3 章对照实验也说明，结构更复杂只能约束输出形状，不能保证 Writer 不漏记或不发生语义错绑。

## 放什么

### 用户信息

保存与用户后续取数、分析有关的关键信息。

### 用户偏好

重点包括：

- 数据呈现偏好；
- 可视化偏好；
- 分析方向偏好。

### 多会话连续性

按 Task 专题记录用户做过的事情，包括：

- 围绕什么专题进行分析；
- 已经做过哪些事情；
- 做到了什么程度。

Task 不是用户对话过程中显式感知或主动续接的运行状态。系统只在写入、整理记忆时，判断一段分析应该归入已有 Task 还是形成新的 Task。

判断发生时，相关对话通常已经做得比较完整，主题、过程和产物都已经出现，因此比较容易归类。普通的漏归或错归通常不会影响未来使用，除非发生严重的错误归类。

### 历史分析经验

分析经验跟随相关 Task 保存，主要包括：

- 历史分析过什么主题；
- 使用了什么数据；
- 做了什么可视化；
- 报告或其他产物的链接；
- 最终效果怎么样。

## 怎么放

### 会话内写入

存在两种触发方式：

- 用户明确指定需要记住某项信息；
- AI 判断某项信息值得保存，调用工具写入长期记忆。

记忆写入对用户无感。用户在对话中不会看到 Task 归类、摘要生成或长期记忆更新等内部过程。

如果用户明确指出“之前说的某项信息是错的”，系统需要找到并修改对应记忆。

### 闲时整理

系统在闲时拉取活跃用户的完整对话记录，再由 AI 整理需要长期保存的内容，包括：

- 用户信息；
- 用户偏好；
- 按 Task 组织的多会话过程；
- 历史分析经验。

### Task 组织

每个用户维护一份完整 Memory 和一份 Memory Summary：

- 完整 Memory 内部按 Task 专题记录详细内容；
- Memory Summary 是完整 Memory 的压缩版本；
- 用户信息和用户偏好单独维护，不属于这两个文档；
- 分析经验记录在完整 Memory 的相关 Task 中。

## 放哪里

记忆保存在两个位置：

- 数据库；
- Wiki。

数据库和 Wiki 分别保存哪些对象，以及两者之间如何同步，后续继续讨论。

## 记忆整理和压缩机制

### 第一层：重要性评分筛选

重要性评分综合四个因素：

- 访问频率：经常被检索的记忆更重要；
- 时间衰减：越久远的记忆越容易被遗忘；
- 情感强度：作为低权重的辅助参考。用户强烈表达不满或强烈提出要求时，说明相关内容可能存在问题或对用户比较重要，但它不是决定记忆重要性的关键因素；
- 信息独特性：重复信息的重要性降低。

低于阈值的记忆被标记为可压缩或可删除。

例如，一条被访问 5 次、创建于 3 天前且无重复记录的记忆，会获得较高的重要性得分；强情感标记只能在此基础上提供辅助信号。一条仅被访问 1 次、创建于 90 天前且与其他 3 条记忆高度重复的记忆，可能低于压缩阈值，是否带有情感标记不会单独决定结果。

### 第二层：聚类和代表性摘要

系统将相似记忆分组，并为每组生成代表性摘要。

例如，多次天气对话可以压缩为“用户经常询问天气，特别关心降雨”。原始详细记忆可以归档到二级存储。

### 第三层：抽象和泛化

系统从具体情景记忆中提取一般性规律，把情景记忆转化为语义记忆或程序记忆。

例如，从多次购物对话中学习到“用户偏好性价比高的产品，重视用户评价”。

## 后续讨论

后续仍需依次讨论：

1. 访问频率的计数口径及各项评分因素的权重；
2. 数据库与 Wiki 的职责分工；
3. 用户信息、用户偏好和 Memory Summary 的读取与注入策略；
4. 记忆冲突、纠错、过期和删除机制。

上述内容先在对话中确定方向，确认后再写入设计。
