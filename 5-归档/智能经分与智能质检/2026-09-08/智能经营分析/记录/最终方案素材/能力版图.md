1. 保费；
2. 渗透率；

## 2026-09-07｜本地 Skill 与分析能力拆解复原

> 状态：业务分析方向沿用用户已确认名称；底层分析能力是 Codex 根据本地原始资料反向归纳的候选拆解，尚未等同于公司内原 Skill 的准确名称和数量。

### 一、业务分析方向：四类

| 业务分析方向 | 本地材料情况 | 当前判断 |
| --- | --- | --- |
| 保费分析 | 有完整的 `P = A × R × Q`、Shapley 因子归因和目标 Gap 拆解材料 | 方法较完整 |
| 渗透率分析 | 有指标分层、分子分母拆解、异动五步法和代表性背离案例 | 方法较完整，但分散在多份资料中 |
| 渠道归因 | 有“全渠道 → 一级渠道 → 二级渠道 → 漏斗 → source”的完整五步法 | 方法最完整 |
| 用户留存归因 | 已确认名称，但当前本地原始材料未找到完整的方法、输入输出和案例 | 只有方向名称，仍缺细节 |

### 二、可复用的底层分析能力：建议拆为五类

#### 1. 趋势与异动确认

- 统一基期和当期；
- 计算同比、环比、绝对变化和 pp 变化；
- 判断是否真实异动、方向和严重程度；
- 处理周期、趋势、周末效应和动态阈值。

这是所有归因分析的入口，不等同于完整异动归因。

#### 2. 公式链路拆解

- 将结果指标拆为存在明确公式关系的驱动因子；
- 例如保费 `P = 单均保费 A × 订单渗透率 R × 订单基数 Q`；
- 渗透率还可以继续拆为可投保订单占比和可投保订单渗透率；
- 使用 Shapley 等方法量化每个因子对总变化的贡献。

它回答“是哪个组成因子导致指标变化”。

#### 3. 维度下拆与贡献归因

- 按新老商、商户类型、品类、配送方式、一级渠道、二级渠道、source 等维度下钻；
- 计算维度值自身变化、结构变化和对总体变化的贡献；
- 按贡献度排序，选择 Top N 继续分析；
- 支持单维度、交叉维度和层级维度下拆。

它回答“变化集中在哪类对象或哪个渠道”。原复盘中明确口述的“下拆分析”主要对应这一类。

#### 4. 漏斗分析

- 根据业务转化链定义各环节的量和转化率；
- 比较基期与当期，定位与最终结果同方向恶化的环节；
- 在同方向环节中按影响大小排序；
- 继续下钻到具体渠道、source 或业务对象。

它回答“问题发生在转化链的哪个环节”。原复盘中明确口述的“漏斗分析”对应这一类。

#### 5. 目标 Gap 拆解

- 将实际值与目标值进行比较；
- 计算达成率与 Gap；
- 将 Gap 分摊到公式因子或业务维度；
- 区分拉动项、拖累项和贡献百分点。

它回答“为什么没有达标或为什么超额完成”。本地保费材料已有完整示例。

### 三、哪些不建议单独算作底层分析能力

| 内容 | 归属判断 |
| --- | --- |
| source 级定位 | 是维度下拆的更细层级，不必单独成为一种分析方法 |
| 运营建议 | 是分析后的解释和行动输出，不是独立分析方法 |
| 图表、报告 | 是输出与交付能力，不是分析方法 |
| WBR 周报 | 是常规经营分析的报告型 Skill / 交付场景，不是底层分析算法 |
| 异动监控 | 是触发和检测能力；触发后可调用趋势、公式、维度和漏斗分析 |
| 指标口径查询、查数 | 是数据咨询和取数能力，不是经营分析方法 |

### 四、本地能够明确识别的 Skill / 方法载体

| 本地材料 | 明确包含的内容 | 应怎样归类 |
| --- | --- | --- |
| 场景险智能经分 Skill V13 / V16 | 查口径、查数、异动分析报告；早期材料另列维度下拆 | 综合型业务 Skill |
| 场景险 WBR 报表 Skill | BI 取数、数据规范化、绘图、填充和文档校验 | 报告交付型 Skill |
| 保费链路分析逻辑 | 公式拆解、Shapley 归因、目标 Gap | 保费专题方法，不足以证明它独立发布为一个 Skill |
| 流量渠道归因分析思路 | 渠道层级下拆、Shapley 贡献、漏斗和 source 定位 | 渠道专题方法，不足以证明它独立发布为一个 Skill |
| 指标异动检测策略 | 同星期对比、动态阈值、STL、集成投票等 | 异动检测方案，不是完整经营分析 Skill |

### 五、当前建议采用的表达

如果面试官问“你把分析能力拆成了哪些”，可暂时回答：

> 我们没有继续按保费、渗透率、渠道等专题分别复制一套大流程，而是把其中共用的方法拆成五类基础分析能力：趋势与异动确认、公式链路拆解、维度下拆与贡献归因、漏斗分析、目标 Gap 拆解。Agent 根据用户当前的问题位置选择入口并组合执行。source 定位是维度下拆的更细层级，图表和报告属于输出层，不再重复建设成分析方法。

这段是根据本地材料复原出的候选表达；其中原复盘能够明确证明用户曾口述“下拆分析”和“漏斗分析”，另外三类来自现有保费、渗透率、渠道和异动材料的共同结构，仍需用户确认是否符合公司内原始拆法。

## 2026-09-07｜用户校正：按任务范围路由，而不是默认多层组合

用户确认实际设计应当区分两种完全不同的请求：

### 1. 完整专题分析

当用户明确要求“生成今天的渠道分析报告”时，才调用完整、较长的渠道专题分析 Skill，从整体情况开始，按专题方法从头分析到尾并生成完整报告。

### 2. 局部指标异动分析

当用户问“为什么某个维度下的某个指标发生变化”时，应调用通用的指标异动分析 Skill。它只围绕用户已经指定的当前分析节点做一层分析，不默认继续拆很多层，也不重新从全局开始执行完整专题。

例如，用户已经指出某个一级渠道的指标下降，指标异动分析只分析该一级渠道当前指标及其下一层影响因素；如需继续进入二级渠道、漏斗或 source，应由用户继续追问，或者由系统给出下一步建议后再执行。

### 3. 对前一版候选拆解的影响

- “趋势、公式、维度、漏斗、目标 Gap”仍可以作为内部分析方法或计算能力，但不代表普通用户问题会默认串行调用全部方法；
- 用户当前问题的位置和要求的交付范围，是选择“完整专题 Skill”还是“一层指标异动 Skill”的主要依据；
- 完整专题 Skill 可以内部包含多层固定或半固定分析链路；
- 指标异动分析 Skill 的核心价值是就地分析、只下一层、快速回答，避免答非所问和无效查询；
- 图表、报告和运营建议仍属于输出，WBR 等固定报告仍属于独立交付场景。

### 4. 当前可确认的路由

```text
用户请求经营分析
├─ 明确要求完整专题报告
│   └─ 对应专题分析 Skill
│       └─ 从专题起点开始，执行完整链路并生成报告
└─ 询问某维度下某指标为什么变化
    └─ 指标异动分析 Skill
        └─ 只分析当前节点的一层原因
            └─ 需要继续时再追问或再次调用
```

此前“由 Agent 默认组合多种方法持续下钻”的说法被本次用户确认覆盖，不再作为项目实际设计。

## 2026-09-07｜用户再次校正：指标所属专题决定分析 Skill

用户进一步确认，项目的分析能力是按业务专题组织和路由的，不存在一个面向所有指标的通用“指标异动分析 Skill”。

不同专题的用户问法可能完全一样，例如都是“某指标今天怎么样”或“某指标为什么变化这么多”，但实际命中的分析方法由指标所属专题决定：

| 用户问题中的指标 | 应命中的专题分析 | 已确认的关注重点 |
| --- | --- | --- |
| 渗透率类指标 | 异动分析专题 | 判断当日变化，并按该专题的方法分析 |
| 商户活跃用户数等商户类指标 | 商户分析专题 | 按商户专题的方法分析，而不是进入通用异动分析 |
| 保费类指标 | 保费分析专题 | 需要结合目标和达成情况分析 |
| 渠道完整报告请求 | 渠道专题分析 | 从专题起点执行完整分析链路并形成报告 |

因此正确路由应拆为三步：

```text
用户问题
→ 识别并确认标准指标
→ 根据“指标 → 业务专题”映射选择专题分析 Skill
→ 根据用户要求决定执行深度
   ├─ 完整专题报告：执行专题完整链路
   └─ 具体指标问题：只执行该专题针对当前问题的一层分析
```

这里“问法”主要用于判断用户要查数、看现状、问原因还是要完整报告；它不能单独决定分析 Skill。真正的专题路由依据是标准指标及其所属专题。

### 对上一轮记录的覆盖

- “局部指标变化统一进入通用指标异动分析 Skill”的说法被本次用户校正覆盖；
- “完整专题与局部一层分析”的深度区分继续有效，但它发生在专题 Skill 内部或专题路由之后；
- 趋势、公式、维度、漏斗和 Gap 仍属于专题内部可使用的方法，不是顶层路由；
- 保费分析需要优先结合目标与达成情况，不能仅按普通同比 / 环比变化分析。

### 新出现的分类冲突，暂不推断

2026-08-31 用户曾确认四类常规经营分析为“保费、渗透率、渠道归因、用户留存归因”；本次又明确出现“商户分析专题”。当前材料无法判断：

1. 商户分析是第五个独立专题；
2. 商户分析替代此前某一分类；
3. 商户分析是用户留存归因或其他专题的上位 / 下位概念。

在用户进一步确认前，两个版本同时保留，不修改四类正式名称，也不把商户分析强行并入其中。
