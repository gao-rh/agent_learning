- 分类：技术架构与核心机制。
- 性质：经讨论确认的理想目标架构绘图规格，不代表全部模块已在生产实现或验证。
- 当前作用：技术架构的候选主材料，用于检查主链路、Agent / Skill / Tool 边界和横切治理缺口。

### 已明确的高层架构决定

1. 主骨架采用“受控编排器 + 边界内 Agent 自主判断”。
2. 主 Agent 负责对话、意图、通用澄清、高层计划、上下文组装和最终回复。
3. 口径咨询由主 Agent 使用受控只读元数据工具完成，不新建咨询 Agent。
4. 取数 Agent 是直接取数和分析内部取数的共享可信执行能力。
5. 常规经营分析与开放式经营分析共用分析 Agent，通过不同 Skill、计划模板和报告模板区分。
6. 主 Agent 组装完整的结构化分析任务，分析 Agent 负责详细计划、取数拆分、数据依据解释、迭代下钻、图表和报告。
7. 通用兜底 Agent 只做能力探索、澄清和重路由，不绕过专业 Agent 访问底层数据工具。

### 2026-08-30 首轮候选缺口（2026-08-31 后不再作为必备前置）

1. **生产现状映射**：图中每个 Agent、Tool、Skill、状态节点和校验节点，需分别标注“原项目已实现 / 平台提供 / 迁移后提供 / 理想补充 / 尚未验证”。
2. **真实端到端调用链**：尚缺一个具体请求从用户输入到取数、分析、报告和回复的生产级节点与数据传递记录。
3. **结构化任务和结果对象**：取数任务、分析任务、带来源的取数结果和分析结果目前是架构语义表达，字段、版本和原生产对应物尚未核对；不再使用“证据契约”作为项目术语。
4. **受控编排细节**：平台实际控制的状态、路由、准入、超时、重试上限、预算、checkpoint 和停止条件尚未逐项核对。
5. **工具和数据底座**：实际 Tool Gateway、日期工具、指标工具、复合计算、数据接口、数仓、文件结果和缓存之间的具体边界尚未画清。
6. **上下文、记忆与知识注入**：哪些是已实现的写入、召回和冲突处理，哪些是理想分层，还需与已有记忆复盘对齐。
7. **校验与治理的实现状态**：指标身份、业务适用性、数据完整性、报告一致性、权限、脱敏、Trace、审计、人工复核等节点中，目前有一部分是目标设计而不是已验证生产能力。
8. **非会话入口与交付**：定时任务、主动提醒、通知、补跑和高影响报告审核链路在拓扑中仍是可选扩展。
