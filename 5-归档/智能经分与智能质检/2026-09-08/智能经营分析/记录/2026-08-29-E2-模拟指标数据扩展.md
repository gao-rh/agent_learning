# 2026-08-29 E2：模拟指标数据扩展

## 原始问题

用户指出当前返回似乎是固定值，希望为澄清与查询 Graph 增加一个月的假数据，覆盖准时宝保费收入、
取消险保费收入、安心吃保费收入、订单渗透率和客户渗透率，并支持商家和渠道维度。

## 用户理解

- 当前实验中的 Tool 返回来自本地模拟数据，不是真实业务数据。
- 用户希望扩大数据覆盖面，使后续澄清、路由和分析实验不再只能使用一两个固定案例。
- 用户原话先说“三个指标”，但随后实际列出了五个指标；本次实现按列出的五个指标处理。
- 用户原话使用“准时宝”，此前记录中的标准指标名是“准时保保费收入”。本次不改标准名，暂将
  “准时宝”作为口语别名兼容；这项命名假设仍可由用户后续纠正。
- 用户实际运行后发现：回复“三种 保费”仍被原样追问标准指标，说明当前状态只支持单个
  `confirmed_metric_id`，且确定性解析器没有理解集合式多指标表达。
- 用户明确反对继续增加“三种保费”等固定短语规则；用户认为这类自由表达应由大模型理解，代码不应
  枚举所有可能说法。

## Codex 反馈

本次将“三个维度”解释为三种查询范围：整体汇总、商家维度、渠道维度。数据采用固定公式生成，
而不是每次运行随机生成，原因是 LangGraph Checkpoint 回放、自动化测试和面试演示需要同一输入得到
稳定结果。

数据范围为 2026-08-01 至 2026-08-31：

| 类型 | 标准指标 | 单位 |
| --- | --- | --- |
| 金额 | 准时保保费收入 | 元 |
| 金额 | 取消险保费收入 | 元 |
| 金额 | 安心吃保费收入 | 元 |
| 比率 | 订单渗透率 | % |
| 比率 | 客户渗透率 | % |

商家维度包含连锁商家、中小商家、新入驻商家；渠道维度包含 App、API。金额指标的整体值与两种
拆分分别守恒。比例指标的维度值是各自范围内的渗透率，不能相加得到整体值。

当前只扩展“一个月的每日数据”，查询 Tool 仍接收一个日期。月累计、月平均、趋势序列和任意日期范围
聚合尚未实现，不能因为底层有 31 天数据就表述为已经支持月度分析。

针对多指标澄清问题，改为以下职责分工：

```text
用户自由回复
→ Kimi 结构化解释单选、多选、全选、局部修改和局部否定
→ Python 校验指标 ID、维度和值是否在允许目录内
→ State 保存 confirmed_metric_ids
→ 对每个指标执行受控 Tool
→ Kimi 汇总多个工具结果
```

这不是让模型直接决定可查询内容：模型负责语义映射，指标目录仍是执行边界。简单的“确认/1”保留本地
快速路径；只有需要语义理解的回复才新增一次 Kimi 调用。

## 发散联想

- 金额指标可以求和，比例指标通常需要分子、分母重新聚合，不能平均各天百分比或相加各维度百分比。
- 合成数据也需要业务不变量；否则 Agent 即使正确调用 Tool，也可能生成内部自相矛盾的分析结论。
- 指标目录负责标准名、别名、口径和单位，数据层负责日期与维度值；这两层分开后更容易增加指标。
- 可复现假数据比运行时随机数据更适合演示 Checkpoint、Trace、回放和评测。
