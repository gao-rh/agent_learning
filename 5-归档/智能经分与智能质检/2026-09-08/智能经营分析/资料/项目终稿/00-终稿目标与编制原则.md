# 智能经营分析项目终稿：目标与编制原则

> 状态：终稿目标与核心约束已由用户确认；具体组织形式仍为 AI 草案，待确认后再据此重写 v2.0。

## 一、终稿的核心目的（已确认）

这份终稿首先是一份面向未来面试的项目知识底稿。

它要帮助用户完整梳理智能经营分析项目，并把原本分散在记忆、复盘记录、技术资料、评估文档和案例中的内容，变成一份可复习、可检索、可直接用于回答问题的项目手册。

最终希望达到：未来面试中遇到与该项目相关的常见问题时，用户能够从终稿中找到答案；即使部分细节已经遗忘，也能通过终稿恢复项目全貌、关键机制、事实依据和回答思路。

它不是单纯为了“介绍项目”，也不是只服务于一段简历描述，而是把“准备好这个项目”具象化为一份覆盖面广、质量高、能够支持常见面试问题及后续追问的完整材料。

## 二、终稿的核心约束（已确认）

1. **覆盖要足够全面**：常见项目问题、技术问题、业务问题、评估问题、成果问题和个人贡献问题都应有答案。
2. **内容要能实际回答面试问题**：不能只有名词、目录和零散事实，需要形成可以直接复述的核心回答。
3. **细节要能够找回**：对于容易遗忘的架构、决策、案例、指标口径、问题与解决方案，应保留必要细节和依据。
4. **篇幅不能无限膨胀**：不能因为追求完整而变成用户没有耐心阅读和复习的超长资料库。
5. **高质量优先于表面完整**：不确定的事实不得补写；已经被用户否定的旧表述不得继续沿用；正文应突出面试中真正有用的内容。

## 三、终稿的验收标准（根据已确认目的提炼）

| 验收维度 | 判断标准 |
|---|---|
| 问题覆盖 | 常见项目面试问题能够在终稿中定位到对应内容 |
| 回答完整 | 每个核心问题至少包含结论、关键依据和必要的追问展开 |
| 快速检索 | 用户忘记某项内容时，能够通过目录、问题标题或关键词快速找回 |
| 复习成本 | 可以先快速回顾项目主线，再按需进入技术和案例细节，不要求每次从头读完 |
| 事实可靠 | 用户确认事实、AI 提炼、待确认项和历史旧说法保持清晰边界 |

## 四、需要解决的核心矛盾

终稿必须同时满足两件事：

- 覆盖面足够广，能够支撑常见问题和深入追问；
- 主体足够紧凑，用户愿意阅读、复习并在面试前快速回顾。

因此，后续不应继续把所有材料等篇幅地堆进一篇线性长文，而应通过信息分层解决：高频问题给出完整但紧凑的核心回答，深入机制和低频细节按需展开，原始材料继续留在来源层。

## 五、终稿组织形式（AI 草案，待确认）

### 方案 A：传统完整项目报告

按背景、能力、架构、难点、评估、成果顺序连续叙述。

- 优点：项目故事完整，适合从头阅读。
- 缺点：容易再次变成长文；面试时按问题查找答案不够快。

### 方案 B：纯面试问答库

完全按照面试问题组织，每个问题单独回答。

- 优点：检索和复习效率最高，最贴近真实面试。
- 缺点：项目整体主线容易被切碎，相似问题之间可能重复。

### 方案 C：分层式面试项目手册（AI 推荐）

用“一页项目总览 + 按面试问题组织的完整正文 + 少量深入索引”组成终稿：

1. **快速回顾层**：项目一句话定位、为什么做、用户与场景、核心能力、总体架构、难点、成果和个人贡献；
2. **核心问答层**：以面试问题作为章节标题，每章先给可直接复述的核心回答，再补充依据、机制和常见追问；
3. **细节找回层**：只保存架构细节、完整案例、评估口径和失败复盘等容易遗忘但不需要每次通读的内容；
4. **来源与缺口层**：保留证据链接和待确认项，不让它们打断正文叙事。

该方案试图同时满足“全”和“短”：主文档优先覆盖高频问题，细节通过分层和链接找回，而不是在每一处重复展开。
