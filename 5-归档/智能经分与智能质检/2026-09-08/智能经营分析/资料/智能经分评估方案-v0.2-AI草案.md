# 智能经分评估方案 v0.2

> 状态：基于用户口述历史事实形成的 AI 草案。测试方法已形成首个完整版本；带“约、接近、以上、待核实”的题量、模型名和结果，仍需原始题集或运行报告佐证。

## 1. 评估目标与总体结构

评估智能经分 Agent 是否能够正确理解任务、获得可信数据、完成咨询或分析，并可靠交付最终结果；失败时能够通过 Case 和 Trace 定位原因。

### 顶层指标

1. **数据准确率**：取数任务最终返回正确数据结果的比例。
2. **端到端任务成功率**：所有类型任务最终解决用户问题的比例。

统一采用整题 Pass / Fail：

```text
某类任务准确率或成功率
= 该类通过任务数 / 该类有效运行任务总数
```

有唯一标准答案时称“准确率”；存在多条合理路径、需要按 Rubric 判断时称“任务成功率”。失败阶段与原因用于诊断，不参与加权总分。

### 能力级指标

| 能力 | 指标或处理方式 |
| --- | --- |
| 意图识别 | 不作为重点指标，仅保留边界回归和失败标签 |
| 取数澄清 | 澄清成功率 |
| 业务知识与指标口径咨询 | 咨询回答准确率 |
| 可信取数 | 数据准确率 |
| 数据分析 | 分析任务成功率，按固定 / 开放分析分组 |
| 报告与可视化 | 并入分析或端到端任务判定 |
| 跨会话记忆 | 跨会话连续成功率 |
| 定时任务 | 定时交付成功率 |
| 轻度串并行与内部编排 | 不单列指标；违反硬依赖或执行失控时记录失败原因 |

## 2. 历史评测阶段

```text
开发初期：人工小题集 -> 能力隔离测试 -> 快速定位与调试
系统成型后：端到端基准 -> 整题 Pass / Fail -> 失败 Case / Trace 回溯
```

开发初期分别测试澄清、业务知识、指标口径等局部能力。后期主要看数据准确率和端到端任务成功率，失败后逐 Case 分析，不再持续关注所有局部指标。

## 3. 通用评测规则

每项能力应保留：题目与参考答案、数据 / 知识 / 工具版本、运行配置、Agent 和 Judge 版本、最终输出、Pass / Fail、失败原因及必要 Trace。

历史主要使用 LLM-as-a-Judge：Judge 比较最终结果与人工参考答案或 Rubric，输出 Pass / Fail。正式回归应固定 Judge 模型与 Prompt；历史具体版本仍待核实。

## 4. 能力评测卡

### 4.1 可信取数

**任务集**

- 200 条人工确认标准结果的题目；
- 冻结查询日期和版本；
- 覆盖简单取数、当期 / 基期比较、复杂维度、比率型指标、公式型复杂指标及主要业务数据类别；
- 分为信息完整的单轮取数和由便宜模型扮演用户的澄清后取数。

**运行**

```text
固定题目与数据日期 / 版本
-> 直接运行，或由用户模拟器完成澄清
-> 取数 Agent 查询并完成必要计算
-> 输出指标名称、期间、维度和数值
```

复杂取数可能包含日期范围解析、原子指标查询、分子分母分别汇总、派生指标计算和同比 / 环比计算。

**验证与计算**

LLM Judge 比较最终结果与人工标准答案。题内所有关键指标和数值全部正确才 Pass。

```text
数据准确率
= 数据结果全部正确的任务数 / 有效取数任务总数
```

错误按日期、指标匹配、工具参数、原子数据、聚合、公式或结果表达归因。用户口述历史数据准确率在 90% 以上。

### 4.2 取数澄清

**任务集**

- 开发初期人工整理约 50 题，精确数量待核实；
- 覆盖单指标和多指标澄清；
- 每题保存不完整首问与隐藏目标；
- 便宜模型扮演用户，只知道目标指标的业务含义，不知道标准指标名。

**运行**

```text
首轮不完整问题
-> Agent 发起澄清
-> 用户模拟器按隐藏目标回答
-> Agent 继续澄清或调用任务提交工具
-> 提交成功，或超过最大轮次后终止
```

测试终点是把澄清后的任务提交给数据 Agent，不继续执行真实取数。

**验证与计算**

工具先验证接口与参数格式；LLM Judge 再判断交接内容是否与隐藏目标一致。接口成功但指标语义错误仍判 Fail；多指标题必须全部正确且无遗漏、无错误增加。

```text
澄清成功率
= 在轮次上限内正确提交任务的案例数
  / 有效澄清案例总数
```

### 4.3 业务知识与指标口径咨询

**任务集与环境**

- 业务知识与指标口径题合计约 20～50 题；
- 问题和参考答案由人工整理；
- 业务知识来自业务人员梳理的知识文档；
- 指标口径和元数据通过接口查询。

**运行、验证与计算**

```text
人工问题
-> Agent 查询业务文档或指标接口
-> Agent 生成最终回答
-> LLM Judge 只比较最终回答与人工参考答案
-> 错题再查看是否正确召回
```

```text
咨询回答准确率
= 最终回答正确的咨询任务数 / 有效咨询任务总数
```

用户回忆历史准确率接近 100%，原始结果待核验。

### 4.4 数据分析与报告

**任务分类**

- 每一种分析约 5 题，具体类型数和总题量待核实；
- 固定分析有人工参考答案；
- 开放分析没有参考答案；
- Agent 运行到生成含数据和图表的最终报告；
- Judge 只查看最终报告。

**固定分析 Pass 条件**

1. 使用正确的指定方法；
2. 数据和必要计算正确；
3. 图表中的数据、指标、时间、维度和图例正确；
4. 结论不与数据和图表冲突。

**开放分析 Pass 条件**

1. 报告中的数据和图表不存在可识别错误；
2. 不要求命中唯一分析路径或参考洞察；
3. 事实结论有证据支持；
4. 未验证方向标记为假设，不把编造原因写成事实。

**运行、验证与计算**

```text
少量人工分析题
-> 运行到最终报告
-> 固定分析按参考答案 Judge
-> 开放分析无参考 Judge
-> 输出 Pass / Fail
```

```text
分析任务成功率
= 通过的分析任务数 / 有效分析任务总数
```

用户口述历史分析任务成功率约 70%。后期主要通过线上失败问题逐 Case 迭代。

**验证边界**

开放分析没有参考答案，Judge 又只看最终报告，因此可以检查自洽性、明显图文冲突和无依据结论，但不能独立证明报告中的数据查询真实正确。90% 以上的数据准确率来自独立取数评测，不能自动证明每一道开放分析报告的数据正确。

### 4.5 跨会话连续性与记忆

跨会话记忆已经实现。历史测试主要验证已有记忆能否在后续会话被正确读取和使用。

```text
选择线上已有会话及已写入记忆
-> 根据历史内容设计后续问题
-> 在后续会话提问
-> Agent 使用已有记忆续接任务
-> 判断是否正确延续上下文
```

- 约 10 题；
- 题目来自线上真实会话和已有记忆；
- 用户回忆连续成功程度在 90% 以上，待核验。

```text
跨会话连续成功率
= 正确使用已有记忆完成续接的案例数
  / 有效跨会话测试案例数
```

该测试只证明已有记忆的读取与使用，不自动证明记忆写入、冲突更新、错误纠正、应遗忘处理或跨用户隔离。

### 4.6 定时任务与主动交付

定时任务已经实现：每日定时触发，生成报告文档和摘要，并将摘要发送到群聊。

```text
每日定时触发
-> 执行数据与分析任务
-> 生成报告文档和摘要
-> 向群聊发送消息
-> 检查交付状态
```

```text
定时交付成功率
= 按要求完成报告与群消息交付的计划任务数
  / 应执行的计划任务总数
```

用户口述历史测试与运行结果为 100%；统计周期、运行次数和重试口径待核实。报告中的数据与分析正确性复用已有指标。

报告或告警“是否对业务有用”没有固定离线指标，主要根据业务实时反馈持续调整，例如取消无价值告警、调整阈值，或将每日约 10 个告警减少到约 5 个。

## 5. 横向运行与治理现状

### 5.1 模型与 Token

- 没有进行模型对比测试；
- 早期模型由用户口述为“Cloud OPS”，可能指 Claude Opus，精确名称和版本待核实；
- 后期改为 GPT-5.6；
- 没有系统性的 Token 成本治理；
- 每日 Token 消耗约 8,000 万，没有输入 / 输出、任务类型或模型维度拆分，也没有已核实的日成本。

8,000 万 Token / 日只能描述历史消耗量级，不能表述为已经完成成本优化。

### 5.2 延迟与稳定性

历史没有正式统计响应延迟或系统稳定性，没有已确认的 P50 / P95、系统错误率、可用性或重复运行稳定性数据。

### 5.3 权限与数据安全

权限和数据安全由上层平台统一管控，项目团队没有单独实现或评测。项目说明中应明确责任边界，不将平台能力扩写成项目团队已验证成果。

### 5.4 工具失败重试

```text
没有明确报错原因：最多重试 3 次
存在明确报错原因：最多重试 10 次
```

这是恢复控制规则，不是已完成的恢复能力评测。错误分类、参数调整、不可重试错误和重试恢复成功率没有独立统计。

用户另口述整体成功率在 90% 以上；由于分母和指标对象不明确，暂不归入端到端、工具恢复或系统稳定性指标。

## 7. 失败归因框架

最终指标保持精简；错题通过 Case 与 Trace 归因：

```text
澄清失败
知识 / 指标未召回
工具选择或参数错误
日期与指标解析错误
原子数据或公式错误
固定分析方法错误
图表或报告错误
开放分析无依据结论
记忆未读取或误用
定时触发或交付失败
工具重试耗尽
```

失败原因用于改进，不与任务 Pass / Fail 混成一个平均分。

6. 定时任务 100% 的统计周期和成功口径。

在证据补齐前，所有近似历史数字保留“用户口述、待核验”标记。
