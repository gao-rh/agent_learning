## 四、简历应着重的项目事件

以下是应从事实源中提炼的“问题—决策—行动—结果—边界”事件，不是可直接复制的最终简历句子。

### 事件 1：把业务问数需求演进为数据智能产品

- **要突出**：从指标线上化和 Workflow，到可信取数，再到分析 Skill 和开放分析的分阶段演进。
- **证明什么**：你不是只完成一次 Prompt 调整，而是能根据用户使用情况、稳定性和产品目标迭代架构。
- **需补证**：每个阶段的真实时间、用户、产物、个人责任和可验证结果。

### 事件 2：用“澄清—实施—验证”做可信取数

- **要突出**：将模糊指标、时间口径和复合计算收敛为标准指标与结构化参数；让模型做理解和路由，让工具/代码做确定性执行。
- **证明什么**：Prompt Engineering、Tool/Skill、业务语义和可控 Agent 链路的综合能力。
- **需补证**：运行时是否强制调用指标库，跳过工具时能否阻断，失败后怎样重试、降级或拒答。

### 事件 3：一次错误报告暴露语义层和证据链缺口

- **真实链路**：用户分析某业务事件 → 选择了一个合法、可查但不适用的指标 → 查询与计算正常 → 报告生成又将标准指标名改写成用户口语 → 错误报告被用于汇报。
- **要突出**：“指标合法/查得出”不等于“指标适用/答案正确”；语义层需要建模业务事件与指标的适用关系，报告还要保留标准指标身份和来源证据。
- **证明什么**：对语义层、数据可信、badcase 归因和产品风险的深度理解。
- **表述边界**：事故已确认；事件—指标关系约束、标准字段保护和生成后一致性校验是否已上线仍待确认，不能把改进方案写成已落地成果。

### 事件 4：把商分经验沉淀为可复用分析能力

- **要突出**：与商分、运营共同抽象分析方法，将默认从全局开始的大流程拆成下拆、漏斗等基础能力，让 Agent 从用户当前异常节点进入。
- **证明什么**：业务知识抽象、Skill 设计、产品体验与架构选型能力。
- **选型故事**：讲清 Workflow 能跑但建设维护较重，为什么某些分析方法用 Skill 已足够，以及哪些硬约束仍必须留在工具或编排器中。

### 事件 5：建评测、用 badcase 推动回归和可靠性改进

- **要突出**：题集不只看最终回答，而要分开指标识别、口径适用性、查询参数、工具执行、报告表达和端到端任务完成。
- **证明什么**：JD 明确要求的“评测体系搭建”与落地迭代能力。
- **需补证**：题集来源、分类、去重、判分标准、版本、运行方式、失败分布以及 83%/接近 100% 的准确口径。

### 事件 6：在小样本和隐私约束下搭建内容风险质检链路

- **要突出**：关键词预筛 → 内部模型初审 → 脱敏 → 外部模型复审与分级 → 人工确认 → 样本回流。
- **证明什么**：与目标岗位“内容质量业务侧 AI 数据智能产品”在问题机制上相似，同时体现 Prompt、模型路由、隐私、评测和 human-in-the-loop。
- **表述边界**：它是理赔客服风险质检的早期探索，不是字节内容生态项目；约 30% 准确率、无可靠召回率和尚无客诉改善证据都必须如实保留。

### 事件 7：在平台能力上完成应用层交付

- **要突出**：你是 Agent 技术框架主负责人，与业务、产品、商分和数据协作，负责应用层方案、工具/脚本、评测和迭代推进。
- **证明什么**：需求分析、技术设计、编码交付、协作沟通和业务落地的完整性。
- **表述边界**：不使用“独立完成整个 Agent 平台”或“自研底层 Runtime”；必须标出内部平台、模型、指标平台和协作团队的贡献。

## 七、不要为了命中 JD 硬写的内容

- **RAG**：当前指标名匹配是纯字符串模糊检索，不是向量检索；只有补齐知识治理、检索、注入、引用和评测的真实链路后，才能精确命名。
- **LangChain / Dify / LangGraph**：JD 中是“熟悉开源 Agent 框架者优先”，不是强制项。历史项目未使用的框架不写进生产技术栈；本地 LangGraph/Kimi 只是脱敏学习复现。
- **LLM 平台、底层 Runtime 或模型训练**：没有个人建设证据时不写；这些是 JD 加分路径之一，不是替代 Agent/RAG 项目落地经验的必答题。
- **完整语义层已建成**：当前可确认的是标准指标、定义、查询路由和已暴露的适用性缺口，不是所有关系和治理机制都已完成。
- **完善评测体系**：在题集口径、分层指标、版本和回归方式没有核对前，不用“完善”、“全链路”等绝对表述。
- **独立完成平台或项目**：应写清应用层主负责、个人代码/配置/评测产物、平台依赖和协作团队。
- **内容质量同行业经验**：理赔客服风险质检可作相似问题机制证据，不能写成做过头条、番茄或内容生态。
