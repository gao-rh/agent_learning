## 4. Agent 版与 Data Agent 版的核心分歧

用户已经发现：如果恢复数据项目、恢复工作经历中的数据职责，同时智能经营分析大部分沿用 Data Agent 版，那么两份简历可能只剩岗位名称不同。

这是下一会话需要优先解决的战略问题。当前建议不是伪造两套经历，而是调整篇幅和证据权重：

| 版本 | 主要信号 | 公共营销数据建设 | 灰记 |
| --- | --- | --- | --- |
| Data Agent 版 | 智能经营分析、可信取数、分析与数据底座 | 相对完整 | 较短 |
| Agent 开发版 | 智能经营分析、智能质检 Workflow、灰记 Agent 产品 | 保留但压缩 | 3 个贡献点，权重更高 |

Agent 版不应该靠以下方式制造差异：

- 把普通能力硬命名为 Harness；
- 为命中关键词而把每项都叫 Skill；
- 把确定性 Workflow 包装成自主 Agent；
- 宣称高级 Agent Runtime、Infra 或平台能力，但实际项目证据不足。

Agent 版应该靠以下真实证据形成差异：

- 主 Agent、取数 Agent、分析 Agent 的任务编排与职责边界；
- 自然语言取数的受控执行和评测；
- 真实 Case 驱动的 Prompt 自动迭代与评测闭环；
- 确定性 Workflow 的生产交付；
- 灰记的跨端产品、任务持久化、失败恢复、结构化交付和人工确认；
- 公共营销数据项目作为数据理解与工程能力补充。
