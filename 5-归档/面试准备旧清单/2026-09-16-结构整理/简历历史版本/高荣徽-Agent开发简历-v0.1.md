- 建设向量化业务知识库和事件库：按事件类型预处理、分块，采用关键词与语义混合检索并排序；设计从总量到细分维度逐层下钻的异常归因链路，定位至具体人群和 source，再结合关联业务事件形成原因判断。
- 建立“少量初始案例—真实问题抽象—人工设计与 AI 扩展”的三阶段评测迭代机制，形成 100 题端到端数据集并将综合准确率提升至 80%+；上线后根据真实用户问题 case-by-case 修正。核心指标平台覆盖范围内取数准确率接近 100%，满足 90%+ 常见查数诉求。

- 针对场景险活动依赖营销平台几十种历史模板、保险规则难理解、运营容易选错和返工的问题，设计业务意图到营销平台能力之间的 Agent 编排层：理解运营诉求，匹配活动类型、模板和参数，并调用平台接口生成配置。

## 个人项目

### 灰记 GeryRecord｜AI-native 个人生活 Agent MVP·持续迭代

> 当前为一个月后投递目标稿；标记“待验证”的能力只有在投递前完成真实验收后才能保留。

- 以“记录事实优先、AI 只生成可确认草案”为产品原则，设计 iPhone 本地事实主库、Apple Watch 轻交互入口与 Mac 私有 Agent/备份节点，覆盖健康、睡眠、体重、运动、通勤、状态、生活事件、今日时间线和七日回顾。
- 负责产品定义、需求拆解、数据与安全边界、AI 协同开发流程、测试标准和真实设备交付推进；代码主要由 Codex 等 AI 工具生成，通过规格、代码审查、自动测试、模拟器和受控真机验证持续纠偏，不声称手写全部 Swift/Python 实现。
- 构建轻规划 Agent 闭环：Mac Codex 仅读取受限 JSON 上下文并遵循专用 Skill，通过 JSON Schema 生成最多 3 个结果、5 个活动块的次日草案；iPhone 展示草案，用户确认后才形成正式 `DailyPlanVersion`。
- 将事实与规划分库存储，保留计划父版本、生成原因、确认状态和执行结果；剩余日重排只压缩、移动或删除尚未开始的活动，不改写已发生事实、固定安排和历史版本。
- 在 iPhone 接入 Kimi 结构化计划 Patch：API Key 仅存 Keychain，请求限制为 HTTPS 与指定 origin，模型输出经过 JSON、数量、标题、时长和固定时间规则校验，确认前不直接修改正式计划。
- 使用 SwiftUI、SwiftData、HealthKit、Core Location、App Intents、WatchConnectivity 和 Python MacNode 实现跨 iPhone/Watch/Mac 的本地优先系统；断网、Mac 关机或模型不可用时，原始记录和基础统计仍可工作。
- 设计记录与安全链路：原始 Capture 先落库、结构化派生与纠正链追加保存；使用持久 Outbox、ack、重试、canonical hash 和 Mac 幂等副本降低离线同步中的重复与丢失风险，并为 V1→V2 迁移保留只读回退和恢复材料。
- 构建 AES-GCM 加密快照、自动/恢复双密钥、版本保留和隔离恢复工具；Git 仅保存代码、规格、Schema、Skill 和测试，不保存个人健康库、音频、同步凭证或恢复密钥。
