#### 智能经营分析 Agent｜技术框架主负责人

- 面向约 20–30 名场景险产运与商分用户，统一承接指标口径查询、智能取数、流量/保费/商户变化专题分析、开放式分析、业务知识问答及主动巡检；联合业务、产品、商分和数据团队沉淀口径与分析逻辑，个人负责 Agent 整体技术链路。
- 按任务确定性设计两类编排：查口径/查数先澄清诉求并识别指标支持范围，经营分析中固定专题走 Workflow、临时问题由 Agent 按需组合 Tool/Skill；不使用固定意图分类器，而是由 Agent 依据能力规范和上下文自主判断执行路径。
- 构建可信取数与降级机制：核心指标优先调用指标平台，平台未覆盖的长尾需求降级为 SQL 查询数仓并提示可靠性边界；在平台执行校验之外，以单指标参考范围、多指标关系和空结果检查识别错误筛选、关联及异常量级，降低常见低级错误。
- 建设业务知识与事件检索链路：对事件按类型预处理和分块，通过关键词+语义混合检索及排序召回相关知识；异常分析从总量逐层下钻至细分人群和流量来源，再结合关联业务事件归因。
- 将对话式能力扩展为主动执行：通过定时任务和统计方法每日巡检各资源位流量，识别异常、推测原因，并经企业 IM 主动触达业务、附带简要分析报告。
- 分阶段建设评测闭环：先以少量初始案例和 AI 辅助迭代打通能力，再将真实问题、人工设计题与 AI 扩展题归类为 100 题离线评测集，上线后按真实 badcase 持续修正。
- 百题集综合准确率达到 80%+；指标平台覆盖的核心取数准确率接近 100%，覆盖 90%+ 常见查数需求。核心看数由至少等待半天转为用户自助完成，常规分析报告由人工 2–3 天缩短至约 1–2 小时。

#### 活动自动化配置 Agent｜编排与业务适配负责人

- 针对营销平台历史模板多、保险规则复杂、运营容易选错和返工的问题，建设从自然语言业务诉求到活动类型、模板、参数及平台接口的 Agent 适配层，帮助运营完成场景险商家活动配置。
- 将场景险业务知识与平台提供的十余类配置 Skill/Workflow 组合，完成模板匹配、参数补全和接口调用；底层配置 Skill 由平台团队提供，个人负责业务规则、用户意图与平台能力之间的编排衔接。
- 将高风险动作留在人手中：Agent 生成配置后必须由运营确认才正式生效，避免错误活动直接发布。
- 覆盖约 20–30 名运营，其中 5–10 名高频日用，日均配置约 10 个活动；据运营反馈原流程通常约 1 小时，Agent 链路典型运行十余分钟。
- 曾探索按资源位、渠道聚合并生成结论的 AI 活动看板；真实使用中采用度低，因此主动收敛功能，把资源集中到“快速、正确完成配置”的主链路。

#### 其他 AI 探索｜理赔客服风险质检

- 基于平台已有 ASR，负责“关键词预筛—内部模型初审—规则与 AI 脱敏—外部模型复审—人工听取”的完整链路，将身份证号、手机号等敏感信息限制在内部边界。

## 个人项目

### 灰记 GeryRecord｜本地优先的个人生活记录与轻规划 Agent｜开发中

- 以 iPhone 为事实主库、Apple Watch 为轻交互入口、Mac 为私有 Agent 与备份节点，负责产品定义、需求拆解、架构与安全约束、测试验收和交付推进；主要代码由 Codex 等 AI 工具生成，通过规格、代码审查和自动测试约束实现质量。
- 设计“事实记录—受限上下文—结构化计划草案—用户确认—版本化重排”的 Agent 闭环：事实与规划分库存储，草案经 JSON Schema 和规则校验后展示，只有用户确认才写入正式计划；重排仅调整未开始活动，不覆盖已发生事实和历史版本。
- 使用 SwiftUI、SwiftData、HealthKit、Core Location、App Intents、WatchConnectivity 与 Python MacNode 实现 iPhone/Watch/Mac 本地优先架构；模型或 Mac 不可用时，原始记录与基础统计仍可工作。
- 通过持久 Outbox、ack、重试、幂等副本处理离线同步，通过迁移回退、AES-GCM 快照与隔离恢复保护本地数据；Git 不保存个人健康数据、音频、凭证或密钥。
- 截至 2026.08，iOS 自动化测试 171 项通过、1 项跳过，MacNode 56 项通过；真机 Watch、围栏和私有网络链路尚未作为已完成能力写入。
