# Agent / AI 开发面经全景摘要（2026-08-27，2026-08-30 增补）

> 状态：基于已核验资料的分析结果，不是答案库，也不代表本人已掌握。  
> 明细与全部来源见：[Agent开发面试题与来源明细-2026-08-27.md](Agent开发面试题与来源明细-2026-08-27.md)。

## 一句话结论

这批面经最稳定的共同点不是某个框架名词，而是：**面试官会从真实项目出发，连续追问“为什么这样设计、失败了怎么办、怎样证明有效、上线后怎样稳定运行”**。RAG、Memory、Tool/MCP、Agent Loop 只是入口；决定追问深度的是项目真实性、工程边界、评测证据与后端可靠性。

## 6. 各核心类别该准备什么问题

### 6.1 项目深挖

核心问题：业务问题是什么、谁使用、本人负责什么、为何采用当前架构、量级与约束是多少、指标如何定义、最大的失败与迭代是什么、团队如何协作。

特征：面试官经常不接受“提升准确率/效率”这类抽象说法，会继续问基线、数据口径、采样方式、线上使用量和反例。项目越真实，追问越落到具体限制和取舍。

### 6.2 Agent Runtime / Harness

核心问题：Agent Loop 的输入、状态、工具结果和终止条件；Workflow、ReAct、Plan-and-Execute 如何取舍；Checkpoint、Sandbox、失败恢复怎样做；Coding Agent 如何组织上下文、Skills 和测试。

特征：2026 外部社招样本比本地旧资料明显增加 Harness、Skill、Coding Agent 和长任务状态问题，这是最清晰的外部新增主题。

### 6.3 Tool / MCP / Skill

核心问题：模型为何决定调用工具，参数如何生成和校验，Tool Result 怎样回到上下文；MCP 与 Function Calling/Skill 的边界；大量工具怎样路由；弱模型工具调用不准怎么办。

特征：只解释协议不够，常追问部署位置、权限、超时、重试、格式校验、成本和工具链过长。

### 6.4 Memory / Context

核心问题：记忆存什么、按什么粒度隔离、何时写入和召回、冲突怎样处理；上下文怎样分层、压缩后怎样保留可执行状态和工具历史；跨 Session/项目怎样避免污染。

特征：本地资料更常问长短期记忆和 Redis 结构；外部 2026 样本更常问 Context Engineering、长任务、压缩、状态丢失与回归验证。

### 6.5 多 Agent

核心问题：为什么不是单 Agent；Supervisor 与 Sub-Agent 怎样分工和通信；共享状态怎样合并；并发写、上下文污染、闲聊死循环和代码冲突怎样解决。

特征：题量不算大，但追问深。多数材料仍是项目设计或面试场景，真实生产数据、故障率和长期评测证据较少。

### 6.6 Eval / 安全 / 治理

核心问题：离线数据集怎样构建；模块、链路和业务指标怎样分层；LLM Judge 的随机性怎样处理；Trace、Token 与失败路径怎样记录；模型/Skill/Harness 更新怎样回归；幻觉与人工兜底怎样设计。

特征：高质量场次经常问“如何证明有效”。新增 2026 原帖已经出现 LLM-as-Judge 线上抽样、MCP 鉴权和音视频隐私，但 Prompt Injection、红队测试与供应链风险仍覆盖不足。

### 6.7 RAG / GraphRAG / NL2SQL

核心问题：数据源、切分、Embedding/BM25、混合检索、Rerank、Top-K、图谱构建与更新、增量同步、召回评测、Code RAG、NL2SQL 的 Schema/校验与执行边界。

特征：这是覆盖最广的技术领域。面试不是问“会不会 RAG”，而是追问召回不到、冗余、知识过多未被使用、数据更新、一致性、规模和业务效果。

### 6.8 模型训练与推理

核心问题：Transformer/QKV、Token/词表、模型选型、微调与 RAG 取舍、SFT/LoRA/DPO/RL、KV Cache 与 Continuous Batching、多模态。

特征：算法 Agent 会更深；应用/后端 Agent 通常要求能解释机制和取舍，但较少要求完整训练实践。不能把“读过原理”说成“做过微调”。

### 6.9 后端、数据库、中间件与系统设计

核心问题：Redis/MySQL/Kafka、锁与一致性、线程池与并发、SSE/WebSocket、网络/OS、容器、高可用、限流、扩容、海量数据、监控与故障恢复。

特征：Agent 岗没有淘汰传统后端基础；越接近平台与真实线上系统，传统后端追问越强，而且会与 Tool、Memory、会话状态和评测链路结合。

### 6.10 手撕 / Vibe Coding

核心问题：常规数组、树、字符串、图、DP；并发打印、生产者消费者、限流器、Map、文本分段；少数 2026 社招直接要求用 Agent 完成需求并演示澄清、实现和 Review。

特征：传统 LeetCode 仍然存在，但 Coding Agent 团队开始把“怎样用 AI 完成工程任务”本身作为现场考察。

## 7. 本地基线与外部共识

### 交集

- 项目背景、个人贡献、业务效果和量化指标，是本地与外部最稳定的共同入口。
- RAG 的切分、召回、重排、评测与异常定位在两边都高频。
- Agent 与 Workflow、Function Calling/MCP、Memory/Context 都不是孤立定义题，而会落到实际链路。
- 后端并发、一致性、缓存、数据库、网络和系统设计仍是 Agent 开发岗的重要底座。
- 手撕算法没有消失；项目越像 Demo，面试官越容易用异常场景和上线问题追穿。

### 外部新增或明显增强的主题

- Harness 与 Coding Agent：Claude Code/Codex/OpenCode、Sandbox、Skills、AGENTS.md、长任务和回归。
- Context Engineering：不仅是截断/摘要，而是区分不可压缩状态、工具结果、失败路径和普通对话。
- 多 Agent 失效模式：自由闲聊、通信冗余、上下文污染、共享状态、多人代码冲突。
- Benchmark、Trace、Token 成本、火焰图、版本对比与 Skill/Harness 更新后的回归证据。
- Vibe Coding 现场题：让 Agent 澄清需求、执行、测试、Review，而不是候选人只写一段算法。

### 覆盖薄弱点

- Agent 安全：MCP 鉴权、音视频隐私已有原帖证据，但 Prompt Injection、审计、红队测试和供应链风险仍很少。
- 大规模多 Agent 的真实生产指标、故障率与长期稳定性证据不足。
- 算法 Agent 只有 7 场且集中在少数候选人，不能据此概括训练/推理团队的普遍风格。
- 外部秋招增加到 18 场，但与 36 场社招相比仍不平衡；本地 42 场又缺日期，因此只能做有限层级观察，不能把差异都归因于“校招/社招”。
- 本地 42 份 PDF 没有面试日期，不能与 2026 外部样本直接做时间趋势。
- 可命名公司覆盖已超过 15 家，但逐公司达到 3 场门槛的仍有限；单场公司只保留观察，不写成“公司固定风格”。

## 8. 结论限制

1. 本文统计的是公开或本地记录中的“被记录问题”，不是公司完整题库；候选人记忆和选择性记录会造成偏差。
2. 一篇多轮复盘若没有逐题标轮次，只能用于总体主题，不能把同一题复制到每一轮。
3. 中置信度材料进入总体主题是为了保留覆盖，但不参与逐公司高频结论。
4. 低置信度、题库与实习材料全部留在明细补充区，便于后续复核；本轮没有删除它们，也没有拿它们补齐 50 场目标。
5. 本轮只整理问题、来源、频次和特征，不编答案，不判断掌握状态。
6. 摘要中的“核心问题”是对原题聚类后的概括，不是面试官逐字原话；逐题原始清洗文本必须回到明细文档查看。
