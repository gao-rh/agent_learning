# 2026-08-27 Agent 开发面经整理与外部调研

## 原始需求

用户希望把本地多份面经合并整理，并在网上尽可能多地收集 Agent / AI 开发相关面试分享。最终需要：

- 一份全景摘要：题目有哪些、涉及哪些公司、各类岗位与公司核心问什么、每类题量和特征是什么。
- 一份独立明细：所有可保留的问题实例、来源、公司/岗位/轮次、分类、标准化问题 ID 与置信度。
- 本地资料作为高置信度基线；外部高、中、低置信度都保留，但低置信度不混入核心频次。
- 本轮只整理问题和证据，不编答案，不判断本人是否已经掌握。

## 已确认口径

- 保留旧文件 `2026-07-05-面试题目汇总.md`，不把旧摘要当原文，不改写旧汇总。
- 本地 42 份 PDF 每份对应一个来源记录，抽取后逐题清洗；不根据答案片段补造题目。
- 外部优先 2026，数量不足再查 2025；排除实习，校招与社招分开。
- 外部目标至少 50 场、尽量 15 家公司；不足时按实际可核验数量交付，不用低置信度补足。
- 岗位分为后端/平台 Agent、Data Agent、算法 Agent、名义 Agent/AI 但主体偏非 Agent。
- 问题使用“形式 + 技术领域”两轴分类，同场重复追问不重复抬高场次频次。
- 至少 3 场才给逐公司特点，至少 5 场且覆盖 3 家公司才给公司类型特点；否则注明样本不足。

## 后续：回答准备与简历梳理

### 原始问题

用户希望基于已经归并的面试问题，再分别形成两份完整文档：一份是需要准备好回答的问题清单；另一份是由这些问题反推当前简历应该梳理和注意的点，并要求逐个完成。

### 用户理解

- 面经整理不能停留在统计摘要，还需要变成可执行的回答准备范围。
- 简历内容需要能承受这些真实面经的追问，而不只是增加岗位关键词。
- 两类内容分别呈现，避免问题清单和简历修改建议混在一起。

### Codex 反馈

- 已将 427 条问题链去重后的 177 个标准化 ID 全部纳入回答准备清单，并用统一的短答、机制、项目证据、失败边界和追问标准定义“可回答”。
- 已逐段对照 v0.6 PDF、v0.3 可编辑稿和项目事实源，整理定位、工作总述、智能经营分析、理赔客服智能质检、灰记、技能栏和论文部分的追问与证据要求。
- 已发现并保留多项待验证冲突，包括任职时间、评测题数、用户数、质检量、违规发现量、灰记完成状态和测试数；没有替用户选择一个版本当作事实。

### 发散联想

- 面经最稳定的要求是“项目事实—设计原因—失败处理—证据验证—生产可靠性”闭环，因此后续真正有用的材料不是更多关键词，而是每个项目的架构图、指标口径卡和失败案例。
- 简历中的能力栏可以视为面试官的追问目录；每保留一个强关键词，都应能映射到代码、数据、Trace、测试或真实项目边界。

### 结论状态

- 两份清单已生成，但均为 `AI 草案 / 待本人确认`。
- 177 个标准化 ID 已机械对账，不代表本人已回答或掌握。
- 简历没有在本轮被直接改写；冲突项仍为 `待验证`。
