## 3. 项目、业务与个人经历（15 项）

这组问题不能用统一模板替代事实。智能经营分析、理赔客服智能质检和灰记应分别准备背景、架构、个人贡献、指标、失败与边界；具体答案回写各自的“项目准备”事实源。

- `PROJ-01` 自我介绍，并用业务背景、使用者和目标讲清一个代表项目。
- `PROJ-02` 说明从数据/后端走向大模型与 Agent 的过程，以及项目为什么值得做。
- `PROJ-03` 说明项目由谁提出、谁决策、谁开发；本人是否独立负责，边界在哪里。
- `PROJ-04` 证明当前版本比旧版本或上线前更好：基线、指标、样本、评测平台和业务价值分别是什么。
- `PROJ-05` 讲清一个项目最大的挑战，以及另一个项目的完整技术模块。
- `PROJ-06` 解释项目中的算法或调度逻辑、关键特征与可继续优化点。
- `PROJ-07` 给出流量、延迟、数据量、用户量、触发比例和时间上下限等真实规模口径。
- `HR-01` 完成 1～3 分钟自我介绍；解释离职、成长、阶段经历、绩效和其他流程时保持口径一致。
- `HR-02` 选择一次工作状态不佳或失败阶段，讲清原因、行动、结果与复盘，不回避个人责任。
- `HR-03` 用真实事例说明兴趣、优势、缺点和毕业后的非专业成长。
- `HR-04` 解释目标行业、公司业务与岗位的真实工作边界，而不是只复述 JD。
- `HR-05` 准备一次跨角色分歧、协调或负面反馈案例，并说明如何复盘。
- `HR-06` 说明未来两年规划、平台/行业/团队偏好、强度、薪资、职级与到岗条件。
- `HR-07` 说明近期关注的 AI 进展、学习方式、对 AGI 和 AI Coding 的判断，并能给出依据。
- `REV-01` 准备按面试对象选择的反问：业务定位、入职问题、Agent 投入阶段、团队分工、评测指标、节奏与发展。

## 4. Agent Runtime / Harness（17 项）

- `AGT-01` 区分 Agent 与 Workflow，并列出实现单 Agent、多 Agent 所需的运行时模块。
- `AGT-02` 从输入、推理、工具、状态、观察、终止条件讲清 Agent 工作循环。
- `AGT-03` 说明 Workflow 平台的优势、限制、适用场景和迁移成本。
- `AGT-04` 判断一个助手是否应该升级为可自主修改业务配置的 Agent，并给出权限、确认和回滚边界。
- `AGT-09` 解释 Prompt 中角色设定为什么可能有效、什么时候只是表面风格变化。
- `AGT-10` 说明 Coding Agent 修改本地文件的链路，以及 LangChain 等框架的定位、优缺点与是否实际使用。
- `AGT-11` 能讨论近期 Agent 工程热点，并把“了解”与“做过”分开。
- `AGT-12` 设计大型 Agent 系统的分层结构、子 Agent 协作和控制面。
- `AGT-13` 解释愿景/规格驱动开发与 Skill 形成过程，并给出版本维护和验收证据。
- `AGT-14` 说明存量项目如何引入 Agent 开发，以及需求变化时怎样维护规格、上下文和代码一致性。
- `AGT-15` 完整演示一次 Vibe Coding / Coding Agent 流程，并说明五天级长任务怎样防止目标漂移。
- `AGT-16` 设计节点失败、意图识别错误、工具失败时的重试、回退、降级、补偿和人工介入。
- `AGT-17` 怎样用 Agent 做 Auto Research？【Codex 扩展】可按检索、规划、证据管理、综合、引用和停止条件组织回答。
- `AGT-18` AI 在运维和大数据系统改造中有哪些可落地场景？【Codex 扩展】可补充数据闭环和风险。
- `AGT-19` 怎样把既有内部软件逐步改造成 AI 系统？【Codex 扩展】可补充能力切分、试点、评测、灰度和回滚。
- `AGT-20` 训练与评测跨天运行、按 Checkpoint 打分并可能回滚重训时，Agent 怎样编排状态、幂等、恢复与人工接管？
- `AGT-SANDBOX-01` 解释 Agent 为什么需要沙箱，以及文件、命令、网络、密钥和资源限额怎样隔离。

## 5. Tool / MCP / Skill（7 项）

- `TOOL-01` 讲清 Function Calling 的完整链路；模型不原生支持时怎样用协议、解析和校验实现。
- `TOOL-02` 说明 MCP 的目标、优势、客户端/服务端位置，以及无原生 Function Calling 时的适配方式。
- `TOOL-03` 比较 MCP、Function Calling、Tool 与 Skill 各自解决的问题和组合关系。
- `TOOL-04` 设计 Web Search 等高成本工具的路由、预算、缓存、去重和停止策略。
- `TOOL-05` 解释 Skill 与 MCP 的关系，区分知识/流程封装、协议和实际执行能力。
- `TOOL-06` 弱模型工具调用不准时，如何通过工具描述、Schema、候选收缩、路由、示例、校验和重试改进。
- `TOOL-07` 将一组已有接口接入 Agent 和现有系统：鉴权、协议、错误码、幂等、部署、协作与验收。

## 6. Memory / Context（13 项）

- `MEM-01` 说明记忆保存什么、不保存什么，使用什么结构和存储，为什么这样选。
- `MEM-02` 记忆过多时如何筛选、压缩、淘汰和评测，避免“存得越多越好”。
- `MEM-03` 区分短期、长期、情景、语义、任务状态等记忆，并说明使用场景。
- `MEM-04` 说明保存时长、用户/Task/Session 隔离粒度，以及各类记忆的评测方法。
- `MEM-05` 区分本轮上下文与历史会话，明确召回、优先级和覆盖规则。
- `MEM-06` 为“用户—多会话—多轮消息—工具调用—摘要/记忆”设计数据模型和索引。
- `MEM-07` 解释追问识别、上轮实体复用和新旧问题相似度判断，说明阈值失败怎么办。
- `MEM-08` 将用户反馈转成后续可用记忆：写入条件、确认、作用域、冲突和撤销。
- `MEM-09` 解释 Claude Code 等 Coding Agent 的项目级/用户级记忆机制，并与普通聊天记忆区分。
- `MEM-10` 设计 System Prompt、Memory、Tool Result、Conversation 和任务状态的上下文组装顺序与预算。
- `MEM-11` 上下文过长时怎样压缩，并保护不可丢失的工具历史、失败路径和可执行状态。
- `MEM-12` 解决冲突记忆、过期事实和错误记忆；说明为什么检索记忆、是否分层检索。
- `MEM-13` 解释某套记忆系统为何这样设计，怎样做 Session/项目隔离及外部知识库连接。

## 7. 多 Agent（5 项）

- `MA-01` 设计子 Agent 状态汇总、故障消息聚类和 Supervisor 分流，避免全部信息上卷。
- `MA-02` 说明 Agent 间通信协议、共享状态和上下文隔离，避免相互污染。
- `MA-03` 说明 Master/Sub-Agent 的创建、调度、终止和资源回收条件。
- `MA-04` 两个 Agent 自由协作时持续闲聊或无法结束，怎样检测并强制收敛。
- `MA-05` 三人团队使用多 Agent 协同开发时，怎样拆任务、管理依赖、Review 和处理代码冲突。

## 8. Eval / 安全 / 治理（9 项）

- `EVAL-01` 设计自动评测系统：数据集、模块/链路/业务指标、Judge Prompt、随机误差与版本对比。
- `EVAL-02` 解释幻觉的来源，并从检索、约束、验证、拒答和人工兜底降低风险。
- `EVAL-03` 设计 Agent/大模型监控：Trace、Token、时延、工具调用、失败路径、成本、质量与告警。
- `EVAL-04` 为模型生成业务配置设计人工确认、权限、审计、回滚和高风险阻断。
- `EVAL-05` 修改 Harness、Prompt、模型或 Skill 后如何做 Benchmark，证明改动有效而非只看个例。
- `EVAL-06` 新功能加入后怎样防止旧功能漂移；外部云服务不可控时怎样做测试替身、契约测试和回归。
- `EVAL-07` 为 ToC 产品设计 LLM-as-Judge，并说明线上无法全量评分时如何采样、校准和监控。
- `EVAL-08` Agent 工具输出很差时，怎样定位是路由、上下文、模型、工具还是结果校验环节的问题？
- `BE-SEC-01` 音视频、转写文本和其他敏感数据怎样在传输、存储、访问、日志与删除环节保护？

## 11. 后端、数据库、中间件与系统设计（49 项）

### 11.1 分布式、一致性、并发与可靠性

- `BE-LOCK-01` 解释 Redis 分布式锁的缺点：过期、误删、续期、主从切换、时钟与一致性。
- `BE-LOCK-02` 比较分布式锁与乐观锁，并解释 ABA、版本号和冲突重试。
