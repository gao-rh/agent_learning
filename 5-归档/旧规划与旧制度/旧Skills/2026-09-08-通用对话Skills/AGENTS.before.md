# Agent Learning Repository Instructions

本仓库以学习为核心，覆盖学习历史、重要资料、未来事项、人生与学习规划、课外阅读和小探索。

## 项目边界

- 本仓库只做学习和规划；允许保留为理解机制服务的小型学习复现与实验。
- 正式项目或复杂度明显上升的开发工作必须进入独立仓库和独立任务。
- 对外部项目，本仓库可以保存需求、规划、学习记录和交接材料，但不得直接承载其产品代码开发。

## 开始工作前

1. 读取根目录 `PREFERENCES.md`；若本会话已经读取，确认使用的是当前版本。
2. 仅在任务明确匹配时使用项目级 Skill；普通问答、解释、文件查看和一次性处理可以直接完成：
   - 用户明确表示正在学习、想学习或开展学习实验时，使用 `learning-companion`。
   - 用户明确要求调研、查资料、核实事实或比较来源时，使用 `research-assistant`。
   - 用户明确要求制定计划、比较方向、确定优先级或讨论关键决策时，使用 `planning-dialogue`。
   - 周期回顾、索引维护、链接检查和迁移验证等机械维护，使用 `review-maintainer`。
3. 不要仅因为任务发生在学习仓库、涉及技术概念或可能具有教育价值，就触发 `learning-companion`。
4. 不再把旧《长期学习工作流》、旧行动中枢或旧 30 天计划当作现行规则。

## 固定结构

- `1-清单/`：尚未开始的事项。状态只能是 `待判断` 或 `已确认`。
- `2-进行中/`：当前真实投入的主题。
- `3-已完成/`：完成且仍有价值的学习历史。
- `4-学习资料/`：尚未拆分的混合大资料临时区；不得接收新资料。
- `5-归档/`：失效制度、未确认 AI 草案、放弃事项和旧版本。
- `.agents/skills/`：一个 Skill 只承担一个明确职责。

正式主题固定使用：

```text
主题名/
├── README.md
├── 记录/
└── 资料/
```

只有确实需要运行验证时才增加 `实验/`。不要预建无内容的分类目录。

参考资料必须跟随主题放入 `资料/`。不纳入 Git 的大型课程文件、外部仓库和二进制原件放入主题的 `资料/本地资料/`；不要再把新内容放入根目录 `4-学习资料/`。

## 状态和写入边界

- 主题 README 保存：当前状态、重要资料、未解决问题、下一步、下次检查日期。
- 学习问题状态只能是：`已理解 / 待继续 / 待验证`。
- AI 生成的计划、优先级、结论和建议默认是草案。只有用户明确确认后，才能成为正式计划或已确认事项。
- 自动任务不得把 `待判断`、规划草案或建议改为 `已确认`、`已完成` 或 `归档`。
- 保留用户原始理解；先在对话中纠错和补充，用户确认后才能把修正版写成稳定结论。
- 主题不明的新事项写入 `1-清单/README.md`，状态为 `待判断`。
- 简单事项在总清单写一行；需要资料、多个步骤或第二次讨论时，再升级为主题文件夹。
- README 的人工正文与 `AI-SUMMARY` 标记区分开。自动任务只能重建标记内内容。

## 学习和规划原则

- 学习时主动教学、纠错、追问和补充反例，不做被动记录器。
- 实验默认由用户预测、运行和解释；Codex 的环境准备或诊断不等于用户完成学习。
- 规划前先核对事实和未知项；一次讨论一个关键问题，给出 2–3 个真实方案及取舍。
- 新规划不得继承旧 30 天计划、求职冲刺计划或行动队列中的未确认目标。
- 多项平行比较优先用表格；只有确实帮助理解时才使用图表。

## 自动化和 Git

- 凌晨任务只做无需用户参与的扫描、索引和草稿生成；需要决定的内容留到晚间讨论。
- 机械维护通过验证后可以提交并推送；禁止强推。远端分叉、冲突、异常大文件或验证失败时停止。
- 不提交大视频、大 PDF、数据集、模型、`.env`、Obsidian 本地状态和临时输出。
- 不使用 Hermes 作为新系统依赖；QQ 沟通方式另立待办。
