# 操作系统核心疑问总结

[返回学习资料](../README.md)

| 核心疑问 | 当前结论 |
| --- | --- |
| 控制单元是什么？ | 它读取并解码指令，再发出控制信号，让寄存器、ALU、内存和程序计数器按顺序协作；它不是主要的计算或存储部件。 |
| 寄存器、Cache、主存有什么区别？ | 这里的主存基本就是内存/RAM。寄存器保存 CPU 当前直接操作的值；Cache 是 CPU 自动维护的少量内存数据副本；主存保存正在运行的程序和完整工作数据。 |
| 为什么 32 位地址对应 4 GiB？ | 32 个二进制位能组合出 `2^32` 个地址。按字节编址时就是 `2^32` 字节；这是地址范围，不是同时操作的数据量。 |
| 写回和写直达解决什么？ | 解决 CPU 修改 Cache 后何时同步主存。写直达每次都同步；写回先标脏，之后再批量写回，性能更好但一致性更复杂。 |
| 用户线程和内核线程差在哪里？ | 核心是“谁知道并调度它”。用户线程由用户态线程库管理；内核线程是内核可见并直接调度的执行实体。 |
| 现代 CPU 调度只按先来后到吗？ | 不是。系统会综合公平性、优先级、响应时间、吞吐量、多核负载和实时约束。 |
| 管道的读端和写端到底是什么？ | 它们是进程 fd 表中的两个句柄，最终指向同一个内核管道对象；不是简单的链表节点。 |
| 为什么 `fork()` 后管道还能用？ | 子进程继承父进程的 fd 表，父子双方的 fd 仍引用同一个内核管道对象。 |
| fd 到底是什么？ | fd（file descriptor，文件描述符）是进程 fd 表中的一个非负整数编号。它不是文件本体，而是进程找到内核打开对象的句柄；文件、管道、Socket 都可以被 fd 引用。 |
| 为什么会出现 `too many open files`？ | 每次 `open()`、`socket()`、`accept()` 或 `pipe()` 都需要占用 fd 表项。进程达到 fd 上限后没有空编号可分配，内核就让调用失败并返回 `EMFILE`；未关闭对象导致的 fd 泄漏和过高并发都是常见原因。 |
| VFS 抽象了什么？ | 它统一了文件、目录、inode 和文件操作等对象与接口，使应用能用同一套系统调用访问不同文件系统。 |
| FAT 和索引分配有什么本质差别？ | FAT 是全卷共享的“物理簇到下一簇”链表；索引分配为每个文件维护“逻辑块到物理块”的地址表。前者简单兼容，后者随机访问和扩展性更好。 |
| Socket 到底是什么？ | 它首先是内核中的通信端点对象；应用通过 Socket API 操作它，并用 fd 引用它。它本身不是 TCP 协议。 |
| NAPI 的核心优势是什么？ | 低流量时用中断保证及时，高流量时切换为批量轮询，主要减少中断风暴和频繁上下文切换，而不是让 CPU 完全不工作。 |
