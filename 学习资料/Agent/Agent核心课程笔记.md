# Agent 核心课程笔记

[返回学习资料](../README.md)

## 一句话主线

**大语言模型负责根据当前输入生成结果；Agent 是围绕模型搭建的一套运行系统，负责准备上下文、调用工具、保存记忆、持续执行任务并控制权限。**

## 核心框架

```text
目标 / 触发器
    ↓
准备当前上下文
    ↓
模型判断下一步
    ↓
调用工具并观察结果
    ↓
继续循环，直到完成或停止
    ↓
保存必要的结果与记忆
```

| 部分 | 解决的问题 |
| --- | --- |
| 模型 | 理解当前输入、推理、生成下一步动作或回答 |
| Context | 让模型在这一回合看到任务、历史、规则、资料和工具结果 |
| Tools | 让系统能读文件、执行代码、搜索、操作外部软件，而不只生成文字 |
| Memory | 把跨回合需要保留的信息存到模型之外，并在需要时重新取回 |
| Runtime / Harness | 组织执行循环、权限、错误恢复、验证、日志和停止条件 |
| Skill | 把某类任务的做法、规则和工具组合成可复用能力 |
| Sub-agent | 把相对独立的子任务交给另一个执行上下文，再汇总结果 |

## Harness 方法论

从工程实现看，可以把 Agent 写成：

```text
Agent = Model + Harness
Harness = 上下文 + 工具 + 约束 + 验证 + 纠正
```

| 构成 | 解决的问题 |
| --- | --- |
| 上下文 | 模型当前需要看到什么 |
| 工具 | 模型可以通过什么方式行动 |
| 约束 | 哪些动作、参数和边界不能越过 |
| 验证 | 怎样检查这一次执行是否真的正确 |
| 纠正 | 出错后怎样重试、换策略或移交人工 |

这里的“验证”不同于离线“评估”：验证发生在具体运行中，评估通常跨任务、跨样本衡量系统整体表现。

## 选择单次调用、工作流还是 Agent

| 任务特征 | 优先选择 | 原因 |
| --- | --- | --- |
| 一次模型调用即可完成 | 单次 LLM 调用 | 不增加不必要的状态、成本和故障点 |
| 步骤固定、顺序可提前确定 | 工作流 | 把执行路径写死，更可控、可验证 |
| 步骤无法预先确定，需要根据反馈调整 | 自主 Agent | 由模型动态决定下一步行动 |
| 既有开放探索，又有高风险固定环节 | 工作流 + Agent | Agent 负责探索，工作流控制付款、发布、删除等关键步骤 |

选择原则不是“越自主越先进”，而是：**使用完成任务所需的最小自主性。**

## Context Engineering

Context Engineering 不是单纯把提示词写长，而是决定**模型此刻应该看到什么、不应该看到什么，以及怎样以合适结构提供**。

核心动作包括：

- 选择相关历史与资料，而不是无限堆积全部内容。
- 把长期信息放在外部文件或数据库，需要时检索回来。
- 明确规则、任务、证据、工具输出和当前状态的边界。
- 在上下文过长时进行摘要、压缩、卸载和按需读取。

### Attention 到 KV Cache 的主线

在自回归 Transformer 中，当前位置的 Query 与自己及历史位置的 Key 匹配，经过 causal mask 和 softmax 得到 Attention Weight，再对相应 Value 加权求和。热力图展示的是 Weight，不是 Q、K 或 V 本身。

同一次前向计算里，各 Layer 保持相同的序列位置数量，只更新每个位置的 hidden state。最后一个已有位置经过全部 Layer 后，由 LM Head 映射成词表 logits 并选择下一个 token；新 token 在下一轮才进入 Transformer。

生成后续 token 时，历史位置的 K/V 不变并会被新 Query 反复读取，因此可以缓存。Context Engineering 不只是决定“放什么内容”，还要尽量保持系统提示、工具定义和历史消息的稳定前缀，使已有 KV Cache 能继续复用。

### 第 2 章：上下文生命周期

```text
稳定规则与工具定义
    → 追加用户/助手/工具轨迹
    → 按需加载 Skill 与外部资料
    → Harness 维护结构化状态
    → 末尾注入紧凑状态栏
    → 接近容量时裁剪、摘要或窗口化
    → 权限与结果仍由 Harness 验证
```

| 工程问题 | 当前结论 |
| --- | --- |
| 缓存 | 越靠前的稳定内容越不要反复改写；动态信息优先后置追加。 |
| Prompt | 要用控制变量和环境最终状态评价，不靠语气感受或模型自评。 |
| 安全 | 模型能抵抗某次注入不等于系统安全；硬权限和高风险校验留在 Harness。 |
| 渐进式加载 | Tool 是动作接口，Skill 是流程与方法；先发现描述，命中后再加载主文件和参考资源。 |
| 状态 | Agent State 存在模型外；System Hint 是它的文字投影；API 中的 `user` role 只是一种承载格式。 |
| 压缩 | 摘要是有损投影。固定目标优先任务感知摘要，重要事实保留引用和原文回查，目标会变的长轨迹可延迟到阈值再窗口化压缩。 |

详细实验地图、学习时长与主动回忆题见 [第 2 章里程碑复盘](../../90-reviews/2026-08-10-深入理解AI-Agent-第2章里程碑复盘.md)。

## 当前学习结论

1. Agent 的质量不只由模型决定，也由上下文、工具、权限、验证和运行机制决定。
2. “模型看到过”不等于“模型永久记住了”；长期记忆需要外部存储与检索。
3. 工具调用只是动作能力，可靠 Agent 还需要状态管理、错误处理和结果验证。
4. 学习 Agent 不能只读概念，最终要通过最小执行循环和真实项目验证。
5. 工作流与自主 Agent 的核心差别是执行路径由程序员预先确定，还是由模型根据环境反馈动态决定；两者可以混合。
6. Attention Weight 只说明某层某 Head 如何分配读取比例，不能直接当作 token 的语义重要性或最终输出因果贡献。
7. KV Cache 优化依赖稳定前缀；内容相同但顺序或消息结构改变，也可能降低缓存复用。
8. 模型抵抗了固定 Prompt Injection 攻击，不能代替 Harness 权限、参数和结果校验。
9. Agent 动态状态应由程序维护，不应每轮让模型从长轨迹重新统计。
10. 压缩策略的选择要同时考虑任务是否稳定、是否需要引用、旧细节能否回查，而不是只看压缩率。
