# Agent 核心疑问总结

[返回学习资料](../README.md)

| 核心疑问 | 当前结论 |
| --- | --- |
| Agent 和大模型有什么区别？ | 模型是生成与推理核心；Agent 是把模型、上下文、工具、记忆、执行循环和权限组织起来的完整运行系统。 |
| Agent Runtime / Harness 是什么？ | 它是模型外面的执行环境，负责准备输入、调用工具、保存状态、处理错误、验证结果和决定何时停止。 |
| Harness 由哪些部分构成？ | `上下文 + 工具 + 约束 + 验证 + 纠正`：前两项支撑模型决策与行动，后三项让执行可控、可检查、可恢复。 |
| 什么时候用单次模型调用、工作流或自主 Agent？ | 单次调用能解决就不增加编排；路径固定时用工作流；需要根据环境反馈动态决定步骤时用自主 Agent；开放探索与高风险固定环节并存时混合使用。 |
| 上下文和记忆有什么区别？ | 上下文是模型这一回合实际看到的内容；记忆是存放在模型之外、未来可能被检索进上下文的信息。 |
| 聊天历史很长，是否等于模型记住了？ | 不等于。历史只有在仍被放入当前上下文时才可见；被截断、压缩或未检索到的信息不会自动参与推理。 |
| Context Engineering 为什么重要？ | 模型只能依据当前上下文工作。选错、漏掉或混入太多无关信息，都会让再强的模型做出较差判断。 |
| Attention 热力图展示的是 Q、K、V 还是别的东西？ | 展示 Query 与 Key 打分经过 causal mask 和 softmax 后的 Attention Weight；这些权重再用于加权读取 Value。 |
| 新 Token 是在 Transformer 哪一层出现的？ | 它不作为新增位置出现在当前轮的某个 Layer 中；最后一个已有位置的最终 hidden state 经 LM Head 产生词表 logits，选出的新 token 在下一轮才进入 Layer 0。 |
| Causal mask 和 `[MASK]` token 有什么区别？ | Causal mask 是禁止读取未来位置的计算规则；`[MASK]` 是 BERT 类遮盖词训练中可能实际放入序列的特殊 token。 |
| 为什么 KV Cache 缓存 K/V 而不是历史 Q？ | 每个新位置都要用自己的 Query 匹配历史 Key 并读取历史 Value；历史 Query 在完成当时的注意力计算后通常不会再被未来位置使用。 |
| Attention Weight 很高是否意味着该 token 对答案最重要？ | 不能直接这样推断。Weight 只描述某层某 Head 的读取分配；Value 内容、输出投影、残差、MLP 和后续层都会影响最终结果。 |
| Tool 和 Skill 有什么区别？ | Tool 是一次可调用的动作接口；Skill 是完成一类任务的可复用流程，通常会组合规则、上下文和多个工具。 |
| Sub-agent 是什么？ | 它是承担独立子任务的另一个执行上下文，适合并行研究或隔离复杂任务，但需要明确输入、输出和汇总方式。 |
| OpenClaw 这类系统处于哪一层？ | 它更接近 Agent Runtime：连接模型、渠道、工具、记忆和长期运行机制，而不是一个新的基础模型。 |
| Agent 为什么会不稳定？ | 常见原因是上下文不完整、工具结果不可靠、目标或停止条件模糊、权限边界错误，以及缺少验证和恢复机制。 |
| 怎样证明自己真的理解 Agent？ | 能脱离材料讲清执行循环，并实现一个会调用工具、处理失败、验证结果和停止的最小 Agent。 |
| 为什么 Agent 的 KV Cache 强调稳定前缀？ | 新轮次会复用之前请求的相同前缀；如果在 system、工具定义或早期消息中动态改字段、换顺序或删旧消息，分叉位置之后的缓存就无法直接复用。 |
| `cached_tokens` 和 TTFT 应该怎样看？ | `cached_tokens/Cache%` 是判断供应商前缀缓存的主证据；TTFT 必须基于流式首 Token 测量，非流式完整响应耗时不能严格叫 TTFT。 |
| 为什么强模型能抵抗 Prompt Injection，仍需 Harness 防御？ | 模型对某组攻击样本的抵抗只是概率性行为；权限、参数白名单、删除/发布/付款确认和结果验证必须由模型外的确定性程序强制。 |
| Agent State、System Hint 和对话历史是什么关系？ | State 是 Harness 中的结构化真实状态；System Hint/状态栏是选择性渲染给模型的文字投影；正式对话轨迹是另一个持久化问题。实验中状态栏借用 `role=user` 并不代表它来自真实用户。 |
| 状态栏为什么不应让 LLM 每轮从长轨迹总结？ | 计数、步骤、预算、权限和工具结果是可由事件确定更新的状态；让 LLM 重新扫描全轨迹会把原始难题换个位置，还会把摘要错误放大到下游决策。 |
| 额外调用一次 LLM 做摘要，算不算 Sub-agent？ | 不一定。一次固定 Prompt 的 LLM 变换更像摘要函数；拥有独立目标、状态、工具和执行循环的另一个上下文，才更接近 Sub-agent。 |
| 任务感知摘要、带引用摘要和窗口化怎么选？ | 固定目标优先任务感知摘要；需要核查事实和追问时加引用与原文回查；长对话的目标可能变化时，先保留近期全文，接近容量阈值再压缩旧工具结果。 |
| 为什么“带引用组 Token 涨到 5.55 倍”不能直接归因于引用？ | 引用文字本身只会小幅增加输入输出；引用摘要改变了主 Agent 的搜索决策，导致迭代数、网页和长前缀都不同。要测独立成本，必须固定网页、工具轨迹和迭代数，只改引用开关并重复运行。 |
