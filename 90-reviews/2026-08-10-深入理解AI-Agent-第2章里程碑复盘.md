# 《深入理解 AI Agent》第 2 章里程碑复盘

## 完成边界

本章按用户确认的“抓重点”路线完成：2-2、2-3 深入学习，2-4、2-5、2-7、2-8 重点理解实验设计与边界，2-6、2-9 深入理解关键机制。

这里的“完成”指核心学习目标完成，不声称用户亲手完整复现了每一个官方 Campaign，也不把仓库历史凭证当成本次付费运行。

## 一句话总结

> Context Engineering 不是把 Prompt 写得更长，而是由 Harness 在每次模型调用前，组装当前真正需要的规则、轨迹、工具、状态和证据，并同时管理缓存、安全与长度。

## 九个实验串成的主线

| 实验 | 核心问题 | 本次稳定结论 |
| --- | --- | --- |
| 2-1 本地 LLM / Tool Loop | Agent 为什么要多轮调模型 | 模型决定动作，Harness 执行工具并把观察追加回上下文；简单任务不需要强行 Agent 化。 |
| 2-2 Attention Visualization | 模型如何读取历史 Token | 热力图展示 Attention Weight，不是 Q/K/V；Query 匹配 Key，权重加权读取 Value；Head 是同层不同投影视角，Layer 会持续更新 hidden state。 |
| 2-3 KV Cache | 多轮 Agent 怎样复用已算前缀 | 稳定 system、tools 和轨迹前缀；动态内容尽量后置追加。主证据是 `cached_tokens/Cache%`，非流式整轮耗时不是严格 TTFT。 |
| 2-4 Prompt Engineering | Prompt 设计能否用实验比较 | 保持任务与模型一致，每次只改一个变量，用环境最终状态而非模型自评判定成败；小样本单轮结果不能过度泛化。 |
| 2-5 Prompt Injection | 模型能抵抗简单攻击是否等于安全 | 不等于。工具输出、网页和文件是不可信数据；权限、参数校验和高风险动作必须由 Harness 强制。 |
| 2-6 Agent Skills | 专业流程为什么不全放 System Prompt | Skill 先暴露 name/description，命中后加载 `SKILL.md`，再按需读 references/scripts/assets。Tool 是动作接口，Skill 是流程和方法。 |
| 2-7 状态栏注意力对照 | 模型为什么会数不清历史事件 | 原始轨迹里的隐式计数要由程序提炼成显式状态；状态栏写错会直接误导模型，准确率应是生产指标。 |
| 2-8 System Hint | 运行时状态如何给到模型 | 真实状态留在 Harness 结构化 State；每次调用前可渲染成上下文末尾的临时合成 `user` 消息。API role 不等于语义来源，是否进入历史取决于 Session 持久化策略。 |
| 2-9 Context Compression | 上下文过长时该丢掉什么 | 压缩不是单纯变短，而是保留未来决策需要的信息。任务感知摘要适合固定目标，引用支持核查，窗口化是“容量阈值触发 + 延迟摘要”，不是纯删除旧消息。 |

## 上下文生命周期

```text
稳定规则与工具定义
        ↓ 尽量保持前缀稳定
用户 / 助手 / 工具事件轨迹
        ↓ 新事件追加末尾
Harness 外部结构化状态
        ↓ 每轮渲染紧凑状态栏
Skill / 检索资料
        ↓ 按需加载，不全量常驻
上下文接近容量限制
        ↓ 裁剪、任务感知摘要、引用、窗口化
真实权限和结果验证
        ↓ 仍由 Harness 执行，不交给 Prompt 承担
```

## 用户在学习中的重要判断更新

| 阶段 | 最初假设 | 当前更严格的表达 |
| --- | --- | --- |
| Attention | 图里可能是 Key、Value 或下一个 Token | 图里是 Mask + Softmax 后的 Weight；新 Token 在全部 Layer 结束后由 LM Head 选出，下一轮才进入序列。 |
| KV Cache | 新轮次会越来越多复用旧前缀 | 方向正确，但只有字节级/语法级稳定前缀才能复用；供应商还有缓存粒度和准入门槛。 |
| Prompt 实验 | 多跑几次应该很便宜 | Agent 任务是多轮双模型调用，先区分历史收据、本次账单与最坏费用上限。 |
| Prompt Injection | 强模型已经够聪明，可能不需要 Harness | 模型抵抗固定简单攻击只是观察；高风险权限和参数校验必须是模型外硬约束。 |
| Skill | Skill 是规范，Tool 是给参数返结果 | 主干正确；Skill 还可携带脚本、模板和资产，而真实外部动作仍由 Tool/Host 完成。 |
| Context Compression | 有目标摘要应该准确率最高 | 它更有可能保住当前任务证据，但本次“成功”只表示生成最终答案，没有严格证明事实准确率最高。 |
