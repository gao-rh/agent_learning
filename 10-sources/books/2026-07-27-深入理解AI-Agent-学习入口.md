## 为什么以它为核心

这本书不是资料链接合集，而是围绕 `Agent = LLM + 上下文 + 工具` 给出从基础、上下文、记忆、工具、Coding Agent、评估、后训练、自我进化、多模态到多 Agent 的连续主线，并为绝大多数主题提供可运行或可复现的实验。它正好能把当前分散的 Agent、Context、Harness、Skill、MCP 学习放回同一张工程地图。

## 已准备的代码环境

第 1 章四个项目的依赖已安装到独立 Python 3.11 环境：

```bash
cd "/Users/gaoronghui/Documents/agent_learning/学习资料/Agent/参考资料/深入理解AI-Agent/ai-agent-book"
source .venv/bin/activate

```

无需 API Key 的两个起步验证：

```bash
cd chapter1/web-search-agent
python main.py --provider offline-demo

cd ../search-codegen
python main.py --dry-run --request "解释 Agent 的 ReAct 循环"
```

2026-07-27 已完成的本地验证：

- `web-search-agent`：32 个测试通过；离线 ReAct 演示可启动。离线模式输出的是项目内置固定示例轨迹，不代表真实搜索，也不会完整响应任意输入问题。
- `learning-from-experience`：4 个基础测试通过。
- `context`：7 个 Agent 单元测试通过；仅出现上游依赖 `PyPDF2` 已弃用的提示，不影响当前运行。
- `search-codegen`：`--dry-run` 能生成包含系统提示、工具定义和用户请求的完整请求体，未调用外部 API。
- 真实模型调用与联网搜索尚未验证，因为没有读取或写入任何私人 API Key。

需要真实模型调用时，从对应项目的 `env.example` 复制为 `.env`，只填自己选择的平台密钥。常见变量包括 `MOONSHOT_API_KEY`、`OPENROUTER_API_KEY`、`SILICONFLOW_API_KEY`、`ARK_API_KEY`、`DEEPSEEK_API_KEY`、`ZHIPU_API_KEY`。不要把 `.env` 提交到 Git。

全书没有一个安全可靠的“统一环境”：92 个实验包含 Python、Node、训练框架、GPU、浏览器、语音和机器人依赖。后续应按章、按项目建立独立环境；每个项目已经保留自己的 `requirements.txt`、`pyproject.toml`、`package.json` 或 README 配置。
