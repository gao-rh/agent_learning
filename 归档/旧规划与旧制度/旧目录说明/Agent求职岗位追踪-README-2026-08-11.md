## 目标与偏好

这套追踪系统当前直接服务于 2026-08-31 前的社会招聘冲刺，不再以“约三个月后再投递”为默认节奏。用户当前有一年大数据开发经验，但岗位筛选不以数据开发为主线。

固定优先级：

```text
P0 直接 Agent 开发
> P1 大模型应用后端 / Agent 全栈 / Harness / Agent 平台
> P2 数据 + Agent / RAG 数据 / AI Search 等兜底方向
```

- 主推：Agent 开发、Agent 后端、Agent Runtime、Agent Harness、智能体平台、Agent 全栈、AI 应用研发。
- 重点机制：Planning、Tool/Function Calling、MCP、Skill、Memory、Context、Workflow、多 Agent、Eval、Trace。
- 后端要求：Java / Python / Go、分布式、高并发、高可用、缓存、消息队列、RPC、数据库、Docker、Kubernetes、可观测性。
- P2 每期最多两条；传统数据开发、纯数仓、纯离线/实时计算不进入推送。
- 经验段：0–3 年和未明确年限为主；3–5 年只保留高度匹配挑战岗；5 年以上只作趋势观察。
- 排除：产品、运营、销售、纯预训练/后训练算法、与 Agent 应用无关的 AI Infra、实习和校园招聘。

## 岗位分类与业务标注

| 分类 | 判断标准 | 示例 |
| --- | --- | --- |
| P0 | 标题或主要职责直接开发 Agent 核心系统 | Agent开发工程师、Agent后端、Agent Harness、智能体工程师 |
| P1 | 标题不一定写 Agent，但主要工作是大模型应用后端、平台、全栈、评测或搜索 | AI应用研发、AI全栈、Agent Infra、AI Search、Agent测试开发 |
| P2 | 数据能力与 Agent/RAG 强交叉，仅作为兜底 | Agent数据平台、Code Agent数据、知识底座、Text-to-SQL |

关键词只用于发现岗位，不用于决定是否收录。收录后必须阅读职责，并补充两层业务信息：

| 字段 | 含义 |
| --- | --- |
| `business_unit` | 官网公开的事业群、事业部或产品线；官网没公开更高层组织时明确标记“未公开” |
| `business_direction` | 根据职责判断的实际业务场景，如 Office Agent、AI Coding、外卖 Agent、搜索 Agent |

同名岗位若事业部、产品线或业务方向不同，视为不同岗位保留。不能因为标题没有 `Agent` 就排除，也不能因为正文出现 `Agent` 就直接判定为目标岗位。

## 增量识别规则

1. 优先用官方岗位 ID；没有 ID 时用“公司 + 标题 + 部门 + 城市”生成 `key`。
2. 列表阶段只读取岗位元数据；只有新增或内容变化的岗位才读取完整 JD。
3. `jd_hash` 是标题、部门、事业部、业务方向、城市、年限、发布日期和能力标签标准化后的 SHA-256。
4. 同一 `key` 的 `jd_hash` 变化记为“岗位要求变化”，不算新增。
5. 官网明确显示“已结束”时直接关闭；普通访问失败第一次只增加失败计数，连续两次才标记 `suspected_closed`。
6. 官网搜索数不等于 HC；报告分别记录关键词命中、已验证技术岗和明确招聘人数。

## 数据接口

`02-岗位追踪/岗位状态.json` 是机器状态，`02-岗位追踪/岗位索引.md` 是阅读入口。每条记录固定包含：

```text
key, company, title, department, business_unit, business_direction,
city, experience, degree,
category, tags, published_at, first_seen, last_seen,
jd_hash, status, official_url
```

状态值：

- `active`：官网当前可见或详情页可申请。
- `closed`：官网明确显示已结束。
- `suspected_closed`：连续两次无法在官网确认。
- `verification_limited`：官网动态化或详情提取受限，不能确认关闭。

连续失败次数保存在 `02-岗位追踪/岗位状态.json` 顶层 `failures` 映射中，不污染岗位记录接口；下一次成功确认后将对应计数清零。

## 每周输出

每周归档写入 `03-增量周报/YYYY-MM-DD-Agent岗位增量.md`，包含：

- 本轮覆盖、失败官网和覆盖限制。
- 新增、要求变化、关闭数量，以及 P0/P1/P2 分布。
- 最多 10 张岗位卡；P2 最多 2 张。
- 岗位要求变化：年限、技术栈、Agent 机制、后端、评测、部署与产品交付。
- Token/额度消耗的可获得指标；若单次超预算，下一轮将轮换公司从 6 家降为 3 家。
