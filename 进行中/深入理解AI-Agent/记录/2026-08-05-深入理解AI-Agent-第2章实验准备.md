### 学习问题：Attention Head 是什么

- 触发材料：准备从默认 `avg heads` 进入 README 第二步的单 head 观察。
- 用户问题：“16个head切换到单个head是啥意思啊？我不太理解head。”
- 用户假设：暂无；当前尚未区分 Layer、Head 与 Token position。
- 助手反馈：一个 Transformer layer 内有多组并行的 Q/K/V 投影与注意力计算，每组称为一个 head。对于同一段 token、同一层，16 个 head 会产生 16 张不同的 attention matrix；模型实际将各 head 的输出拼接并通过输出投影继续计算，而默认热力图中的 `avg heads` 只是为了展示而把 16 张权重图做算术平均。
- 严格边界：单个 head 不是另一个模型，也不能在观察前给它强行贴上“语法 head”“实体 head”等固定语义标签；是否出现分工要由具体输入、层与证据判断。

### 用户假设：多头的投影与平均图亮度

- 触发材料：多头注意力与默认 `avg heads` 热力图讲解。
- 用户原话：“多头注意力的多头就是多个WK、WV，然后乘出多个KV。是这个意思吗？某个格子很亮是平均值很亮是吗？应该是有正有负，不一定都很亮。”
- 用户假设：每个 head 有不同的 K/V 投影；平均图中亮格代表平均值高，但可能由正负 attention 值抵消而来。
- 助手反馈：方向上正确的是每个 head 有自己的投影视角，并且平均图亮格只说明跨 head 的平均 attention weight 高。严格地说每个 head 通常有 `W_Q^h/W_K^h/W_V^h`，先得到 `Q_h/K_h/V_h`；分数由 `Q_h K_h^T` 产生，经 mask 与 softmax 得到 `A_h`，再计算 `A_h V_h`，不是“乘出多个 KV”。
- 关键纠偏：softmax 前的 attention logits 可以有正有负；热力图显示的 softmax 后 attention weights 全部非负且每行和为 1。因此平均图不存在正负抵消；平均值高可能是所有 heads 都较高，也可能是少数 heads 很高、其他 heads 较低，仅凭平均图无法区分。

- 可提炼概念：attention logits 与 weights、`QK^T`、`AV`、非负平均的歧义。

### 学习问题：Transformer Layer 是什么

- 触发材料：准备把网页参数从 Layer `-1` 改为 Layer `0`。

### 用户假设：热力图展示 Value，Q 乘 K 得到新 Value

- 用户原话：“这个图里展示的是啥呀？这个图里展示的是value吗？还是key？应该是用新的token的query去乘以之前的算好的ABCD的key得到新的value，这是这个要算的。”

- KV Cache 连接：当前 token 自己的 `K_new/V_new` 由其表示经 `W_K/W_V` 投影得到并追加缓存，供未来 token 使用；历史 Query 在完成当时那一行注意力后通常不再被未来 token 读取，所以缓存的是 K/V 而不是 Q。

### 用户复述：Attention Weight、Value 与 Hidden State

- 用户原话：“图里展示的是权重，是 query乘以Key得到的，然后还有规矩化之后得到的。因为value也是长期使用的，变化的只是权重，权重乘以value才是下一个下一个hidden state的一个value不是不是叫value是叫输入的token。”
- 助手评估：热力图是 `QK^T` 打分经 mask/softmax 归一化后的 Attention Weight、历史 Value 需要缓存复用，这两点正确。
- 纠偏一：不是只有权重变化。对固定历史前缀，历史 K/V 可复用；每追加一个新 token，还会计算并缓存它自己的新 K/V。新的 Query 会产生新的一行 weights。
- 纠偏二：`weights × V` 得到当前位置的 attention output，经输出投影、残差、MLP 与后续 layers 更新当前位置 hidden state；它既不是新的 V，也不是下一个 token。最后层当前位置 hidden state 经 LM Head 得到下一 token 的 logits/概率，采样出的 token ID 再经过 embedding 成为下一个位置的输入表示。
- 严格索引：若最后已有 D，D 位置最终 hidden state 预测 E；E 被追加后，E 的 Q/K/V 参与计算并用于预测 F。教材用“E 的 Query 生成 E”是便于理解的简化说法。
- 状态：`[主干理解正确，输出链路已纠偏待复述]`

### 用户假设：每层生成下一个 token，末位 Mask 对应输出 token

- 用户表达：每层第一个/第二个 token 由上一层可见位置的 Value 加权得到；最终最后层输出第三个 token；第0层最后可能存在一个 Mask，传到最后层后成为输出 token。
- 正确部分：在同一序列位置上，下一 Transformer layer 的位置 `i` 会通过 causal attention 读取上一层位置 `0..i` 的 Value 表示；例如位置2不能读取未来位置3。
- 核心纠偏：Layer 不生成新 token，也不改变序列位置数量。各层只是串行更新同一批位置的 hidden states；只有最后一层最后一个已有位置的 hidden state 经 LM Head 才产生下一 token 的 logits。
- Mask 区分：Qwen 的 causal mask 是注意力分数矩阵上的禁止规则，不是序列尾部的 `[MASK]` token。`[MASK]` 占位符属于 BERT 式 Masked Language Modeling 的常见训练方式；自回归生成不会预先放一个未来 token 占位。
- 严格生成流程：已有 A/B 时，各层保持 A/B 两个位置；最后层 B 位置预测 C。C 被采样并追加后，序列才变成 A/B/C；C 经过所有 layers 后预测 D。
- 状态：`[关键混淆已识别，待用位置×层二维图复述]`
- 可提炼概念：layer depth 与 autoregressive time、causal mask 与 mask token、next-position prediction。

### 学习问题：各层形状不变时，新 Token C 在哪里出现

- 用户问题：“生成的 Token C 是只在最后一层出现吗？每一层的特征量应该对齐，Transformer 每层的数据量是一样的。”
- 用户判断：Transformer 各层的序列长度和隐藏维度应该保持一致，因此 C 若只作为最后层新增位置出现，会破坏层间对齐。
- 助手评估：对“层间张量形状保持一致”的判断正确；C 也并不作为最后层中的新增位置出现。输入 A/B 的一次前向传播中，各层始终处理形状为 `2 × d_model` 的 hidden states。最后层 B 位置的向量经 Transformer 外的 LM Head 投影为词表 logits，选择一个 token ID C。
- 下一轮：C 被追加到输入序列并查 embedding，新的前向计算/增量解码才具有 A/B/C 三个位置（概念形状为 `3 × d_model`）；使用 KV Cache 时只重新计算 C 的当前 hidden state，历史 A/B 的 K/V 从缓存读取。
- 严格区分：`d_model` 维 hidden state、`vocab_size` 维 logits 和离散 token ID 是三种不同对象。LM Head 实现从 hidden space 到 vocabulary space 的映射，采样/argmax 再把 logits 变为 C。

### 学习问题：TTFT、模型回答与逐轮明细

### 学习问题：Kimi 的 256 Prompt Token 缓存门槛

- 用户问题：“前一个请求超过 256 Prompt Tokens 后，后续相同前缀才可能命中”是什么意思。
- 核心解释：256 是缓存准入门槛，不是“只缓存第 257 个 token 以后”。若请求 A 的整个 prompt 少于 256 tokens，Kimi 不保留它作为可复用前缀；即使请求 B 再发送相同短前缀，也不能从 A 建立的缓存命中。若 A 超过 256，服务端才可能保存其初始前缀；B 从开头重复相同 token 序列时才有资格命中。
- “可能”边界：超过 256 只表示具备缓存资格，不承诺全部保存或 100% 命中；还取决于初始 token 是否逐个相同、服务端自动策略、缓存生命周期和块粒度。
- 本次连接：本轮首个成功请求有 462 prompt tokens，因此可以为后续请求建立缓存；但它自己 `cached=462` 仍说明请求发出前已有匹配缓存，不能用 462>256 单独解释首轮命中。

- 动态 system 五轮均为 256 Cached；动态 profile 前四轮为 256、第五轮为 0。变化字段靠近前缀开头后，后续增长的历史无法连续复用。
- 滑动窗口真实截断证据：第 5 轮 `messages` 仍为 8 条，但 tool 结果从完整模式的 4 个减少为 3 个，最早的 `find` assistant/tool 对被删。第 4 轮 Prompt 3,368 / Cached 1,536；截断后的第 5 轮 Prompt 4,179 / Cached 256，Cache% 从 45.6% 降到 6.1%。
- 工具乱序逐轮工具顺序确实不同；最后一轮却命中 1,536，提示连续 campaign 的服务端预热或偶然排列重合会干扰固定排名。正确读法是比较稳定前缀范围和逐轮轨迹，而不是假定每个反模式必然按教材示例排序。
- 首轮自动缓存仍存在：`correct` 首轮 647 Prompt / 256 Cached，后运行的滑动窗口和纯文本首轮甚至 647/647；这是 Kimi 服务端已有/跨模式缓存证据，不是本地 Agent 在第一轮提前计算 KV。

## 实验 2-4：提示工程消融实验

### 从零导入

- 实验问题：同一个 Agent、同一组航空客服任务，如果只破坏提示词的一部分，任务成功率会怎样变化。
- “消融”含义：从完整基线中有控制地去掉或破坏一个部件，再与基线比较；不是让模型自由改写提示词。
- 评测场景：τ-bench airline。一个 Agent 使用查询、改签、退款等工具服务模拟用户；环境根据最终数据库状态和任务要求给出客观 reward `0/1`。

- 观察指标：首要是成功任务数/成功率；其次是工具调用轨迹、错误类型、步骤数、usage 与成本。不能用模型“回答看起来不错”代替环境 reward。
- 与 2-3 的区别：2-3 研究相同前缀是否省计算；2-4 研究模型看到的提示结构是否帮助它把任务做对。
